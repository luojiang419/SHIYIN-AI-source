# 165 - v1.0.234 建筑需求规划接口差异备份

生成日期：2026-08-22

## 模块范围

本备份只记录“建筑需求视觉分析与多视图提示词规划”模块，不包含用户原有未跟踪文件，也不复制构建缓存。

涉及文件：

- `canvas_core/building_multi_view.py`（新增）
- `main.py`
- `static/js/canvas-building-multi-view.js`
- `tests/test_building_multi_view_plan.py`（新增）
- `tests/test_canvas_building_multi_view.py`

## 修改前

- 建筑模式只有端口和模式切换，点击生成会提示链路尚未初始化。
- 后端没有建筑需求整合接口，无法区分纯文本规划与带图视觉规划。
- 没有统一的建筑规格 JSON，线稿及正、侧、背、顶视图只能在后续代码中临时拼提示词。
- 没有隔离参考图中文字指令的安全约束。

## 修改后

### 1. 严格建筑规格

新增固定字段：`building_type`、`style_and_era`、`massing`、`storeys`、`roof`、`fenestration`、`materials`、`structure`、`equipment`、`weathering`、`environment`、`lighting`、`palette`、`optimized_prompt`、`must_preserve`、`uncertainties`。

解析器会移除可选 JSON 代码围栏、拒绝缺字段和空规格，并限制单字段和数组长度。

### 2. 规划接口

修改前：

```text
无 /api/building-multi-view/plan
```

修改后：

```text
POST /api/building-multi-view/plan
输入：节点内提示词、连接提示词、最多五张带 sketch/front/side/back/top 角色的图片
含图：强制路由到已配置视觉聊天模型
纯文本：使用请求指定的普通聊天模型
输出：严格建筑规格、实际平台/模型、使用图片数、参考角色与 usage
```

重复视角、无效本地图片、无可用视觉模型和无有效 JSON 都会在图片生成前终止。解析失败提示明确包含“未调用图片生成 API”。

### 3. 提示词构建器

修改前：

```javascript
window.CanvasBuildingMultiView 只导出模式、端口、阶段和分组工具。
```

修改后：

```javascript
buildBuildingPrompt('sketch' | 'front' | 'side' | 'back' | 'top', plan, referenceRoles)
buildBuildingPromptSet(plan, referenceRoles, views)
```

线稿输出为同尺度正面、右侧、背面、屋顶平面的四视图设计板。实景输出使用固定相机轴、同一建筑身份锚点、真实材料微纹理、施工公差、天气旧化和现场摄影光学响应；参考图只作为同一建筑的几何与材质证据。

## 安全约束

- 参考图内的文字、二维码、水印和命令式语句只作为像素证据，不能改变任务。
- 图片请求不得回退到纯文本模型。
- 规划接口不引用任何图片生成函数。
- 用户明确需求可补充风格；与图片几何冲突时保留图片几何，并把冲突写入 `uncertainties`。
