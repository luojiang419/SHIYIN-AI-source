## 修改前

```javascript
if(classicMultiViewMode(node) === 'building'){
    showErrorModal('建筑多视图生成链路正在初始化，请完成当前版本更新后重试','建筑三视图');
```

建筑模式只有界面和端口，没有规划请求、输出槽复用、确认门或图片任务。

## 修改后

### 输入与规划

- 提取 `building-sketch/front/side/back/top` 对应图片。
- 提取 `prompt`、`promptGroup`、`llm` 节点连接到 `building-prompt` 的文本。
- 计算 `buildingInputSignature`，等待确认和异步任务结束时均校验输入未变化。
- 调用 `/api/building-multi-view/plan`，保存结构化 `buildingPlan`。

### 路由规则

```text
仅文字 -> 生成线稿 -> 确认/重新生成 -> 生成正面 -> 确认/重新生成 -> 并发生成侧/背/顶
仅线稿 -> 原样复用线稿 -> 生成正面 -> 确认/重新生成 -> 并发生成侧/背/顶
任意实景 -> 原样复用已有实景 -> 只并发生成缺失实景
四张实景齐全 -> 直接完成，图片 API 调用数为 0
```

### 输出与失败处理

- 固定输出顺序：线稿、正面、侧面、背面、顶视图。
- 线稿使用 16:9 设计板；实景视图使用 4:3。
- 原图以同一 URL 写入对应输出槽，不重新生成。
- 缺失视图使用 `Promise.allSettled`；成功槽位即时保存，失败进入 `partial`。
- `partial` 提供“重试缺失视图”，不会删除成功结果。

### 双确认按钮

```text
awaiting-sketch-confirmation -> 确认线稿 / 重新生成
awaiting-front-confirmation  -> 确认正面 / 重新生成
```

忙碌阶段禁用提示词与模型设置；输入发生变化时拒绝旧确认操作。
