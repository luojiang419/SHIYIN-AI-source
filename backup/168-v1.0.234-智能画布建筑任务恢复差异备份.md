## 关键代码前后对比

### 任务持久化

修改前：建筑视图生成只在当前 JavaScript Promise 中轮询，页面刷新后无法知道已提交的任务。

修改后：提交图片任务后立即把 `view/taskId/providerId/model/startedAt/inputSignature` 写入 `buildingPendingTasks` 并保存画布；成功后才移除对应任务。

### 任务恢复

修改前：智能画布启动只恢复通用 `pendingTasks`，建筑专用任务没有恢复入口。

修改后：新增 `resumeSmartBuildingNodePending` 与 `resumeSmartBuildingPendingTasks`，在画布加载和远端合并后只调用 `pollSmartCanvasTask(task.taskId)`，不再次调用 `runApiGeneration`，并将结果回填到原建筑视图槽位。

### 重试防重复扣费

修改前：失败后直接点击重试可能重新提交仍在后台运行的任务。

修改后：`completeSmartBuildingMissingViews` 先恢复已有任务；若任务仍在恢复中则明确阻止新的生成请求，提示稍后再次重试。建筑错误态统一显示“重试缺失视图”。

### 资源缓存

`canvas-building-multi-view.js` 版本由 `.2` 升级为 `.3`；智能画布脚本由 `rev=20260821.10` 升级为 `rev=20260821.11` 并增加 `building-recovery.1` 特性标记。
