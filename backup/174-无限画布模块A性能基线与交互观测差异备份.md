# 模块 A 无限画布性能基线与交互观测差异备份

## 修改范围

- `static/js/canvas-performance.js`
- `static/js/canvas.js`
- `static/js/smart-canvas.js`
- `tests/test_canvas_performance_baseline.py`
- `开发文档/无限画布性能优化开发文档-v1.md`

## 目标

在不改变节点、连线、媒体、文本输入/输入法、远程同步和撤销重做语义的前提下，为无限画布建立可重复的性能基线入口。模块 A 只增加观测和 fixture，不进入增量连线、视口 LOD 或小地图 Canvas 化。

## 详细前后对比

### 性能观测层

修改前，`CanvasPerformance.installFixture()` 将传入参数直接交给画布 fixture 工厂，没有固定档位，也没有在性能快照中标记当前 fixture 规模。

修改后：

```js
const FIXTURE_PRESETS = Object.freeze({
    100: Object.freeze({nodes:100, connections:200}),
    300: Object.freeze({nodes:300, connections:600}),
    500: Object.freeze({nodes:500, connections:1000}),
    1000: Object.freeze({nodes:1000, connections:2000})
});
```

`fixtureOptions()` 统一解析数字或 `preset` 选项，`snapshot()` 输出 `fixture.kind` 与实际 `nodes/connections`；清理函数仍会调用原工厂恢复节点、连接和选择状态。`beginInteraction()` 增加同名活跃手势幂等保护，新增 `isInteractionActive()`，避免连续滚轮事件覆盖起始时间。

### 经典画布

修改前，经典画布只有零散的 render/拖放性能埋点，节点拖动、平移、缩放、端口连线、框选和小地图拖动没有统一的手势区间样本。

修改后在对应入口增加：

- `classic.node-drag`
- `classic.pan`
- `classic.zoom`
- `classic.port-link`
- `classic.marquee`
- `classic.minimap-drag`

手势开始调用 `beginInteraction()`，松手或下一帧完成调用 `markPaintFrom()`；不改变原有移动、连线提交、框选和视口保存逻辑。

### 智能画布

修改前，智能画布仅对部分端口拖动/连接层函数计时，节点拖动、平移、缩放、框选和小地图拖动未形成同一观测协议。

修改后接入对应的：

- `smart.node-drag`
- `smart.pan`
- `smart.zoom`
- `smart.port-link`
- `smart.marquee`
- `smart.minimap-drag`

全局 mouseup 仅负责提交首帧完成样本，原有连线兼容性判断、撤销快照、分组吸收和保存流程保持不变。

### 测试与文档

新增 `tests/test_canvas_performance_baseline.py`，覆盖四档 fixture、快照记录、恢复路径及两套画布的六类观测指标；主开发文档将模块 A 标记为已完成并指向模块 B。
