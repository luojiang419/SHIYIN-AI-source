## 主要差异

### 1. 历史条目联合类型

修改前：经典 `classicHistorySnapshot()` 与智能 `snapshotForUndo()` 对整张画布同步 `JSON.stringify + JSON.parse`，历史条目只有快照。

修改后：两套历史都支持：

```javascript
{kind:'snapshot', nodes, connections, selection...}
{kind:'transaction', createdNodes, deletedNodes, replacedNodes,
  createdConnections, deletedConnections, selectionBefore, selectionAfter}
```

`performUndo()` / `performRedo()` 按条目 `kind` 分派，双方栈均使用 `pop()` 保持跨类型 LIFO。

### 2. 结构事务覆盖

经典右键创建、快捷创建、悬浮菜单、内部节点粘贴、影视/工作流导入改为结构事务；智能菜单创建、内部节点粘贴、素材收件箱粘贴和工作流导入改为结构事务。事务只克隆新增或删除的数据，不深拷贝既有画布。

### 3. 字节限制与画布切换

经典新增 `CLASSIC_UNDO_BYTE_LIMIT = 16 * 1024 * 1024` 以及 undo/redo 双栈字节账本、裁剪和清理；智能沿用原有 `UNDO_BYTE_LIMIT` 并统一事务条目计数。切换画布会清空历史和账本。

### 4. 异常回退

智能粘贴、素材粘贴和工作流导入采用 `completed + finally`：成功提交事务，异常调用 `abortSmartHistoryTransaction()` 释放深度，不污染后续历史。

### 5. 明确回退范围

Alt 拖拽复制、复杂删除、分组/解组、原地字段替换和异步媒体任务仍使用 snapshot 或既有历史语义。拖拽期间可能修改目标分组原地 `items`，当前事务记录不足以安全表达，因此本模块不强行事务化。
