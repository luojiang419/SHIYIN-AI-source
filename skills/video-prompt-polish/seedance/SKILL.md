# Doubao Seedance 2.0 / Fast

本 Skill 只用于 Seedance 2.0 系列，不用于 Seedance 1.x、普通即梦 3.x 或其他仅名称相近的模型。最终只输出可直接提交的提示词正文，不输出分析、Markdown 围栏、模型名、画幅、分辨率或接口参数。

## 1. 先判断任务类型

根据素材在目标视频中的实际作用选择一种或组合多种任务，不得把所有素材一律写成“参考”。

### 全模态参考

从图片、视频或音频提取主体、场景、动作、运镜、特效、视觉风格、音效或音色，生成全新视频。

- 图片：`参考图片N中的主体/场景/风格，生成……`
- 视频：`参考视频N中的动作/运镜/特效/风格/音效，生成……`
- 音频：`参考音频N中的音色/节奏/声音质感，生成……`

必须写明“参考哪个素材的哪个维度”，不能只写“参考视频1”或“参考图片1”。

### 编辑视频

直接修改已有视频，未提及部分默认保持不变。

- 增加元素：写清元素特征、出现时机和出现位置。
- 修改元素：`严格编辑视频N，将其中的原特征修改为新特征，其他内容保持不变。`
- 删除元素：点明删除对象，同时说明需要保持不变的主体、动作、运镜和背景。

编辑任务必须直接写“编辑视频N”或“在视频N中”，不要写“参考视频N”，否则可能被误判为参考生成。

### 延长或补全视频

- 向后延长：`生成视频N之后的内容，……`
- 向前延长：`向前延长视频N，……`
- 轨道补全：`视频1，过渡画面与动作，接视频2……`

延长时保持原视频的主体、空间、动作惯性、音画风格和叙事连续。轨道补全最多引用 3 段视频，总输入时长不得超过 15 秒。编辑、延长和补全只在实际接口提交了对应视频时使用。

### 组合任务

明确区分参考源和编辑源，例如：`参考图片1的产品外观，严格编辑视频1，将原产品替换为该产品，其他动作和运镜保持不变。`

## 2. 接口能力优先

模型原生支持图片、视频、音频联合生成，但最终提示词只能引用当前请求实际提交的素材。

- LinkFox 当前图转视频接口只提交图片：不得保留或编造视频N、音频N、编辑视频、延长视频或音色复用能力。
- 原生全模态接口收到视频/音频时，才可使用对应参考、编辑、延长和声音规则。
- 素材顺序必须与请求清单一致，使用 `图片1`、`图片2`、`视频1`、`音频1` 等自然语言编号；不得使用 H3 XML 标签、Kling 三角标签或虚构的 Asset ID 绑定。
- 不支持的素材关系必须转换为可执行的自然语言事实，或在无法保持时停止提交，不能静默丢失。

## 3. 提示词工程结构

按实际需要组织以下信息，不机械堆砌：

`精准主体 + 动作细节 + 场景环境 + 光影色调 + 镜头运镜 + 视觉风格 + 有意义的画质描述 + 约束条件`

空间层回答“画面里有什么、分别在哪里”；时间层回答“事情怎样依次发生、动作和镜头如何变化”。主体和核心动作优先，风格与画质不能覆盖身份、空间和动作。

## 4. 主体定义与素材绑定

- 从每个参考素材中识别真正需要复用的主体。人物、产品、道具、场景均可成为主体。
- 每个主体使用 2–3 个稳定、可见、互不矛盾的静态特征定义，例如服饰、发型、外观或类别。
- 同一主体来自多份素材时，明确各素材职责，例如：`将图片1中的面部、图片2中的全身服装定义为女主。`
- 多主体必须分别命名或编号；后文每次出现都使用同一名称，禁止“她/另一个人”等可能混淆的省略指代。
- 未预先命名的简单主体，每次使用 `主体名称@图片N` 或等价明确绑定。
- 不把主体编号等同于图片编号，不把场景图误作人物身份来源。
- 重要参考素材在提示词中靠前。人脸一致性优先使用独立人脸特写加全身照，不建议把同一人物多视图当成多人素材。
- 参考人物较多时，优先把人物整合进不超过 4 人的组合参考图；不得用文字虚构不存在的合成结果。

## 5. 分镜与时间层

复杂视频使用 `镜头1`、`镜头2`、`镜头3` 按事件顺序展开。单一动作或单场景文戏优先连续长镜头；剧情转折、复杂动作或明确要求切换时才使用多镜头。

每个镜头按以下顺序写：

1. 景别、机位、运镜或明确切换方式。
2. 当前主体及其动作、表情和视线。
3. 主体位置、朝向、前中后景关系和空间变化。
4. 与当前动作同步的音效、台词或音乐。

不要强制写 `0–3秒` 等精确时码。Seedance 2.0 对精确时间控制不稳定，应优先使用“开场、随后、接着、最后”和镜头顺序建立节奏。节点总时长只用于内部控制动作密度和收束点。

多镜头必须保持人物身份、服装、道具状态、左右关系、视线、光照方向、动作惯性和环境连续；切镜后不得让动作重置、主体瞬移或凭空出现新角色。

## 6. 动作与情绪

- 动作具体到手、腿、头部、肩背、视线或重心，并写出必要的幅度、速度和力度。
- 优先低缓、连续、可完成的小动作；高爆发动作只在用户明确要求且时长足够时使用。
- 写清准备、启动、接触或空间变化、惯性承接和最终落点，避免只有“走路”“打斗”“很紧张”等概括。
- 情绪使用可见行为表达，例如视线闪躲、手指攥紧、肩膀放松、呼吸变化，不只写抽象情绪词。
- 接触动作必须符合重力、重量、摩擦、碰撞、衣物和头发的惯性；手、道具和身体状态在整个镜头中连续。
- 多主体按触发者和反应者错峰行动，避免所有人同步做同一动作。

## 7. 运镜与构图

- 一个镜头尽量只指定一种主要运镜，如缓慢推近、平稳横移、跟拍、环绕或固定镜头。
- 运镜必须绑定主体或揭示目的，说明方向、速度、景别变化和最终看到的信息。
- 重要主体应在首个可见画面中处于明确位置；写清屏幕左/右、前景/中景/背景、身体朝向和视线目标，避免空镜开场或延迟出现。
- 空间关系能由参考图明确表达时保持文字简洁；需要改变参考图机位时，仍保持场景地理、主体距离和接触关系。
- 禁止同一镜头堆叠互相冲突的推、拉、摇、移、环绕指令。

## 8. 光影、风格、画质与约束

- 写明实际光源、方向、明暗关系、色调和需要保持的曝光结果。
- 风格使用一个清楚、稳定的视觉方向，不把写实参考图和动画目标风格含糊混用。
- 画质词必须服务具体结果，例如自然色彩、稳定画面、清晰材质、无闪烁；不得只堆叠 8K、masterpiece 等无执行意义标签。
- 用户没有要求文字时，按风险加入“保持无字幕、不要生成无关文字、不要生成Logo或水印”。这只能降低概率，不能承诺绝对消除。
- 多人物存在重复风险时，明确每个主体只出现一次，禁止同款分身或双胞胎效果。
- 需要精确特效时优先引用特效视频的形态和运动逻辑，不依赖抽象形容词猜测。

## 9. 声音、台词和文字

- 台词逐字保留原语言和标点，不翻译、不改写、不增加台词；同一段台词语言保持统一，专有名词除外。
- 明确说话人、语气、发声时机和其他人物的反应。只有用户要求时才生成字幕、旁白或气泡文字。
- 推荐符号：音乐用 `（……）`，音效用 `<……>`，台词用 `{……}`，字幕用 `【……】`。
- 小语种台词标注语种。中文生僻字可能误读，但不得未经用户授权改成同音字；仅可提示风险或在用户明确要求时替换。
- 参考音色时同时描述可听的音高、厚度、颗粒感、年龄感、语速或情绪，并保持新台词风格与参考音频相近。
- `generate_audio=false` 时保留原始声音意图供追踪，但不得声称本次一定输出音频；原文明确无配乐时必须保留“无配乐”。
- 用户要求可见文字时，写清文字内容、出现时机、位置、方式、颜色或风格；常用字优先，避免无必要特殊符号。

## 10. 图片、视频和音频素材职责

- 角色锚定：图片提供面部、全身、服装或产品身份。
- 场景定调：场景图提供环境、材质、地理和风格，不自动锁死摄影机角度。
- 运镜/动作参考：视频提供明确的运镜、动作、节奏或特效维度。
- 节奏氛围：音频提供音色、节奏、音乐或音效质感。
- 推荐总素材量为 4–5 个；素材过多时必须明确优先级，避免身份和风格冲突。
- 多图有顺序要求时按上传顺序引用；故事板只有在用户要求逐格或按构图顺序生成时才按格展开。

## 11. 常见失败预防

- ID 漂移：独立面部特写与全身图分工，清楚定义主体，重要身份参考靠前。
- 字幕、Logo、水印：加入明确局部约束，并避免输入素材本身携带无关文字。
- 风格漂移：明确唯一目标风格，必要时先把参考素材处理为同一风格。
- 双胞胎：分别定义人物与素材关系，限制每个主体出现一次，不使用混乱多视图。
- 延长跳变：保持衔接帧、动作状态和切镜时机一致；模型生成后仍需成片检查。
- 多次延长画质下降：这是模型边界，提示词不能保证消除，不得虚假承诺。
- 片尾音频截断：让对白和声音在结尾前自然收束或淡出，不把长台词塞进最后一刻。

## 12. 输出前自检

输出前静默确认：

- 任务究竟是参考生成、编辑、延长、补全还是组合任务。
- 每个图片、视频、音频编号都真实存在并承担明确职责。
- 主体名称、身份来源、数量、位置、朝向和视线没有漂移。
- 动作存在起因、过程、物理反馈和收束，且能在当前总时长完成。
- 每镜头只有一个主运镜，多镜头连续性没有重置。
- 台词、歌词、画面文字逐字保留，未擅自增加字幕、Logo、音乐或人物。
- LinkFox 请求中没有视频/音频/编辑/延长等未接入能力。
- 最终正文不超过 2000 字符；优先删除重复风格词和次要背景细节，不截断主体、动作结尾、台词或素材引用。
