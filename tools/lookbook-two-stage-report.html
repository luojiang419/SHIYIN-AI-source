01 / DESIGN DECISION

建立一个真正独立的“故事完成点”

推荐将默认创作流程收敛为两次逻辑 LLM 请求：第一阶段看图并形成简明的完整故事，第二阶段拿着已完成的故事重新看图、设计机位和撰写提示词。第一阶段结束后立即保存故事、回填广告需求；第二阶段使用同一份冻结故事，随后自动生图。

01综合图片 → 故事事实、立意、连续事件、摄影意图
02保存并回填需求用户立即知道在拍什么、为什么拍
03独立会话 → 提示词重新附图，锁定故事，展开机位
04提交图片生成沿用用户指定数量、比例和版式
“两次”指默认成功路径中的两次故事/提示词 LLM 请求，不包含图片 API。可选联网、结构修复与失败重试必须单独计数，不能宣传成绝对只有两次网络请求。

02 / CURRENT IMPLEMENTATION

现有系统已经“看图”，但尚未独立完成故事

从源码看，“结果平淡”不能简单归因为完全没有图片解析。目前已经有参考分析、参数理解和分镜请求；缺口是没有把故事作为第一阶段必须完成、可回填、能冻结的独立产物。用户补充情景后更好，是支持该设计的观察，尚不是已验证的单一根因。

03 / TWO INDEPENDENT CONVERSATIONS

第一轮做选择，第二轮把选择拍出来

API 1 · 故事创意总监

综合素材，确定“这一组发生了什么”

输入所有有效参考图、顺序和角色标签、用户原始需求、节点参数与所选风格。只有人物图也必须从现有目光、动作、衣着或物件找到事件起点。

  1. 逐图列可见事实与保留项，再建立图片之间的关系。
  2. 从素材提炼一个可拍的小事件，形成目标 → 触发 → 行动 → 反应 → 结果。
  3. 生成短故事、立意、随数量伸缩的关键情节，以及多机位/特写意图。
  4. 返回可直接阅读的 ad_brief 和紧凑结构化依据。

这一轮不展开完整逐镜头生图长提示词，以免执行字段挤占故事设计。

API 2 · 摄影执行导演

继承完整故事，展开“每一张怎么拍”

以新的会话请求重新附上全部原图和角色映射，加入第一轮完整 ad_brief、参考锁与已解析参数。必须显式携带内容，不能假设第二次请求会自动记得第一次。

  1. 锁定人物、服装、商品几何、道具状态、光源与空间。
  2. 把每个情节转成动作、视线、手部接触与前后状态。
  3. 规划主体、景别、方位、高度、焦距及构图目的，检查相邻镜头差异。
  4. 输出连续性总表、精确数量分镜卡和每张最终提示词。

普通独立出图仍一张一请求；用户选择拼图时才编译组合提示词。报告的四格图是案例预览选择。

不同输入如何成为故事起点

输入组合第一轮的创作策略必须保留的边界
只输入人物从姿态、服装、视线和可见互动衍生小事件；没有场景则合理创作一个，并标注为扩展设定。默认保留现有衣着；不得把创作的职业、关系当成图片事实。
人物 + 商品让商品参与选择、穿着、携带或使用，细节在动作中得到展示。只依据可见结构，不编造型号、品牌与功能参数；用户指定换装优先。
人物 + 道具 + 场景让道具触发人物在真实地点中的动作与反应。场景拓扑、门窗与光源不随机位改变；未知区域保守延展。
只输入商品 / 多商品优先物品自身的场景故事、排列变化与材质关系；需要人物时明确是新增创作角色。不要为了套用模特故事而必定新增人脸；避免多个商品相互串色、串结构。
已有简短 / 完整需求简短情景补足因果，完整故事保留目标、事件顺序和立意，只补必要执行缺口。原始文字始终保存，AI 扩展不得覆盖用户明确指定情节。

“全部图片”必须在接口上有可核验含义：提交数、成功解码数、角色数应一致。目前各分支存在 12 张、20 张等截断上限。实施时统一上限并显式拒绝超额或损坏输入；不静默丢图，也不声称全部分析。若将来支持分批，就应明确会超过两次请求。

04 / PHOTOGRAPHIC GRAMMAR

30° 是机位变化，不是把画面倾斜 30°

30° 规则用于相邻的同主体镜头：相机围绕主体改变观察方向，帮助形成清楚的视角差。180° 规则约束相机留在行动轴一侧，维持人物左右与视线关系。将这两条原则引入连续静帧，是本方案用于减少重复与空间混乱的设计选择。30° 来源 · 180° 来源

推荐默认：相邻可比较主体镜头方位差 ≥30°；同时合理变化景别或高度。细节插入镜头记录对应手部、衣料与空间位置，不把手部俯拍角直接混入主体方位差计算。

数值是规划坐标，不能从生成图片的 EXIF 或文字标签证明已经满足。最终还要观察脸部朝向、背景透视、遮挡和空间关系。高角度、低角度与长焦不是越多越好，每个变化都要解释为什么服务此刻事件。

方案示意，非本次实图的摄影测量。若行动轴发生变化，需要记录新坐标与过渡镜头。

故事因果

每张卡必须回答“上一张造成了什么变化”。拒绝用四个同义姿势伪装连续故事。

编辑摄影构图

用明确主次、前中后景、负空间或遮挡安排视觉注意力；关键镜头能单独作为广告主视觉。

商品 / 穿着细节

触碰、拉动、转动等真实动作自然带出缝线、褶皱和材质。特写必须对应源图事实与当下情节。

05 / EXPERIENCE & STATE

故事先可见，生成自动继续

主按钮仍为“生成”。默认无需多一次确认：第一阶段返回后，需求框显示完整故事与立意，旁边标明“AI 故事方案”；进度切换为“正在编写镜头提示词”。生图结束不应成为故事首次可见的时间点。

  • 原始输入保存为独立字段，可折叠查看和恢复。
  • 系统回填不是用户编辑，不触发自身故事缓存失效。
  • 用户正在输入或输入法组合时不强行重绘；文本已变更则保留其修改，并把生成方案保存在任务中供查看。
  • 第二阶段使用启动时冻结版本。用户中途修改显示“修改用于下一次生成”，避免旧结果反向覆盖。
  • 第一阶段失败停在“故事生成失败”，不悄悄退回泛化提示词生图；第二阶段失败保留故事，可从提示词阶段重试。

模块建议变更验证重点
参考校验 / 第一阶段新增 enrich_lookbook_story_brief，合并事实分析与故事创作；参数建议、自动风格选择可作为同轮短字段。所有输入可解码；原图角色映射完整；空需求有具体故事；原始要求不被覆盖。
prepare_lookbook_creation调整为故事 → 持久化 → 提示词；本地解析显式数量与版式，再合并 AI 参数建议；默认不再调用旧的独立参数/事实/自动风格请求。标准无搜索成功路径恰好两次 LLM；第二次在第一轮完成后开始；失败无误生图。
第二阶段 / 导演分支复用分镜卡标准和完整导演分支，输入冻结故事，保留用户版式；编译前验证机位、事件与数量。故事不被替换；镜头不被旧固定景别模板改回同机位；普通风格与完整导演风格都覆盖。
任务持久化 / 轮询第一阶段成功就写入任务 options/request 和阶段元数据；中途同步携带请求 ID 与文本版本。刷新可恢复；仅同一节点当前任务可回填；取消/旧任务返回不得覆盖新任务。
canvas.js / 节点 UI在运行中同步函数添加故事回填与保存，结果同步不再重复覆盖；需求框提供生成来源和原始输入入口。输入法组合态、焦点、编辑冲突、撤销、重复点击与刷新恢复。
缓存签名原始输入签名与执行提示词签名分开；系统回填有明确来源；纳入模型/模板版本与素材内容摘要。回填不自我失效；换图/换角色会失效；仅改分辨率不必重新创作故事。

成功路径与恢复路径

READY → STORY冻结原始输入和任务版本；防止重复提交
STORY → PROMPTS先保存完整故事，再发起第二次请求
PROMPTS → IMAGES校验结构、数量、连续性后提交生成
FAILED → RETRY按失败阶段恢复，保留成功产物

默认首次生成跑两个阶段；同素材、同故事的失败重试只重做失败阶段。若用户编辑生成故事，则该文字成为本次明确要求，重新执行第二阶段；若用户明确选择重新构思故事，则第一阶段重新运行。数量变化是否重做故事按事件覆盖判断，比例变化至少重新做镜头设计，分辨率变化通常只影响图片生成。

可选联网搜索默认关闭。需要搜索时，作为明确可见的附加阶段，并在故事冻结之前形成参考方法；不能在第二阶段又悄悄换故事。超时与格式修复计入诊断信息。沿用现有任务超时机制，不在本方案中凭单次样本硬编码等待秒数。

实测后补充的冻结条件：第一轮应先做道具能力、服装结构和因果自检，再输出故事；本地至少校验结构与明显矛盾。第二轮发现事实错误时，返回显式校验失败，不带着错误继续生图。修复需要重写故事时递增故事版本并重新回填，修复请求额外计数；成功路径仍保持两轮。

为什么两轮可能改善，以及代价是什么

两轮提供了显式的创意检查点：先集中资源决定事件，再用独立上下文展开执行。保存的故事也便于用户判断是否值得继续。但多一次串行依赖会增加首图等待；两次附图可能增加输入 token。相较当前通常三次或更多的规划调用，合并后总次数可能下降，实际延时取决于路由、输出长度与并行结构，不能仅按次数推断。

成本口径应为：故事输入/输出 + 提示词输入/输出 + 图片生成 + 显式重试/搜索。本次只记录客户端耗时与逻辑调用数；未获得可靠账单和价格，报告不虚构费用。

建议实施顺序

  1. 先做故事结构与后端两阶段编排，测试输入/失败/重试。
  2. 再做中途任务同步、回填来源和版本冲突处理。
  3. 接入现有普通/完整导演两条分镜编译与图片路由。
  4. 执行代表性多素材回归，再决定是否作为默认行为。
