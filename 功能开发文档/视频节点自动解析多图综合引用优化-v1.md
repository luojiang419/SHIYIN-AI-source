# 视频节点自动解析多图综合引用优化 v1

## 任务目标

修复视频节点自动解析在连接多张参考图时只使用部分图片、且忽略节点内用户提示词的问题。自动解析必须把用户提示词、所有实际连接且可用的参考图和当前视频模型规范放入同一次多模态请求，由视觉模型综合理解故事情节、主体关系、动作时序与画面证据；输出中应智能引用全部相关主体，并保留每张图片的稳定编号映射。

## 问题拆分

1. 梳理经典画布与影视节点的参考图收集、去重、模型上限和自动解析请求载荷。
2. 修复前端自动解析未传递节点用户提示词的问题；将提示词作为请求字段并同步显示在图片映射上下文中。
3. 优化多图收集与映射：仅对完全相同的 URL 去重，保留真实连接顺序、角色标签和图号；请求前后校验实际发送图片数量。
4. 加强后端系统提示词与输出归一化：要求逐张检查全部图片，依据故事情节智能分配主体/引用，禁止遗漏有视觉证据的图片；当提示词存在时以提示词为叙事主线、图片为事实约束。
5. 增加回归测试，覆盖四图 + 故事提示词载荷、稳定图号、后端联合约束和不丢主体。
6. 递增版本，更新开发进度、进度快照、源码备份与避坑记录，并运行定向及全局检查。

## 文件/模块清单

- `static/js/canvas.js`：经典画布视频自动解析请求与多图标签。
- `static/js/canvas-film-nodes.js`：影视视频节点自动解析请求与资产映射。
- `main.py`：自动解析请求模型、联合分析系统提示词、图片数量契约。
- `tests/test_video_auto_parse.py` 及新增静态契约测试：回归覆盖。
- `功能开发文档/`、`进度快照/`、`backup/`、`避坑指南/`：过程记录。

## 验收标准

1. 节点连接 4 张不同参考图并输入故事情节时，请求体包含完整提示词、4 个图片 URL 和 4 个一一对应标签。
2. 图片顺序与连接顺序一致；只有完全相同 URL 才允许去重，不因角色或端口不同误删。
3. 后端系统提示词明确要求逐张综合解析、按故事情节组织叙事、智能引用有证据的全部主体，并声明不得只使用前两张图。
4. 自动解析输出不包含分析过程，且引用编号不漂移、不丢失主体关系。
5. 现有单图自动解析、提示词润色、影视节点和经典画布功能不回归。
