# 桌面启动令牌重复导航修复

状态：已完成
当前阶段：4/4
最后更新：2026-08-31

## 当前状态

1.0.379/1.0.380 桌面窗口实际出现 `{"detail":"桌面启动令牌无效或已使用"}`。根因是 WebView 启动、恢复和 Cookie 建立竞态可能重复导航 `/api/auth/bootstrap`，一次性启动令牌即使扩大重放次数仍可能被旧 URL 或循环恢复耗尽。

## 下一步

1. 已将桌面模式 bootstrap 改为固定 loopback 地址，不再依赖 URL 中的一次性启动令牌；进程控制令牌仍保留给 `/api/runtime/shutdown`。
2. 完成鉴权专项、桌面运行时 smoke、版本递增和安装包构建。

## 技术方案

- 桌面令牌仍由 Tauri 每次启动生成 64 位 UUID 组合随机值。
- `/api/auth/bootstrap` 继续限制为 loopback；桌面模式直接创建桌面管理员会话，不解析 URL token。
- source/浏览器模式仍保留 `AuthManager` 的令牌校验，兼容已有测试和外部脚本。
- `/api/runtime/shutdown` 继续要求 Tauri 与后端共享的进程控制令牌。
