## 一、需求结论

### 1. 总体可行性

结论：**核心功能可行，建议按“AI助手视觉分析 + 图片模型规范编译 + 原生生图提交”的三段式流水线实现。**

在当前项目基础上，复用 API 设置中的聊天/视觉模型、复用已有参考图传输和图片生成 provider 路由，能够实现以下目标：

- 用户点击图片生成节点的执行按钮后，自动分析节点内提示词、上游提示词和全部连接参考图。
- 使用 AI助手平台配置的视觉/聊天模型生成中间结构化意图和视觉证据。
- 根据图片生成节点当前选择的 provider/model，加载对应的本地 prompt profile，编译成该模型更适合执行的规范提示词。
- 将全部参考图和最终规范提示词一起提交到实际图片生成接口。
- 在生成记录中保留原始提示词、优化后提示词、参考图映射、模型 profile 版本和失败/回退原因。

### 2. 不能承诺的结果

该功能可以显著提高模糊需求的可执行性和参考图利用率，但不能保证每次图片都符合主观意义上的“顶级”“大片”或完全理解用户隐含意图。图片生成模型自身的随机性、参考图能力、内容安全策略和上游接口实现仍然决定最终结果。

“自动转换为规范提示词”应理解为：**按当前模型已知能力和官方公开规则编译出更容易被该模型执行的提示词**，而不是存在一套所有图片模型都通用、能够保证结果一致的魔法语法。

## 三、推荐产品行为

### 1. 点击执行后的统一流程

```text
图片生成节点执行
    |
    v
收集节点内提示词 + 上游提示词 + 全部参考图
    |
    v
解析当前图片 provider/model 与参考图能力上限
    |
    v
AI助手视觉/聊天模型：理解用户原意，分析全部参考图，按需检索风格资料
    |
    v
结构化意图与视觉证据
    |
    v
按图片模型 profile 编译规范提示词 + 参考图映射
    |
    v
校验：用户意图、参考图覆盖、模型长度/参数/输入能力
    |
    v
提交图片生成任务
    |
    v
保存原始提示词、最终提示词、profile 版本、参考图映射和生成结果
```

推荐由后端统一处理这条链路。经典画布和智能画布只增加 `auto_optimize_prompt: true` 以及必要的节点上下文，避免两套前端各自实现一份提示词逻辑。

### 2. 用户原意优先级

提示词编译器应固定使用以下优先级：

1. 用户明确要求、否定要求和数量要求。
2. 用户连接的参考图及其可见事实。
3. 节点选择的图片模型能力和官方 prompt 结构。
4. 用户明确指定的风格、行业、品牌或视觉用途。
5. AI助手根据场景补足的摄影、构图、材质、光线和环境细节。
6. 通用质量表达只作为最后的低优先级约束，禁止堆叠 `8k`、`masterpiece` 等无效尾缀。

优化模型不得把“高压锅爆炸”改成别的主题，也不能把参考图里的商品、脸、服装、场景或文字擅自互换。信息不确定时应标记不确定或省略，而不是编造细节。

### 3. 模糊需求的扩展方式

以“一个高压锅爆炸了”为例，AI助手可以在不改变核心事件的前提下补足：厨房这一合理空间、压力释放的蒸汽和碎片方向、锅盖与食材的运动关系、台面受影响区域、瞬间光线和安全的画面构图。扩展应来自物理常识和视觉叙事，并给“事实推断”和“艺术补足”分层，防止模型把补足内容伪装成用户原话。

### 4. 时尚/品牌/Lookbook需求

以“一个女人穿着牛仔裤，顶级时尚大片”为例，推荐识别为“时尚编辑大片/Lookbook”意图，而不是普通电商白底图。优化器应优先补齐：编辑主题、模特姿态、服装版型与面料、场景、构图、光线、镜头和后期质感。

如果用户没有指定品牌，联网检索只应提取公开案例中的可迁移方法，例如版式、构图、光线、镜头、造型叙事和广告语境；不能声称画面就是某个品牌的官方作品，也不应直接复制某个广告的主体、模特、文案或独特构图。

如果用户明确指定品牌，可检索该品牌官方公开的 lookbook、campaign 和产品资料，用于确认品牌公开的材质、剪裁、色彩和视觉语境；检索失败时必须退回通用高端时尚编辑方法，并在任务状态中记录未使用联网资料。

## 四、模型规范内置方案

### 1. 不建议从模型名自动猜规范

`gpt-image-2`、`gemini-3-pro-image-preview`、`seedream`、`FLUX`、`Qwen-Image` 等模型的输入协议、参考图上限、编辑语义、尺寸参数和提示词偏好不同。仅凭模型名拼接几个关键词会造成“看似规范、实际失配”。

### 2. 建议建立版本化 profile

新增项目内置资源，例如：

```text
skills/image-prompt-polish/
  registry.json
  generic-openai/SKILL.md
  gpt-image/SKILL.md
  nano-banana/SKILL.md
  seedream/SKILL.md
  flux-qwen/SKILL.md
  references/
    source-manifest.json
```

每个 profile 至少包含：

- `id`、匹配的 provider/model 规则和优先级。
- 官方公开资料来源、版本、抓取/核验日期和许可证说明。
- 适用协议、文本长度上限、尺寸/质量参数规则。
- 文生图、图生图、编辑、多参考图的能力声明。
- 推荐 prompt 结构、引用图标记方式和禁止项。
- 与模型名不匹配或官方规则缺失时的通用降级 profile。

### 3. D 盘安装资源的正确使用方式

可以读取本软件安装目录中已经随包发布的 `app/skills` 资源，作为本软件自己的内置规范；也可以在开发阶段从已安装版本核对资源是否完整。但不建议运行时扫描任意 D 盘软件目录来“推断”其他软件的内部提示词：

- 其他软件可能没有公开 skill 文件，或者只在服务端动态下发。
- 配置可能加密、压缩、版本化或只存在内存中。
- 任意软件目录扫描会引入路径、权限、升级和隐私风险。
- 读取到的模型名称不等于读取到了官方提示词教程。

推荐把核验过的公开规则整理成项目内置 profile，安装包构建时复制并做完整性断言；运行时只读取自己的资源。新增官方资料时通过版本更新或用户明确触发的“更新规范库”流程导入，不在每次生成时联网查规范。

## 五、联网检索策略

### 1. 适合检索的场景

- 用户明确提到品牌、lookbook、campaign、广告参考、当代趋势或某种行业视觉。
- 用户使用“顶级时尚大片”“奢侈品广告级”等需要语境判断的模糊质量描述。
- 内置 profile 需要补充公开的创作方法，但不是为了查询模型协议本身。

### 2. 不应默认检索的场景

- 普通静物、简单头像、明确产品说明和重复批量生成。
- 用户已提供完整可执行提示词且没有要求参考外部风格。
- 纯粹为了查询模型官方语法；这部分应由本地 profile 负责。

### 3. 具体实现建议

复用已有 Responses `web_search` 能力，但只把检索作为“方法上下文”输入，不把网页原文直接拼进最终提示词。搜索结果应保存短摘要、来源 URL、时间和缓存键，设置缓存有效期，避免每次重复检索。

联网不可用、当前聊天模型不支持 `web_search` 或第三方协议不兼容时，直接使用本地 profile 和内置通用方法，不阻塞普通生图；如果用户明确指定的品牌事实无法验证，应标记为未验证，不能猜测。

## 六、接口与数据方案

### 1. 请求扩展

在 `OnlineImageRequest` 增加内部任务字段，建议最小化为：

```json
{
  "auto_optimize_prompt": true,
  "optimizer_provider_id": "ecommerce-vision",
  "optimizer_model": "当前配置的视觉聊天模型",
  "optimizer_web_search": "按意图自动决定",
  "prompt_context": {
    "node_type": "image",
    "upstream_prompt": "...",
    "reference_order": ["..."],
    "camera_settings": {}
  }
}
```

实际字段应避免把 API Key、完整 provider 配置或不必要的历史消息传入前端。若 `optimizer_provider_id` 为空，由后端按 AI助手平台和可用视觉聊天模型规则选择。

### 2. 结构化优化结果

优化器不要直接返回一段不可审计的长文本，建议内部先要求 JSON：

```json
{
  "intent_summary": "用户想要的最终画面",
  "hard_requirements": [],
  "subject": [],
  "action": [],
  "environment": [],
  "composition": [],
  "camera_lighting": [],
  "style_context": [],
  "text_requirements": [],
  "negative_constraints": [],
  "reference_map": [],
  "uncertainties": [],
  "search_context": [],
  "final_prompt": "按目标图片模型 profile 编译后的提示词"
}
```

最终提交只使用通过 profile 编译和校验的 `final_prompt`，同时保留结构化结果用于日志和调试。参考图映射必须包含原始顺序、用途、证据和所有权，防止多图请求只使用第一张图。

### 3. 任务快照

每次生成记录至少保存：

- 原始节点提示词和合并后的上游提示词。
- 优化后提示词和结构化意图摘要。
- 实际使用的优化器 provider/model 及图片 provider/model。
- profile ID、版本、来源和校验结果。
- 参考图顺序、数量、角色映射和上传/转换状态。
- 是否联网、搜索摘要缓存键、失败原因和是否回退原始提示词。

图片生成接口收到的仍是最终提示词和参考图，不应让上游图片模型再次自由改写提示词，避免双重改写导致用户意图漂移。

## 七、失败、成本和安全策略

### 1. 优化失败

推荐默认策略：**记录失败并显示状态，随后使用原始合并提示词继续生成**，但在结果元数据中明确 `prompt_optimization: fallback`。这样不会因为 AI助手暂时不可用而让已有图片节点完全失去生图能力；用户也能从任务详情看出本次没有完成优化。

对于参考图无法读取、用户明确要求品牌事实但检索无法验证、或模型能力与参考图数量硬冲突的情况，不应静默生成错误结果，应显示可操作错误或要求减少参考图。

### 2. 成本与延迟

每次生成可能多出一次视觉/聊天模型调用，带来延迟和费用；多参考图、Responses SSE 和联网检索还会增加 token 与网关超时风险。建议：

- 相同的提示词、参考图哈希、图片模型和 profile 版本命中短期缓存。
- 普通需求默认不联网，只有高价值风格语境触发检索。
- 视觉模型只收到必要尺寸的压缩图，生图接口仍按原能力上传参考图。
- 通过异步画布任务显示“分析中、编译中、生成中”三阶段状态。

### 3. 隐私和安全

参考图会被发送给 AI助手视觉模型和图片生成上游，必须在请求前保留现有用户提示，并明确记录实际路由。API Key 继续只在后端使用，不写入 profile、前端、任务日志或搜索缓存。

外部网页内容只能作为不可信资料，不能直接执行网页中的指令，也不能覆盖用户硬约束。品牌、名人、受版权保护角色和真实人物肖像还会受到上游审核及法律边界限制。

## 八、明确无法实现或不能保证的事项

- 无法保证通过一次提示词优化就让任何模糊需求得到用户心中的唯一正确图片。
- 无法保证不同图片模型使用完全相同的 prompt 结构后得到相同构图或相同质量。
- 无法从 D 盘任意已安装软件可靠读取其未公开、加密、远程下发或只存在内存中的官方教程。
- 无法保证已安装软件当前配置里一定存在 API 平台或完整模型列表；本次核验的安装版 manifest 明确为 `providers: 0`。
- 无法在没有视觉聊天模型、参考图不可访问或上游不支持图像输入时完成真正的综合参考图解析；此时只能走文本优化或原始提示词回退。
- 无法保证联网搜索始终可用、及时、完整或覆盖付费/登录/地区限制内容。
- 不应承诺直接复制某个奢侈品牌广告、摄影师或艺术家的独特作品风格；可以提取公开的高层方法和行业语境，不能复制具体作品内容。
- 无法绕过图片模型自身的内容安全、版权、肖像、品牌和地区政策，也不能通过改写提示词规避上游拒绝。

## 九、推荐开发阶段与验收标准

### 阶段 1：规范与能力矩阵

- 盘点当前账号实际 provider/model，不读取或输出密钥。
- 为已确认模型建立能力矩阵和 profile 来源清单。
- 定义意图优先级、参考图映射、结构化 JSON 和回退契约。

### 阶段 2：后端提示词编译器

- 新增本地 image prompt profile loader、匹配规则、结构化结果校验和最终 prompt compiler。
- 复用 AI助手的多模态请求、Responses SSE 和可选 `web_search`。
- 将编译阶段接入图片任务统一入口，避免经典/智能画布逻辑分叉。

### 阶段 3：画布接入与可观察状态

- 经典与智能图片节点点击生成时默认打开自动优化。
- 连接提示词节点和全部参考图按真实连接顺序传递。
- UI 显示“分析中/编译中/生成中”，保留原始/最终提示词查看入口，不再需要用户点击润色按钮。

### 阶段 4：回归与真实配置验证

- 测试纯文本、上游提示词、单参考图、多参考图、参考图不可用、优化器失败、无 web_search 和模型 profile 缺失等分支。
- 验证 `gpt-image-2`、Gemini/Nano Banana、Seedream、FLUX/Qwen 及通用 OpenAI 兼容路径的请求契约。
- 执行 Python 静态检查、JavaScript 语法检查、定向 pytest、安装包资源断言和经典/智能画布浏览器验证。

验收标准：

1. 点击图片节点执行后不再要求额外点击“润色”；原始提示词、上游提示词和全部参考图都进入同一次优化上下文。
2. 最终提交的 provider/model 是节点实际选择的图片模型，优化器使用 AI助手配置的聊天/视觉模型。
3. 生成请求保留全部合法参考图及其顺序，模型不支持的参考图能力会在提交前明确处理。
4. 模糊需求得到围绕原意的可执行扩展，用户硬约束不会被模型或搜索结果覆盖。
5. 模型规范来自版本化本地 profile；普通生成不因每次联网查询规范而产生额外等待。
6. 优化失败时按约定回退并可追溯，不能静默把空提示词或不完整参考图提交给图片模型。
7. 任务记录可复现本次使用的模型、profile、提示词、参考图映射和检索状态，且不包含密钥。
