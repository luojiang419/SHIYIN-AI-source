## 任务目标

把现有 Lookbook 节点改造成面向故事创作的智能节点：用户只需在编辑框输入故事或广告需求，点击“生成 Lookbook”，后台 AI 助手自动完成需求理解、显式参数提取、参考素材分析、连续故事设计、逐镜头分镜拆解、图片提示词编译和有序图片生成。

用户在文本中明确提出的数量、画幅、分辨率、质量、时长/节奏或镜头类型必须进入结构化任务设置。例如：

> 生成 20 张 16:9、4K 的故事分镜图，讲述模特穿着黑色风衣在雨夜从地铁站走到街角书店，最后停在橱窗前。

系统应生成恰好 20 张独立画面，并让第 1 张到第 20 张形成可理解的开场、发展、转折、高潮和收束，而不是生成 20 张互不相关的时尚照片或一张包含多个格子的拼图。

## 当前项目现状

### 已有可复用能力

- `static/js/canvas-lookbook-node.js`：Lookbook 节点 UI、自动风格、参考端口、参数输入和节点状态。
- `static/js/canvas.js`：`runLookbookNode`、`pollEcommerceLookbookTask`、输出节点创建、任务恢复和级联运行。
- `main.py`：`/api/ecommerce/tasks`、SQLite/磁盘任务持久化、Lookbook agent 阶段、总超时、参考图事实分析、联网研究和 art direction。
- `canvas_core/ecommerce.py`：Lookbook 的参考图语义、统一 prompt、数量/尺寸解析和图片生成路由。
- 视频节点自动解析：`/api/canvas-video-auto-parse-tasks`、多图一次性综合、用户故事作为叙事主线、模型 Skill 注入、稳定图片标签、阶段化后台任务和 SSE/短轮询经验。
- 现有 Lookbook 的 `lookbook_generation_prompts`：已经有单幅图片硬约束，可作为逐镜头 prompt 的底层保护，但不能继续作为唯一的故事规划器。

### 必须解决的现有限制

1. `EcommerceTaskRequest.count` 和电商公共生成逻辑当前按最多 4 张设计，不能直接把普通电商任务全局放大到 20。
2. 当前 Lookbook 主要依赖预设的 4 张镜头角色，缺少由故事因果推导出的镜头数量和顺序。
3. 当前生成任务把同一个全局 prompt 与固定卡片组合，缺少人物状态、服装、道具、空间、光线和上一镜头收束状态的连续性字段。
4. 20 张图不能假设图片 provider 支持单次 `n=20`；需要在 agent 层控制单镜头任务、并发度、结果顺序和部分失败重试。
5. 前端当前数量控件 `max=4`，轮询客户端超时固定为 30 分钟，不能根据 20 张图和后台规划动态显示预计任务量。

## 产品交互方案

### 主路径

Lookbook 节点的核心界面改成：

1. 一个较大的“故事 / 广告需求”编辑框。
2. 一个主按钮“生成 Lookbook”。
3. 自动风格保持默认，不要求用户先选择视觉预设。
4. 现有画幅、分辨率、质量、数量和图片平台/模型放入“高级设置”，继续支持手动调整。
5. 点击后先进入“理解需求 / 规划分镜”，规划完成后自动生成，不弹出必须确认的中间步骤。
6. 节点底部显示当前阶段，例如“正在拆解 20 个连续镜头（3/20）”“正在生成第 8 个镜头”“已完成 17/20 张”。
7. 提供一个轻量“查看分镜规划”入口，用于查看镜头序号、剧情节拍、景别、动作和连续性；不阻断自动生成主流程。

现有参考图端口继续有效。用户没有连接参考图时，AI 只能依据文字创作；连接了人物、商品或场景时，这些图片是身份、商品几何、空间和材质事实的约束，不能被故事解析阶段擅自替换。

### 参数优先级

为避免“文本写了 20 张但控件仍是 4 张”的问题，采用以下规则：

1. 用户明确手动改过的高级控件优先级最高。
2. 高级控件保持默认值时，故事文本中的明确参数覆盖默认值。例如默认数量 4，但文本写“20 张”，最终使用 20。
3. 文本未出现的字段使用节点当前值；节点新建默认沿用现有 `16:9 / 2k / high / 4 张`，保持旧节点兼容。
4. 解析结果必须回写节点控件和任务快照，让用户能看到系统实际采用的参数。
5. 文本存在冲突时保留解析警告并采用“手动控件 > 文本中最后一次明确指令 > 默认值”的规则，不静默猜测。

### 自然语言参数识别

先使用确定性解析锁定高置信度字段，再由 AI 解析故事语义；不能让 LLM 自由返回一个未经校验的数量。

- 数量：`20张`、`生成二十幅`、`做 12 个镜头` → `count=20`。
- 画幅：`16:9`、`横版`、`竖屏`、`9比16` → 标准比例。
- 分辨率：`1K`、`2K`、`4K`、`高清`、`超清` → `1k/2k/4k`。
- 质量：`高质量`、`快速出图`、`自动质量` → `high/medium/auto`。
- 交付类型：`故事分镜图`、`时装大片`、`广告组图`、`海报` → 影响镜头编排和留白规则，但不改变“每张独立图片”的底层契约。
- 节奏：`开场-发展-转折-结尾`、`先…然后…最后…`、`逐渐下雨` → 转换为镜头因果与状态变化。

Lookbook 故事模式数量上限建议为 20；超过 20 时前端和后端都明确提示“当前最多生成 20 张”，并在生成前截断/拒绝，不能提交后才静默少生成。普通电商节点继续保持 1～4 张。

## 技术方案

### 总体数据流

```text
用户故事 + 节点高级参数 + 参考图
        ↓
需求解析 brief_parse（显式参数、故事目标、限制条件）
        ↓
参考事实分析 reference_facts
        ↓
全局视觉圣经 campaign_bible
        ↓
精确 N 张连续镜头 shot_cards[0..N-1]
        ↓
逐镜头 prompt 编译（全局圣经 + 当前镜头 + 模型 Skill）
        ↓
受控并发图片任务（保持 index 顺序）
        ↓
逐张校验 / 失败镜头重试 / 结果回写
```

### 1. 任务协议：复用现有持久化任务

推荐继续使用 `/api/ecommerce/tasks`，不新建一套重复的图片任务协议。Lookbook 请求增加：

```json
{
  "operation": "universal",
  "options": {
    "prompt_policy": "lookbook",
    "lookbook_mode": "story-campaign",
    "instruction": "原始用户故事或需求",
    "lookbook_count": 20,
    "lookbook_parse_source": "brief",
    "lookbook_manual_overrides": {},
    "lookbook_style": {"id": "auto", "name": "自动"}
  },
  "count": 20,
  "aspect_ratio": "16:9",
  "resolution": "4k",
  "quality": "high"
}
```

任务公共字段新增/扩展：

- `agent_stage`：`queued`、`brief-parse`、`reference-analysis`、`art-direction`、`storyboard`、`prompt-compile`、`generation`、`continuity-check`、`completed`、`failed`、`timeout`。
- `brief_parse`：原始文本、结构化字段、字段来源、冲突和警告。
- `lookbook_bible`：人物/服装/商品/场景/道具/色彩/光线/镜头语法/负面约束/连续性锁。
- `lookbook_shot_cards`：完整分镜卡数组，按 `index` 排序持久化。
- `lookbook_generation`：`requested_count`、`completed_count`、`failed_indices`、`retry_count`、`concurrency`。
- `partial_result`：继续复用现有部分结果，但每个图片项增加 `shot_index`、`shot_role`、`beat` 和 `prompt` 元数据。

任务必须在每个阶段完成后写入 SQLite/磁盘，前端中途关闭后能通过任务 ID 恢复，不重新规划或重复提交已完成镜头。

### 2. 需求解析器 brief_parse

新增一个 Lookbook 专用解析函数/模块，分为两层：

1. `parse_explicit_lookbook_settings(text)`：正则、中文数字和枚举归一化，只负责高置信度的数量/画幅/分辨率/质量/交付类型。
2. `parse_lookbook_brief_with_ai(...)`：复用视频自动解析的 `CanvasLLMRequest` 与后台任务模式，读取完整故事、角色、动作、因果、情绪、场景变化和用户限制，严格输出 JSON。

AI 输出至少包含：

```json
{
  "logline": "一句话广告故事",
  "beats": ["开场", "发展", "转折", "高潮", "收束"],
  "subjects": [],
  "locations": [],
  "must_keep": [],
  "must_avoid": [],
  "requested_settings": {"count": null, "aspect_ratio": null, "resolution": null, "quality": null},
  "delivery_type": "fashion-storyboard"
}
```

解析失败时，如果确定性层已经识别到明确参数，可以保留参数但必须停止在规划阶段并显示“故事结构解析失败，请重试”；不能静默退回固定四张普通广告图。

### 3. 全局视觉圣经 campaign_bible

参考图事实分析和故事解析完成后，由 AI 助手生成一次全局圣经，作为所有镜头的共同约束。内容包括：

- 人物身份：脸型、肤色、发型、体态、年龄感、表情基线。
- 服装与商品：款式、颜色、材质、穿着关系、Logo/文字保护和不可改变的几何细节。
- 场景地图：地点、空间布局、入口/出口、光源方向、天气、时间和可用道具。
- 叙事状态：人物初始状态、欲望/任务、关键触发、转折、结束状态。
- 视觉系统：主色/辅色/强调色及比例，曝光、对比、胶片/数字质感、镜头高度和景别语法。
- 连续性锁：衣物穿着、道具所在手、人物朝向、天气演进、空间方向、上一镜头结束状态与下一镜头起始状态。
- 反普通化约束：禁止无意义棚拍、静态证件照、无因果换场、无理由换装、拼图/网格/分屏和泛化质量词。

联网研究继续作为可选方法证据，只允许提取色彩、构图、动作、光线和留白等可迁移方法，不得复制品牌、模特、Logo、文案、地点或独特构图。联网结果不能成为故事主体来源。

### 4. 连续镜头 shot_cards

AI 必须根据 `count` 生成恰好 N 张卡片；不按固定 4 张模板循环。每张卡至少包含：

```json
{
  "index": 1,
  "beat": "开场",
  "story_purpose": "建立地铁站与人物任务",
  "time_position": "故事开始",
  "location": "地铁站出口",
  "subjects": [{"id": "person-1", "role": "主角", "action": "走出出口"}],
  "wardrobe_state": "黑色风衣扣合，左手持纸袋",
  "prop_state": "纸袋在左手，未打开",
  "camera": {"shot_size": "环境远景", "angle": "眼平", "movement": "侧向跟拍"},
  "composition": "人物位于左三分之一，保留右侧城市空间",
  "lighting": "雨夜冷色环境光，地铁出口暖光为动机光",
  "continuity_in": "从上一张的地铁门合拢状态开始",
  "continuity_out": "人物向画面右侧书店方向离开",
  "reference_ids": ["lookbook_reference_1", "lookbook_reference_3"],
  "prompt": "由后端编译，不接受模型自行改变 index"
}
```

分镜规划硬规则：

- 第 1 张建立空间和人物初始状态；最后 1 张完成情绪/商品/品牌视觉收束。
- 相邻镜头必须有可描述的状态变化或因果关系，不能只有“换个角度”。
- 每张只有一个主要动作，复杂动作拆成准备、执行、反应或结果的不同镜头。
- N 大于 8 时按故事段落分配镜头，而不是平均重复同一动作；建议至少覆盖开场、发展、转折/揭示和收束四个阶段。
- 景别、机位、前景遮挡、人物朝向和动作节奏要有目的地变化，但全局视觉圣经保持稳定。
- 多主体必须记录主次、视线、接触关系和错峰反应，避免所有人物同步摆姿势。

### 5. 图片生成与 20 张任务执行

图片 provider 的 `n` 参数不作为 20 张能力前提。推荐 Lookbook 故事模式按“单镜头单图片”执行：

- 每个 shot card 编译为一个独立图片生成请求，`n=1`，保留 `shot_index`。
- agent 使用受控并发，默认并发 3；根据 provider 路由能力和速率限制动态降到 1～2。
- 结果按 `shot_index` 写入数组，不按返回完成先后排列。
- 每完成一张就更新 `partial_result`，前端可以即时看到已完成缩略图和进度。
- 单镜头失败只重试该 index，最多 2 次；不重复生成已成功镜头，不自动切换到语义不兼容的模型。
- 若 provider 支持批量且明确允许的 `n` 范围，可按小批次执行，但仍必须在本地建立 shot index 映射。

为了降低连续性漂移，可在生成前按段落选出 1～4 张视觉锚点；后续镜头优先携带原始参考图和对应锚点，而不是把全部 20 张结果互相作为参考，避免超过模型参考图上限和成本失控。第一期先以“全局视觉圣经 + 相邻状态 prompt + 有序生成”为主，锚点增强作为同一任务内的可选优化。

### 6. Prompt 编译规则

每张最终图片 prompt 按以下顺序拼接：

1. 当前图片模型 Skill 正文和 provider 规则。
2. 全局视觉圣经中的身份、服装、场景和连续性锁。
3. 用户原始故事中与当前镜头相关的不可违背要求。
4. 当前 shot card 的剧情节拍、动作、景别、构图、光线和 `continuity_in/out`。
5. 对应参考图的稳定标签和使用理由。
6. 单幅图片硬约束：只输出一张 full-bleed 图片，禁止 grid/contact sheet/collage/split-screen/storyboard 排版。

模型只能执行当前 shot card，不能把第 1～20 张镜头描述全部渲染进同一张图；“故事分镜图”表示一组独立图片，不表示单张拼图。

## 验收标准

### 功能验收

1. 用户只输入一段故事并点击“生成 Lookbook”，无需手动填写 prompt 或逐张创建节点，即可启动完整广告组图任务。
2. 输入“生成 20 张 16:9、4K 的故事分镜图”时，任务快照、节点控件、分镜规划和结果元数据均为 `count=20`、`aspect_ratio=16:9`、`resolution=4k`。
3. 成功任务返回恰好 20 个独立图片结果；每张包含稳定的 `shot_index`，前端显示顺序为 1～20。
4. 20 张图的 shot cards 有明确故事段落、相邻镜头状态变化、动作因果、景别/机位变化和最后收束，不是固定四卡片循环。
5. 每张图都是单幅 full-bleed 画面，不出现联系表、九宫格、分屏或把全部镜头挤进一张图。
6. 参考人物身份、服装、商品几何、场景空间、Logo/文字约束在全局视觉圣经和逐镜头 prompt 中保持一致。
7. 单张失败只重试失败镜头；已完成镜头不重复计费、不改变顺序；任务重启后可从已完成 index 恢复。
8. 普通电商节点仍保持最多 4 张，旧 Lookbook 任务和旧画布 JSON 可以正常加载。

## 风险与处理

| 风险 | 处理方案 |
|---|---|
| LLM 输出数量与用户文本不一致 | 确定性 parser 先锁定数量；schema 校验不一致则拒绝进入生图 |
| 20 张并发触发 provider 限流 | 单镜头 `n=1`、默认并发 3、指数退避；只重试失败 index |
| 长故事超过模型上下文 | brief、bible、shot cards 分阶段生成；每张 prompt 只注入必要的当前镜头信息 |
| 多张图片人物/服装漂移 | 全局视觉圣经、连续性锁、稳定参考标签和段落锚点；末尾做连续性抽检 |
| 生成结果先后顺序错乱 | 所有任务带 `shot_index`；持久化和前端渲染统一按 index 排序 |
| 用户以为“分镜图”必须是一张九宫格 | UI 和系统 prompt 明确“一组独立图片”；提供分镜预览而不是让模型生成拼图 |
| 需求解析失败后退回普通广告 | 故事模式解析失败直接停在规划阶段并显示错误，不静默生成无关图片 |
| 修改公共电商数量规则导致回归 | `1～20` 只对 `prompt_policy=lookbook` 且 `lookbook_mode=story-campaign` 生效，其它 operation 继续 1～4 |

- 故事模式核心代码已实现，分镜预览弹窗和真实付费生成验收仍未完成。
