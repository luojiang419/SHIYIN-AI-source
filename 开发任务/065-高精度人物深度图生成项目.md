## 任务目标

建立可频繁调用、结果可追溯、对网络路径和中文路径稳定的深度图生成能力，同时提供两级模式：

- 快速档：复用现有 `Depth Anything V2 Small FP16 ONNX` CPU 实现，适合画布即时参考和一般场景深度。
- 高质量人物档：使用更高质量的深度模型与人物前景精修，适合人像后期、景深、视差、位移和 3D 辅助用途，输出 16-bit 深度及独立蒙版。

优先交付稳定的核心模块和 CLI；API、UI、队列化与画布入口在核心能力验收后按真实调用需求接入。

## 技术方案

### 模式与职责

- 保持现有 `DepthInference` 为 `fast/scene` 模式，继续承担轻量 CPU 深度任务。
- 新增独立 `high/person` 实现，不把 PyTorch、Transformers、CUDA 和人物分割依赖强制加载到普通启动路径。
- 通过统一请求参数表达 `quality=fast|high`、`subject=scene|person`、`bit_depth=8|16`，内部按模式路由；第一阶段 CLI 可先使用等价命令行参数。
- 高质量模式没有可用 CUDA 时必须给出明确错误或显式降级提示，不得静默输出低质量结果并仍标记为 high。

### 数据流

1. 读取本地文件、UNC 网络文件或批量目录，验证格式、尺寸和可读性，不修改源文件。
2. 计算源文件指纹并检查任务缓存；缓存键包含模型 revision、推理尺寸和关键参数。
3. 深度模型生成浮点相对逆深度，数值越大表示越靠近相机。
4. `subject=person` 时运行前景分割，生成软蒙版并精修发丝和细长物体边缘。
5. 仅依据人物前景有效区域的 1%～99% 分位归一化；约定白色更近、黑色更远，背景固定为 0。
6. 输出 16-bit 深度 PNG、8-bit 预览 PNG、可选蒙版和叠加图，并写入 JSON manifest。

### 输出规范

- 主深度文件：与原图同宽高、单通道 `uint16` PNG、范围 0～65535。
- 预览文件：与原图同宽高、单通道 `uint8` PNG、范围 0～255。
- 人物蒙版：与原图同宽高，默认同时保留 16-bit 软蒙版与 8-bit 预览。
- 深度方向：近处为白，远处为黑；背景为 0。
- 因背景与人物最远端都可能接近 0，消费方需要精确区分时必须同时读取人物蒙版。
- manifest 至少记录源路径/指纹、源尺寸、模型和 revision、设备、推理尺寸、归一化分位、耗时、输出文件及错误状态。

### 性能、并发与缓存

- 高质量模式使用单 GPU worker 和进程内推理锁，避免多个 Large 模型同时占满 16GB 显存。
- 模型实例在批处理中复用，禁止每张图重复加载权重。
- 大文件下载必须支持代理、断点续传、完整性校验、明确进度和失败重试；不得依赖匿名在线请求每次重新拉取。
- 原始浮点深度缓存默认可关闭或设置过期清理；不得让批量任务无限累积 96MB 级 `.npy` 文件。
- 输出 4000×6000 不代表模型拥有原生 4K 几何细节；当前有效推理尺寸为深度约 1078、蒙版 1024，原尺寸输出主要用于位深和边缘保存。

### 兼容性与安全

- Windows 中文路径和 UNC 路径必须作为一等输入测试；OpenCV 直接 `imwrite` 中文路径可能静默失败，应使用 `imencode` 后写入并检查返回值。
- 所有模型在本机推理，不上传用户原图。
- 模型依赖采用延迟导入，未安装高质量依赖时不得影响现有快速深度接口和应用启动。
- 模型权重、下载临时文件、浮点缓存和大批量输出必须纳入 `.gitignore` 或存放于账号数据目录。
- `Depth Anything V2 Large` 为 `CC-BY-NC-4.0`；商业产品不得在未确认许可前默认启用。需要评估可商业使用的替代模型或单独获得授权。

### 软件集成方案

#### 推荐架构：安装包外置的高精度组件

- 主安装包只包含轻量 `PersonDepthComponentManager`、状态 API、首次运行弹窗、任务编排和 worker 协议，不包含模型权重、PyTorch、Transformers、Torchvision、Kornia 或 CUDA 运行时。
- 把已验证算法封装为独立 `person-depth-worker` 进程。为了不依赖用户本机 Python 环境，worker 自带版本锁定的运行时，但和模型一样在用户确认后下载，不进入正式安装包。
- 模型与运行时分包：`person-depth-models-v1` 保存 Depth Anything V2 Large 与 BiRefNet 固定 revision；`person-depth-runtime-win-x64-v1` 保存 worker 和重型依赖。分包后模型更新无需重复下载运行时，也能为未来 CPU/CUDA 或其他模型变体单独发布。
- 当前两套权重实测合计约 1.79GB；独立 worker 压缩包体积必须在首次正式构建后实测，UI 不得在未测量前显示虚假总大小。
- 组件安装到 `ACCOUNT_STORE.system_root / "models" / "person-depth"` 与 `ACCOUNT_STORE.system_root / "runtimes" / "person-depth"`，属于整台机器共享数据，不放入账号目录；升级安装继续复用。
- 现有 `DepthInference` 与 `/api/depth/estimate` 保持快速 CPU/角度参考职责。一键复刻的高精度深度模式只调用新的 `/api/person-depth/estimate`；组件未就绪时提示下载或允许用户切换骨架模式，不得静默降级为 Small ONNX 并仍标记为高精度。

#### 首次运行与按需下载

1. 后端启动只校验组件 manifest，不自动下载高精度组件，确保 `/api/health` 和主界面快速可用。
2. 本机桌面首屏完成登录后请求 `/api/person-depth/component/status`。若所需版本缺失且该版本尚未提示，显示一次下载弹窗。
3. 弹窗说明功能用途、已确认的模型体积、仍需实测的运行时体积、磁盘位置、非商业许可证边界和“下载后升级无需重复下载”。
4. 用户选择“立即下载”后由后端后台任务下载；选择“稍后”不阻塞软件，进入一键复刻深度模式时再次按需提示。
5. 下载进度属于系统级任务，切换页面或账号不会中断；关闭应用后保留 `.part`，下次从 Range 断点续传。
6. 完成下载后依次执行文件大小检查、SHA-256、受控解包、原子目录切换、worker 版本握手和内置小图 smoke；全部通过后状态才可进入 `ready`。
7. 设置页增加“高精度人物深度组件”管理区，显示版本、大小、来源、状态、重新校验、继续下载和删除组件。删除仅允许本机管理员执行。
8. 一键复刻节点订阅同一系统级组件状态，下载中每 1.5 秒刷新整数百分比、已下载/总量与来源；多个节点不得启动重复下载。
9. 下载完成后节点依次显示“校验中”“安装中”“正在验证组件”，只有 `ready` 后才恢复生成按钮；下载期间其他参数和提示词仍可编辑。

#### 下载源与代理顺序

- 每个组件包由内置只读 manifest 描述：`id`、`version`、`platform`、`size`、`sha256`、`domestic_url`、`official_url`、模型 revision、许可证和最低磁盘空间。
- 推荐使用项目可控的版本化国内对象存储或 ModelScope 资产作为 `domestic_url`，禁止依赖会改变内容的 latest URL。
- 自动顺序：国内镜像直连 → 官方外网源（Windows 系统代理）→ 官方外网源直连作为最后回退。
- Windows 系统代理继续通过 `urllib.request.getproxies()` 读取；`requests.Session.trust_env=False`，只显式注入解析出的 `http/https` 代理，防止环境与系统配置叠加产生不可解释行为。
- 若代理 URL 含账号密码，公共状态 API、日志和错误弹窗不得输出完整代理地址；只显示“已检测到系统代理”。
- 国内镜像和官方源下载到同一内容寻址候选文件，必须通过相同 SHA-256；来源不同不能降低校验标准。

#### 下载器状态机与失败处理

- 状态：`missing → awaiting-consent → checking-space → downloading → verifying → installing → smoke-testing → ready`。
- 失败状态必须带阶段码：`insufficient-space`、`network-failed`、`proxy-unavailable`、`checksum-failed`、`extract-failed`、`runtime-incompatible`、`smoke-failed`。
- 开始前按“压缩包 + 解包后文件 + 安全余量”计算磁盘需求；空间不足时不创建大文件。
- 使用系统级互斥锁防止多个页面、多个账号或重复点击启动多个下载；重试复用已完成分包和合法 `.part`。
- 解包必须防 Zip Slip，先写入 staging，校验通过后用版本目录与 active manifest 原子切换；旧版本在新版本 smoke 通过后再进入可清理状态。
- worker 崩溃、CUDA 不可用或显存不足时必须明确报错。可以让用户手动选择快速深度或骨架模式，但不得自动冒充高精度成功。

#### Worker 协议与安全边界

- 主后端通过受控子进程调用 worker，输入使用本地临时文件或受控管道，输出 16-bit 深度、8-bit API 预览和人物蒙版；任务结束后按策略清理临时文件。
- worker 启动时输出协议版本、模型 revision、设备、可用显存和能力；主程序发现版本不匹配时阻止推理并要求修复组件。
- 当前原型对 BiRefNet 使用 `trust_remote_code=True`。产品化时必须把固定 revision 的模型结构代码审查后纳入 worker 包，并改为本地加载，禁止运行时执行远端仓库代码。
- 下载 manifest 和组件包需要固定 SHA-256；如未来具备签名基础设施，再增加签名验证，不能只依赖 HTTPS。
- 公共状态 API 只返回进度、阶段和友好信息；本地路径、代理详情、下载错误链和源尝试记录只允许本机管理员读取。

#### 与一键复刻的调用链

1. 动作参考变化后计算源图指纹，按模型 revision、推理尺寸、人物前景策略生成缓存键。
2. 一键复刻节点处于深度模式时查询高精度组件状态；未就绪则打开下载弹窗，不提交图片生成任务。
3. 组件就绪后调用 `/api/person-depth/estimate`，worker 输出人物深度与 mask；API 返回用于 Nano Banana Pro 的 8-bit 深度 PNG，16-bit 与 mask 可保留在系统缓存用于复核。
4. 深度图按固定参考顺序插入为图2，并在提示词中同时约束姿势、人物体积、遮挡和动作造成的自然褶皱受力结构。
5. 提示词只能复刻动作参考中的褶皱位置、走向、堆叠、拉伸和受力逻辑；褶皱的厚度、锐度和幅度仍由目标服装的材质、版型和松量决定，避免把旧衣表面机械贴到新衣。
6. 缓存命中时直接复用控制图；失败时保持动作参考和用户文本，允许重试深度提取或切换骨架模式。

## 验收标准

1. CLI 可处理单个本地文件、UNC 网络文件和目录批量输入，源文件不被修改。
2. 快速档继续通过现有测试，高质量档不影响应用冷启动或未安装 GPU 依赖的环境。
3. 高质量人物档稳定输出同尺寸 16-bit 深度 PNG 与人物蒙版，近白远黑、背景为 0。
4. 对头发、手指、衣物边缘和细长随身物体进行真实样本目视回归，不出现明显背景泄漏或人物缺口。
5. 重复处理相同文件时可命中模型和任务缓存，批量任务复用模型实例，不重复加载权重。
6. Unicode/UNC 路径、损坏图片、无 GPU、显存不足、模型下载中断和输出写入失败均有明确错误。
7. 每个输出目录包含可追溯 manifest，模型 revision 和处理参数可复现。
8. 自动化测试、相关集成测试、静态检查和至少一组真实高分辨率回归全部通过。
9. 模型权重、临时缓存和大批量输出不进入 Git；商业启用前完成许可证确认。
10. 干净安装包和 PyInstaller 后端不包含 person-depth 权重、torch、transformers 或 CUDA worker。
11. 首次运行弹窗只由本机桌面会话触发，用户可稍后处理且不阻塞软件其他功能。
12. 国内镜像失败后自动尝试 Windows 系统代理访问官方源；所有来源共享大小与 SHA-256 校验，并支持断点续传。
13. 组件只有在原子安装、worker 版本握手与内置小图 smoke 全部通过后才进入 `ready`。
14. 一键复刻高精度模式不会静默降级为快速 Small ONNX；未就绪时提示下载或由用户显式切换骨架模式。
15. 下载期间节点内持续显示百分比、已下载/总量、来源和阶段；下载到 100% 后仍明确显示校验、安装与 smoke 状态。

## 已知问题

- 当前是单图脚本，输入、输出和模型参数仍为常量，无法直接批量复用。
- 高质量模型依赖 PyTorch、Transformers、Torchvision、Kornia 和 CUDA，尚未纳入项目依赖隔离与安装检查。
- `Depth Anything V2 Large` 许可证不允许直接用于商业默认能力，需替代模型或授权方案。
- 当前生成的是单目相对深度，不是带真实单位的 metric depth，不能直接解释为米或厘米。
- 原尺寸输出来自较低有效推理尺寸的回采样，细节精度受模型输入分辨率限制。
- 人物分割会把与人物相连的包带等前景物体一并保留；后续需要可选的“仅人体/人物及随身物”语义策略。
- 原型保留约 96MB 的 `XSY_1801_raw_depth.npy`，批量模式需要明确缓存生命周期和清理策略。
- 尚未创建回归样本集，也未测试多人、透明衣物、复杂背景、全身脚部和强遮挡场景。
- 尚未建立高精度组件的国内镜像资产与正式 SHA-256 manifest，不能在实现前虚构下载 URL。
- 独立 worker 运行时压缩/解压体积尚未测量，首次运行弹窗只能在构建实测后显示准确总大小。
- 当前原型使用 `trust_remote_code=True` 加载 BiRefNet，产品化前必须改为审查后的本地固定代码。
