## 任务目标

建立可频繁调用、结果可追溯、对网络路径和中文路径稳定的深度图生成能力，同时提供两级模式：

- 快速档：复用现有 `Depth Anything V2 Small FP16 ONNX` CPU 实现，适合画布即时参考和一般场景深度。
- 高质量人物档：使用更高质量的深度模型与人物前景精修，适合人像后期、景深、视差、位移和 3D 辅助用途，输出 16-bit 深度及独立蒙版。

优先交付稳定的核心模块和 CLI；API、UI、队列化与画布入口在核心能力验收后按真实调用需求接入。

## 技术方案

### 模式与职责

- 保持现有 `DepthInference` 为 `fast/scene` 模式，继续承担轻量 CPU 深度任务。
- 新增独立 `high/person` 实现，不把 PyTorch、Transformers、CUDA 和人物分割依赖强制加载到普通启动路径。
- 通过统一请求参数表达 `quality=fast|high`、`subject=scene|person`、`bit_depth=8|16`，内部按模式路由；第一阶段 CLI 可先使用等价命令行参数。
- 高质量模式没有可用 CUDA 时必须给出明确错误或显式降级提示，不得静默输出低质量结果并仍标记为 high。

### 数据流

1. 读取本地文件、UNC 网络文件或批量目录，验证格式、尺寸和可读性，不修改源文件。
2. 计算源文件指纹并检查任务缓存；缓存键包含模型 revision、推理尺寸和关键参数。
3. 深度模型生成浮点相对逆深度，数值越大表示越靠近相机。
4. `subject=person` 时运行前景分割，生成软蒙版并精修发丝和细长物体边缘。
5. 仅依据人物前景有效区域的 1%～99% 分位归一化；约定白色更近、黑色更远，背景固定为 0。
6. 输出 16-bit 深度 PNG、8-bit 预览 PNG、可选蒙版和叠加图，并写入 JSON manifest。

### 输出规范

- 主深度文件：与原图同宽高、单通道 `uint16` PNG、范围 0～65535。
- 预览文件：与原图同宽高、单通道 `uint8` PNG、范围 0～255。
- 人物蒙版：与原图同宽高，默认同时保留 16-bit 软蒙版与 8-bit 预览。
- 深度方向：近处为白，远处为黑；背景为 0。
- 因背景与人物最远端都可能接近 0，消费方需要精确区分时必须同时读取人物蒙版。
- manifest 至少记录源路径/指纹、源尺寸、模型和 revision、设备、推理尺寸、归一化分位、耗时、输出文件及错误状态。

### 性能、并发与缓存

- 高质量模式使用单 GPU worker 和进程内推理锁，避免多个 Large 模型同时占满 16GB 显存。
- 模型实例在批处理中复用，禁止每张图重复加载权重。
- 大文件下载必须支持代理、断点续传、完整性校验、明确进度和失败重试；不得依赖匿名在线请求每次重新拉取。
- 原始浮点深度缓存默认可关闭或设置过期清理；不得让批量任务无限累积 96MB 级 `.npy` 文件。
- 输出 4000×6000 不代表模型拥有原生 4K 几何细节；当前有效推理尺寸为深度约 1078、蒙版 1024，原尺寸输出主要用于位深和边缘保存。

### 兼容性与安全

- Windows 中文路径和 UNC 路径必须作为一等输入测试；OpenCV 直接 `imwrite` 中文路径可能静默失败，应使用 `imencode` 后写入并检查返回值。
- 所有模型在本机推理，不上传用户原图。
- 模型依赖采用延迟导入，未安装高质量依赖时不得影响现有快速深度接口和应用启动。
- 模型权重、下载临时文件、浮点缓存和大批量输出必须纳入 `.gitignore` 或存放于账号数据目录。
- `Depth Anything V2 Large` 为 `CC-BY-NC-4.0`；商业产品不得在未确认许可前默认启用。需要评估可商业使用的替代模型或单独获得授权。

## 验收标准

1. CLI 可处理单个本地文件、UNC 网络文件和目录批量输入，源文件不被修改。
2. 快速档继续通过现有测试，高质量档不影响应用冷启动或未安装 GPU 依赖的环境。
3. 高质量人物档稳定输出同尺寸 16-bit 深度 PNG 与人物蒙版，近白远黑、背景为 0。
4. 对头发、手指、衣物边缘和细长随身物体进行真实样本目视回归，不出现明显背景泄漏或人物缺口。
5. 重复处理相同文件时可命中模型和任务缓存，批量任务复用模型实例，不重复加载权重。
6. Unicode/UNC 路径、损坏图片、无 GPU、显存不足、模型下载中断和输出写入失败均有明确错误。
7. 每个输出目录包含可追溯 manifest，模型 revision 和处理参数可复现。
8. 自动化测试、相关集成测试、静态检查和至少一组真实高分辨率回归全部通过。
9. 模型权重、临时缓存和大批量输出不进入 Git；商业启用前完成许可证确认。

## 已知问题

- 当前是单图脚本，输入、输出和模型参数仍为常量，无法直接批量复用。
- 高质量模型依赖 PyTorch、Transformers、Torchvision、Kornia 和 CUDA，尚未纳入项目依赖隔离与安装检查。
- `Depth Anything V2 Large` 许可证不允许直接用于商业默认能力，需替代模型或授权方案。
- 当前生成的是单目相对深度，不是带真实单位的 metric depth，不能直接解释为米或厘米。
- 原尺寸输出来自较低有效推理尺寸的回采样，细节精度受模型输入分辨率限制。
- 人物分割会把与人物相连的包带等前景物体一并保留；后续需要可选的“仅人体/人物及随身物”语义策略。
- 原型保留约 96MB 的 `XSY_1801_raw_depth.npy`，批量模式需要明确缓存生命周期和清理策略。
- 尚未创建回归样本集，也未测试多人、透明衣物、复杂背景、全身脚部和强遮挡场景。
