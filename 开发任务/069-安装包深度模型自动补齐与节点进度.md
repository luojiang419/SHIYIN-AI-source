## 任务目标

用户添加一键复刻节点或深度图节点后，如果高精度人物深度组件缺失，应用自动下载并补齐运行时与模型；节点内持续显示下载百分比、字节量、来源及校验/安装/smoke 阶段。组件完成后自动加载，并继续生成原本等待中的深度图。

## 当前项目现状

- `PersonDepthComponentManager` 已支持多包、断点续传、系统代理回退、SHA-256、安全解压、原子激活与 smoke。
- `/api/person-depth/component/status|install|retry` 和 `/api/person-depth/estimate` 已存在。
- 共用节点脚本已按 1.5 秒轮询 active 状态，多个节点共享同一份状态。
- 一键复刻与独立深度图节点在组件 `ready` 后都会根据输入签名自动调用推理。
- 内置 manifest 被禁用且没有下载地址，是全新安装环境的直接阻塞。
- candidate.3 runtime 为 `4,198,761,464` bytes，models 为 `1,786,166,020` bytes。

## 技术方案

- 保持现有组件格式和安装器数据目录，不把 6GB 组件塞入安装包。
- 构建期按文件做 first-fit runtime 分包，单包硬限制低于 GitHub 2GB；所有包仍解压到同一个 staging 根目录。
- 使用源代码仓库的组件专用 prerelease 承载下载资产，避免干扰 `SHIYIN-AI` 安装器仓库的 latest 更新语义。
- 正式 manifest 写入每个包的固定 URL、大小、SHA-256 和许可证来源；安装包继续随 `canvas-backend` 携带该 manifest。
- 前端绑定深度能力节点时，读取状态后自动调用 install；使用单一 Promise 和状态判定去重，多节点不会重复 POST。
- 下载失败不循环重试，节点显示失败状态和显式重试按钮。

## 验收标准

1. 全新组件目录中添加一键复刻或深度图节点后，无需二次确认即可启动一次组件下载。
2. 多个节点同时存在时只共享一次后台安装任务。
3. 节点显示整数百分比、已下载/总量、下载源及 verifying/installing/smoke 文案。
4. 下载支持断点续传，所有包通过大小与 SHA-256 校验后才激活。
5. 下载完成后已有输入的节点自动提交深度推理并得到 PNG 输出。
6. 安装包不包含大模型，升级后复用 `data/system/components/person-depth`。
7. 相关测试、全量测试、安装包构建与隔离空目录真实回归通过。
