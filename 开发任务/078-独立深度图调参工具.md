## 任务目标

开发一个不依赖主应用运行、与主应用业务文件完全隔离的暗黑模式 Tauri 桌面调参工具：

- 左上显示并支持选择/拖入输入图片。
- 右上显示深度图实时预览。
- 底部横向参数区提供比无限画布深度图节点更大的调整范围。
- 参数变化只进行本地非破坏式像素处理，不重复运行大模型，保证实时反馈。
- 支持把调整后的深度 PNG 保存到任意位置。
- 右下支持导出包含每项参数、范围、模型版本和兼容字段的版本化 JSON 配置。
- 支持重新导入配置，便于对比、复用和后续编译为无限画布默认参数。
- 直接复用已经安装的 person-depth worker 与模型，不重复安装或部署。

## 当前项目现状

- 主桌面端为 Tauri 2，Rust 入口位于 `src-tauri/`。
- 高精度组件由 `canvas_core/person_depth_components.py` 管理，当前激活信息保存在 `data/system/components/person-depth/current.json`。
- worker 命令由组件 `manifest.json` 的相对 `command` 决定，协议版本为 1，支持 `hello`、`estimate` 与 `shutdown`。
- 无限画布现有高级控制包含 `farPoint`、`nearPoint`、`midtone`、`contrast`、`brightness`、`smooth`、`invert`，范围较保守。
- 现有实时调整从原始深度图重算 256 级 LUT，不累积处理损失；新工具继续采用这一正确的数据流，并扩大范围。

## 技术方案

- 新增 `tools/depth-map-tuner/` 独立工程，拥有自己的 `package.json`、`frontend/` 与 `src-tauri/`。
- Rust 层按“环境变量 → 工具私有配置 → 源码/可执行文件祖先目录 → 常见安装目录”定位共享组件。
- 对 `current.json`、`manifest.json`、安装目录和 worker 路径做边界校验；用户也可手动重新定位组件目录。
- 每次更换输入图时由 Rust 启动共享 worker 执行一次 8-bit 推理；参数拖动全部在前端 Canvas 完成。
- 预览使用受限分辨率保持流畅；导出时从原始深度图按原分辨率重新渲染。
- 配置 JSON 同时保存人类可读说明、camelCase 画布兼容参数、参数范围、模型版本与输入元数据。
- 工具只向自身应用配置目录写入共享组件路径偏好；不会写入主应用配置或模型目录。

## 验收标准

1. 工具可独立启动，不要求 SHIYIN AI 主后端运行。
2. 自动识别当前已安装的 person-depth 组件，且不产生模型下载、复制或安装目录。
3. 页面为暗黑模式，桌面布局明确满足左上输入、右上预览、底部横向参数区和右下导出区。
4. 输入支持原生选择和拖放；更换输入后执行一次推理并显示尺寸、状态和模型版本。
5. 七项画布兼容参数均可调，数值范围明显大于节点高级控制；拖动时预览即时变化。
6. 调整始终基于原始深度图，不因反复拖动累积损失。
7. 可在任意目录保存完整分辨率 PNG；可在任意目录保存和重新导入 JSON 配置。
8. JSON 明确记录 schema、模型组件/版本、输入元数据、每项参数和值域，可直接用于后续默认参数编译。
9. Rust/JavaScript 专项测试、Tauri 编译和至少一次真实 worker 推理通过。
10. 主项目既有文件内容和用户工作区改动保持不变。
