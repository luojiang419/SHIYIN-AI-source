## 任务目标

在 `tools/video-depth-lab/` 建立独立技术验证项目：

- 部署 GemDepth 官方模型，并使用适配 16GB 显存的 8-frame 推理配置。
- 部署 Video Depth Anything Base，固定使用 FP16 与 Relative Depth，作为对比基线。
- 使用统一输入、采样、灰度深度视频和元数据输出协议验证两模型。
- 开发独立 Tauri 快捷操作软件，复用深度图调参软件的暗黑工作台布局语言。
- 在参数区增加“模型”下拉项，选择后实际切换对应模型进行测试。
- 支持视频选择/拖放、运行状态、进度、原视频与深度视频预览、后处理参数实时调整、结果与配置导出。
- 模型和 Python 依赖优先使用国内镜像；不自动设置或消耗代理流量。

## 当前项目现状

- 主项目为 Python 后端 + Tauri 2 桌面壳，但本工具要求位于 `tools/` 并与主应用隔离。
- `tools/depth-map-tuner/` 已有成熟的暗黑四区布局、七项画布兼容深度参数、Canvas 非破坏处理和 Tauri 文件对话框实现。
- GemDepth 官方源码当前 commit 为 `652865b`，官方单一 checkpoint 约 2.84GB，README 标注 8-frame 配置约需 15GB GPU 显存。
- Video Depth Anything 官方源码当前 commit 为 `4f5ae23`，Base relative checkpoint 使用 `video_depth_anything_vitb.pth`，官方默认支持 FP16。
- GemDepth 源码包含 Linux CUDA cuRoPE 构建产物，但也提供 PyTorch 回退实现；Windows 集成必须显式验证回退路径与显存边界。
- 工作区存在其他任务的大量已修改和未跟踪文件，本任务只处理 `tools/video-depth-lab/` 与本任务文档。

## 技术方案

- 新增独立 Tauri 2 工程，前端保持零框架 HTML/CSS/JavaScript，原生层使用 Rust 管理文件对话框、worker 生命周期和输出目录。
- 使用常驻 Python NDJSON worker 统一封装两个模型，避免每次参数调整重新加载模型；切换模型时释放旧模型并清理 CUDA cache。
- 推理统一读取视频帧，模型输出保存为原始相对深度数据与 8-bit 灰度 MP4；前端参数调整针对已生成深度视频做快速 FFmpeg 后处理，避免重复模型推理。
- GemDepth 将上游全局推理常量参数化为 8-frame profile，保持官方 checkpoint 严格加载；VDA 使用 `vitb`、非 metric、默认 autocast FP16。
- `setup.ps1` 优先使用清华 PyPI 镜像与 Hugging Face 国内镜像；所有下载失败后只回退直连官方地址，不写入系统代理、不自动使用 `127.0.0.1:7890`。
- `runtime/` 中的虚拟环境、上游源码、权重、输出和缓存全部作为本地部署产物忽略提交；仓库只保存安装脚本、适配层、应用源码、测试和版本清单。

## 验收标准

1. 项目完整位于 `tools/video-depth-lab/`，可独立安装、启动和构建，不依赖主应用后端。
2. 安装脚本不主动启用代理，日志可明确显示国内镜像、官方直连与实际下载来源。
3. GemDepth 官方 checkpoint 严格加载，并以 8-frame/4-overlap/2-interpolation 配置在 16GB GPU 上完成真实视频推理。
4. VDA Base relative checkpoint 严格加载，并以 CUDA FP16 完成同一视频推理。
5. 模型下拉项会真实切换 worker adapter，而非只改变界面文字。
6. 输入支持原生选择与拖放；界面明确显示输入信息、模型状态、进度、耗时、输出路径和错误原因。
7. 布局样式与既有深度图调参器一致，包含左侧原视频、右侧深度视频、底部横向参数区和右下操作区。
8. 深度后处理参数调整可快速预览，不重复运行模型；导出结果保留输入 FPS、时长和尺寸。
9. 配置可导入导出，记录模型、精度、深度类型、8-frame 配置、后处理参数和运行元数据。
10. Python/JavaScript/Rust 专项测试、双模型真实推理、Tauri release 编译和进程 smoke 均真实通过。
