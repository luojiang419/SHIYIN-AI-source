## 技术方案

- 新增统一的 Lookbook 前置准备函数，需求理解和参考事实分析并行；显式合并两支 options，避免丢失数量/画幅或分析结果。自动风格仍执行原风格选型，已选定风格直接在分镜 campaign_bible 中完成创意策划，保留身份、服装、场景、色彩、材质、版式和节奏契约。
- 可选搜索最多 30 秒，精简为针对性文字检索，不下载公开候选图片，不自动重试；超时或失败保存提示并继续。
- 质检默认关闭；打开质检默认仅检查，自动修复需另开开关。质检限时 60 秒，失败/超时继续交付原图；显式 max_retries=0 禁止修复。修复失败保留原图并记录，不触发整批补发。保留首帧连续性依赖，不以牺牲一致性换速度。
- 阶段记录真实耗时；完成文案区分未质检、通过、未达标与检查失败，不再统一声称完成研究与质检。
- 不打包、不安装或覆盖运行中的 1.0.417；本轮交付源码修复，安装版生效需后续构建。

## 验收标准

- 默认没有搜索、质检和二次生图；必要的三阶段（需求/事实/分镜）保留，已选风格不再单独请求策划。
- 需求与事实确实并行，取消/失败无遗留任务；数量、版式、图像映射、自动风格与场景/风格锁不回退。
- 搜索超过预算被取消并继续分镜；质检超过预算可交付图片；未通过不得显示已通过。
- 显式自动修复才会再生图；max_retries=0 生效；修复故障保留原图。
- 相关自动回归、JS/Python 静态和浏览器开关交互通过；真实调用报告耗时与输出结构，不推断未测画质。

## 真实调用结果

复用 103 同一任务、同一人物图、相同 2 张输出、选定标准广告风格和 gpt-5.6-terra，直接运行正式 `prepare_lookbook_creation`，每组从清空派生结果开始。未降低模型推理参数。

| 阶段 | 关闭搜索 | 开启搜索 |
| --- | ---: | ---: |
| 需求理解（与参考分析重叠） | 6.235 秒 | 6.953 秒 |
| 参考事实分析 | 37.890 秒 | 36.422 秒 |
| 搜索 | 0 秒，无请求 | 30.000 秒，取消后跳过 |
| 创意与分镜合并 | 112.938 秒 | 107.547 秒 |
| 前置实际总时间 | 150.832 秒 | 173.968 秒 |

关闭组只有 3 次 LLM 请求，开启组 4 次；需求与事实同时启动，未再请求独立策划。两组均产出 2 张可编译分镜和 2 份图片提示词，数量、镜头/节奏、风格与参考约束由正式校验器检查。开启组搜索 CancelledError 被预算捕获，后续分镜成功，没有返回搜索研究成功的虚假状态。

与 103 第二轮阶段合计基线（关闭 224.051 秒 / 开启 337.173 秒）相比，当前前置分别约减少 33% / 48%。旧基线复用共同前置时长，新验收实际完整执行，两者仍是小样本，不能当作所有任务的固定速度或最终画质对照；开启组还发生了明确的研究降级，不等同于原深度搜索完成。

默认质检不发 LLM 或修复图片请求，完整任务路径的模拟验证确认只生成一批并直接交付；未再真实生成整套图片，因此不声称实测最终总出图时间。103 中 224.868 秒的自动质检/修复等待在默认路径不再触发。
