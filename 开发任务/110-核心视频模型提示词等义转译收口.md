## 任务目标

保证 H3、可灵、Seedance 2.0、Seedance 2.5 之间切换时，提示词被直接编译为目标模型的官方/项目规范格式，并尽可能保持主体身份、参考职责、镜头结构、动作因果、空间、摄影、光影、对白和声音等创作语义一致。其他视频模型统一采用不含平台私有标签的通用自然语言提示词。

“效果接近一致”落实为可自动验证的语义等价和格式正确：不同生成模型与随机采样无法保证像素级一致，仍需真实付费 A/B 审片验证成片差异。

## 当前项目现状

- `canvas_core/video_prompt_registry.py` 负责模型到 Skill profile 的注册与加载。
- `canvas_core/video_prompt_adapter.py` 负责跨模型目标 profile、转换 system prompt、素材标签和结果校验。
- `main.py` 负责自动解析、润色、转换调用、参考素材清单与最终提交前校验。
- H3 使用三字段或 Ref2VA 六字段结构及 `<Picture N>`、`<Subject N>`、`<Video N>`、`<Audio N>`。
- 可灵 CLI Omni 使用 `<<<image_N>>>` / `<<<video_N>>>`，普通可灵和 LinkFox 可灵使用自然语言素材编号。
- Seedance 2.0 使用自然语言编号和镜头序号/相对节拍；Seedance 2.5 支持整数秒时间戳及锁定/非锁定任务。
- Hailuo、Wan、HappyHorse 仍在 `PROFILES` 和 `registered_profile()` 中专属路由。

## 技术方案

- `PROFILES` 只注册 H3、可灵 CLI、LinkFox 可灵、Seedance 2.0、Seedance 2.5；保留旧 Skill 文件但不再路由，不执行无关删除。
- 统一由注册表加载 Skill 及 `references/*.txt`，避免 H3/可灵只加载摘要。
- 在适配器中建立共享语义等价合同，覆盖主体/素材职责、镜头/时间、空间/视线、动作/物理、摄影/光影、对白/文字/声音和首尾帧状态。
- 各核心目标在共享语义上只改变目标模型格式，不以“优化”为名新增剧情、删减结尾或改变镜头意图。
- generic 使用图片N/视频N/音频N自然语言编号，禁止 H3、Kling、Hailuo 等平台私有字段和标签。
- 测试采用同一高信息量场景合同检查四类目标 system prompt、引用格式、源文字逐字保留和冷门模型 generic 路由；不通过 mock 文本声称真实生成效果已验证。
