## 当前项目现状

- `canvas_core/video_prompt_adapter.py` 用 QUOTED 提取引号内容和 `<d>` 对白，再执行 `value not in text`。
- 所有引号内容一律被当成对白/歌词/画面文字，没有类型、位置或差异信息。
- `prepare_video_generation_prompt` 最多调用两次 LLM；第二次只有原始请求和一条截断错误，未携带失败正文供定向修复。
- main.py 的润色路径也调用同一校验器，须同步检查，防止两个入口行为不同。
- 缓存按账号、请求、system、素材和路由隔离；校验规则更新需要显式版本进入缓存键。

## 原设计参考（后续方案，本轮不实施）

### 1. 统一受保护文字清单

新增 `canvas_core/video_prompt_literals.py`，将提取、匹配、诊断与安全修复放入纯函数，避免继续扩大 main.py。
每条记录包括 id、原始文字、来源位置、所属字段/镜头、类型（dialogue / lyrics / screen_text / unknown）和原文上下文。原始文字保留不变；去重仅合并完全相同项，保留所有出现位置。
优先识别 `<d>`，处理其语言标签；引号解析覆盖当前支持格式和跨行内容，并避免重复提取 `<d>` 内同一对白。英文单引号不能直接用宽泛正则提取，以免把 don't 等单词拆开。
类型识别依据明确的字段或邻近描述，无法可靠判定时为 unknown，继续严格保护。第一版不自动豁免所谓“装饰性引号”。

### 2. 适配前明确约束

在适配请求数据中加入 protected_literals，包含原文及来源职责，要求模型保持原语言、文字、说话人/画面归属。原文中的重复文字应一致表达。
解析和润色共享规则增加：同一招牌/字幕跨段重复引用时保持拼写一致；普通叙述标点放在引号外，除非确实属于画面文字。只调整项目提示词包装规则，不修改官方 Skill 源副本。
不引入新 LLM 调用，也不强制替换成占位符，以免影响说话人、歌词节奏及 H3 结构生成。

### 3. 严格校验与有限局部修复

先执行原文精确保留检查。格式容差只针对明确的外部包裹符号；默认不忽略大小写、不使用 NFKC、不统一数字或内部标点、不折叠歌词换行。
若只存在末尾一个英文句号或逗号差异，可尝试局部恢复原文，但必须同时满足：

- 原文与输出中均能定位到唯一、明确的画面文字片段，且上下文支持同一招牌/字幕；不得仅在整篇文本中搜索相似字符串替换。
- 文字主体、大小写和内部标点完全相同；仅末尾一个 `.` 或 `,` 不同。
- 原文没有显式“标点必须精确”的要求，没有数字/URL/缩写等敏感歧义，类型不是对白、歌词或 unknown。
- 同一对象原文变体仅为一个带句末标点版本和其无标点版本，可恢复较完整原文版本；若同时有句号与逗号等冲突，不自动选择。

在输出定位范围内恢复为原文完整文字，不修改用户原文，不把文字追加到提示词末尾。修复后重新执行全部格式、素材引用、文字、声音约束和长度校验，成功才可提交。
对用户样例，若输出能明确定位招牌文字 `FRESH LOCAL ORANGES`，恢复为原文 `FRESH LOCAL ORANGES.`，两条现有精确包含要求均满足；若无法确认归属则进入模型重试，不猜测。
这种恢复不能证明参考图片本身含句号，它只维持用户提供原文的完整版本；判断图片真实标点不属于本次修复范围。

### 4. 有针对性的重试

保留最多两次 LLM 调用。第二次传入失败结果正文、完整缺失文字清单和差异类型，要求只修复指定内容并维持人物、镜头、素材职责和其他文字。
缺失多处时一次提供全部问题，不再只给第一项前 60 字。控制重试输入长度；超过预算时按对应镜头携带必要上下文，不截断必须保留的文字。
重试后仍不合格，继续拦截视频提交，不回退到未经适配的原文。纯字符串出现无法证明镜头/说话人归属正确，不能对外声称实现完整语义验证。

### 5. 可诊断错误与兼容性

内部诊断区分 missing_literal、changed_literal、terminal_punctuation_only、ambiguous_literal；包含 id、来源位置、预期文字和可可靠定位的实际片段。无候选时直接说明未找到，不伪造差异。
保留现有 `validate_adapted_prompt(...) -> str` 对外形式，新增内部结构化诊断供修复和重试使用，减少公共调用方影响。HTTP detail 继续返回字符串，首版无需前端结构变更。
用户错误示例：提示词适配未完整保留画面文字（subject_definitions）：预期「FRESH LOCAL ORANGES.」，适配结果仅找到「FRESH LOCAL ORANGES」。已尝试修复，尚未提交视频。
明确记录校验版本、重试次数、有限修复类型、原文/适配结果摘要哈希与请求关联 ID，默认不向公共日志写完整提示词。必要错误片段仅在当前账号请求内返回，不引入跨账号诊断查询。
校验版本进入适配缓存键，更新 prompt_adaptation 版本，旧缓存不复用。

## 验收标准与测试方案

1. 用户样例作为固定文本 fixture，明确招牌上下文下，仅句末点号差异可恢复并通过；逗号版本使用独立样例，不混同两次请求。
2. `Good Things Take Time` 遗漏、大小写变化、翻译、词序变化仍失败；不把缺失文字尾部追加作为修复。
3. 歌词换行、对白问号/感叹号、金额 `3.50`、`1,000`、URL、品牌内部标点仍严格保护。
4. 同一文字出现在不同对象/说话人、原文存在句号/逗号冲突、无法定位输出片段时不自动替换。
5. 标点恢复导致超长时仍失败；引用、H3 字段、无字幕和无配乐检查不被绕过。
6. 首次成功只调用一次 LLM；首次失败后的重试包含失败正文和完整诊断；最多两次；最终失败上游调用次数为零。
7. 用户原提示词保持不变；新旧校验版本缓存隔离；适配和润色入口使用同一规则。
8. 执行相关 Python 编译、新增纯函数测试、test_video_prompt_adapter 及受影响润色/模型路由回归、git diff --check。无需为方案或纯后端修复构建安装包；模拟接口通过不等同于真实视频画面验证。
