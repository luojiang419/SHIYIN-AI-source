## 任务目标

从资产入库、身份、引用、预览、缓存、列表查询到画布显示建立一致契约，解决已知故障及同类隐患。保持已有生成节点、账号边界、历史工程及文件可恢复。

## 当前项目现状

- Python FastAPI + SQLite + Tauri/WebView，画布是 DOM/SVG 渲染，已有显式媒体队列、驻留淘汰和局部渲染。
- 作品接口每次全量读取/合并历史与画布资产、查文件时间，再排序分页，运行于 async 路由的事件循环。
- ThreadPoolExecutor 提交预览工作不传播 ContextVar；目录使用 ScopedPath。
- SW 以 URL 缓存媒体，多个账号具有相同相对 URL，必须验证账号边界。
- 图片保存相信扩展名/Content-Type；作品扩展名接受 html/png_x 等未知后缀。

## 技术方案

1. 独立媒体契约模块：实际字节识别格式，标准后缀/MIME，拒绝非图片响应，原子发布文件；历史引用保留，区分缺失、远程和无效内容。
2. 缓存按账号、源文件版本和尺寸隔离；取消隔离的共享 Future、原子缩略图、受限并发。浏览器旧无账号缓存不可继续复用。
3. 作品聚合移出事件循环，采用数据库变更标记驱动的账号缓存，分页只处理必要媒体；同账号并发避免重复重建。
4. 保留现有画布交互模型，先测主线程/网络/后端的实际瓶颈；只有 DOM 渲染成为主导瓶颈且替换能通过交互回归时才换引擎，禁止用换引擎掩盖存储和鉴权问题。

- 账号 A/B 同名资源互不串读，切换账号和重启 SW 后仍成立。

## 根因证据

1. **网页被当成图片**：`iter_canvas_asset_values` 递归读取节点内全部 URL，而未知扩展名默认返回 image。安装态查到 11 个 Prada/Loewe/Miu Miu `.html` 研究网页链接，随后被作品命名函数拼成 `SHIYIN-xxxx.html`。现在媒体识别使用明确类型/标准后缀，HTML/JSON 不进入图片索引，扩展名未知且无明确媒体类型的网页也排除。
2. **账号不完整隔离**：画布资产缓存原键只有画布 ID + revision；SW 原键只有 URL。新键分别包含数据库路径和已认证会话摘要；真实 HTTP 测试 A/B 的同名红/蓝图片互不串读，预览各自落盘，304 正常。
3. **实际内容未核验**：保存函数原先信任上游 Content-Type/文件名，并在下载失败后把远端 URL 作为成功返回。现在先核验完整图片、实际格式决定扩展名，写入临时文件后原子发布；保存失败返回可处理错误。下载代理拒绝网页/JSON，不再用远程 basename 猜本地文件。
4. **全量同步聚合与重复探测**：原作品列表在事件循环内汇总历史和所有画布媒体，同图多次 stat/解析后才去重。现在在工作线程运行，先去重再探测；热查询复用账号快照。
5. **游标精度丢失**：`1789020631.2760246` 截成 6 位小数后变大，分页重复返回同一批记录；向下舍入则可能漏掉同时间戳剩余作品。旧实现的大规模隔离进程出现超时及约 13GB 内存，现已停止。新游标完整保存 float，1250 条同时间戳作品分 11 页正好全部返回且无重复；汇总另加游标不前进保护。

## 缓存与运行时契约

| 层级 | 身份/失效 | 预算与策略 |
|---|---|---|
| 作品快照 | 账号数据库绝对路径 + DB/WAL 时间/大小；外部文件变化最多 10 秒 | 8 个账号快照，重建合并，返回独立副本 |
| 文件类型 | 绝对路径 + mtime_ns + 字节大小 | 4096 项 LRU，仅存类型信息 |
| 磁盘预览 | 绝对源路径 + mtime_ns + 大小 + 宽度 | 复用已有持久预览，原子发布；图片/视频任务池互不堵塞 |
| HTTP | Cookie Vary + private/no-cache + 内容 ETag | 可条件请求 304，不共享账号私有响应 |
| SW 媒体 | 已认证会话摘要 + URL + 可选媒体 revision | 1000 项/256MiB，单项 16MiB，后台裁剪；旧无账号缓存不复用 |
| 画布驻留 | 现有视口优先队列/预算/移出回收 | 保留现有机制，不增大原图解码量 |

磁盘清理由现有维护线程统一扫描管理员及普通账号的 cache，按总预算淘汰最旧缓存（默认 10GiB、配置硬上限 20GiB，定期扫描，非实时磁盘配额）；跳过账号/缓存目录符号链接，不涉及任何 media 原文件。行为测试验证同时清理账号缓存、保留源图片。

## 性能结果与换引擎决策

复现工具：`tools/media-architecture-fixture.py`、`tests/support/media_architecture_benchmark.cjs`。完整原始结果与截图在 `.codex-artifacts/media-architecture/`。修改前源码使用 `backup/v200`；两组相同确定性分页时间戳、1250 张 2048px JPEG、13 画布，主画布 450 个图片节点，关闭收费任务/启动生命周期。每组服务重启后使用新磁盘预览目录和新浏览器上下文，先测真实首次作品打开，再测热打开。数字为本机单组对照，不能等同于所有硬件、4K视频混合画布或所有真实工程的 SLA。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 作品首张图片（冷） | 2376 ms | 821 ms |
| 作品首张图片（热） | 1945 ms | 109 ms |
