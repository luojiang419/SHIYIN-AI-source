## 任务目标

未变化的画布再次进入时直接恢复可操作状态；软件重启后尽量减少工程读取、配置加载和媒体准备的重复工作，同时保留首次加载资源就绪保障。

## 当前项目现状与根因

1. canvas-session-host.js 已保留最近三个编辑器 iframe，复用 Document、媒体元素、视口、选择和撤销历史，保存或生成中实例受淘汰保护。
2. canvas.js 的 setCanvasRouteActive 在恢复时无条件显示遮罩，等待 checkRemoteCanvasVersion，再执行 prepareCanvasEntry。
3. prepareCanvasEntry 调用两次 CanvasResourceReady.wait；每次新建 WeakMap、重新检查解码，并各等待至少 300ms 稳定时间，还遍历低清预热资源。未变化的驻留画布也承担这条路径。
4. captureCanvasPage 已保存工程、视口、选择、撤销历史和配置到按账号隔离的 IndexedDB；恢复后仍等待 session.ready 的完整工程和配置请求，再执行完整门禁。
5. StudioPageState 已有 flushAll，但写入失败未向调用方明确报告；pagehide 发起异步写入不能作为退出落盘成功保证。Tauri lib.rs 的退出入口需接入握手。
6. 离开期间通常没有编辑，但后台生成、其他窗口或局域网客户端修改、配置更新、资源丢失仍可能发生，不能以“离开过”作为缓存永久有效依据。

## 技术方案

### A. 软件内再次进入：复用活实例

- 首次完成门禁后，记录当前实例的就绪证据：渲染代次、资源代次、配置代次，以及逐元素的 source/currentSrc、资源版本和解码结果。不要在恢复时对整个工程 JSON 做指纹计算。
- 离开保留现有暂停媒体、停止轮询、视口保存与快照逻辑；不清空成功就绪记录。
- 恢复先判断实例未重建、无已知配置/资源失效、无未完成门禁，再做轻量真实状态检查。图片需仍完整且有尺寸、源和版本一致；视频检查真实 readyState。通过后直接显示原画布并恢复调度，版本探测在后台进行。
- 单独的 boolean ready 不够：浏览器可能回收媒体资源，DOM 也可能被异步任务替换。被回收或变化的元素进入局部检查，不把旧记录当成新元素的完成证明。
- 初版快速检查可以一次 O(媒体数) 只读遍历，避免重新 decode、load 和固定稳定等待；后续根据测量再考虑维护失效集合。
- 已知资源失效时只准备变化资源；依旧保留“资源真正可用后进入”的门禁。首次进入、配置导致全量重绘或无法判断有效性时沿用完整路径。
- 新增恢复 generation/token，离开、切换、删除或再次恢复时使旧异步流程失效，旧回调不得关闭当前遮罩、开启隐藏轮询或覆盖编辑。
- 后台版本发现内容变化时沿用保存序号和脏状态防覆盖机制；准备新增资源后应用更新，不能让旧请求覆盖刚完成的本地编辑。

### B. 退出软件后：复用业务快照和媒体文件

- 扩展现有 StudioPageState，不再建立第二套工程缓存。快照增加 schema、渲染兼容版本、账号/工程 ID、服务端 revision、baseRevision、editSequence、配置版本与资源清单。
- 资源清单保存稳定文件标识、内容版本、缩略图/低清缓存标识及节点映射，不保存 DOM、blob URL、解码成功标记或大段 base64。
- 只保留渲染必需配置字段，不扩大完整运行配置的持久化范围；排除凭证。磁盘“ready”不能证明重启后的媒体已解码。
- 鉴权完成后读取匹配快照；用已有版本探测能力校验工程，补齐必要的轻量配置/资源版本元数据。版本一致时跳过完整工程 GET；当前启动模块的自动 prefetch 必须一起调整，否则请求仍会提前发生。
- 命中快照时用现有本地媒体/缩略图缓存构建节点，仍检查此次进程中的真实图片解码和视频可用状态；低清缓存可按稳定资源版本直接复用，缺失才重新生成。
- 本轮保持现有完整资源就绪标准，不擅自改为只等待首屏。若以后采用首屏优先，作为独立体验变更评估。
- 磁盘恢复无法达到活实例完全相同的成本：DOM 与媒体解码必须重建。收益主要来自避免重复传输工程、重复生成缩略图和重复读取未变配置。
- 快照保存沿用合并写入，按编辑版本去重，避免每次普通点击都深拷贝完整撤销栈；视口/选择可独立轻量更新。撤销历史按现有预算限量保存。

### C. 保存一致性与退出握手

- 正常编辑定期落盘，离开补写最新快照；缓存不是替代服务端工程保存。
- 正常退出、托盘退出、更新退出共用一个有防重入保护的准备退出流程：先阻止窗口立即销毁，发送带 token 的准备事件，前端提交当前编辑与 flushAll，事务完成后返回结果，再退出并结束后端。
- flush/flushAll 必须返回可区分成功、超时和失败的结果，不能把 Promise resolve 或 allSettled 当成保存成功。
- 建议等待预算 2 秒。已确认本地草稿落盘但服务端保存失败时允许退出并标记待同步；本地与服务端均未保存成功时保留窗口并说明原因，允许用户明确选择直接退出。
- 最小化到托盘仅保存检查点并暂停可见性相关工作，不执行进程退出；强制结束进程依靠最近成功落盘快照恢复，不承诺保存最后一瞬间输入。
- dirty 草稿必须带 baseRevision。重启发现服务端版本变化时保留本地草稿并进入冲突处理，禁止直接自动 PUT 覆盖远端；无冲突才继续保存。

### D. 失效与容量

| 情况 | 行为 |
| --- | --- |
| 原实例、资源和配置均未变 | 快速显示，后台版本探测 |
| 新增输出、替换图片或媒体被回收 | 使对应记录失效，局部准备 |
| iframe 被淘汰、刷新或软件重启 | 磁盘恢复并重新验证真实媒体状态 |
| 工程 revision 变化 | 获取新版，尊重本地 dirty/baseRevision |
| 工程删除、账号切换或退出登录 | 立即撤销对应实例资格，遵守原账号缓存隔离策略 |
| schema/渲染版本不兼容、缓存损坏 | 回退正常加载；不自动删除唯一未同步草稿 |
| 缓存缺失、配额不足 | 明确标记持久化失败，保留正常工程加载能力 |

内存沿用三个实例上限及保存/生成保护。磁盘按账号和最近使用时间管理，建议初始最多十个干净工程、快照总量上限 100MB；这属于可调起点。未同步草稿单独保护，超预算提示，不能当普通缓存淘汰。媒体复用现有文件缓存，不复制一套原图/视频。
