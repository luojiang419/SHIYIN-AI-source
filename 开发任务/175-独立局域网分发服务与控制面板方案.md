## 实现范围与技术选择

控制面板采用 HTML/CSS/JS + pywebview/WebView2 独立 EXE，后端为同一 EXE 的 `--service` 后台进程。关闭 GUI 不终止分发。当前通过可选的 Windows 登录自启动运行，没有注册 SCM Windows Service，也没有实现登录前运行。

服务端同时广播 mDNS 和 UDP；当前 Windows 客户端使用内置/缓存地址优先、连接失败后 UDP 发现，发现结果必须匹配内置公钥。mDNS 广播用于网络可发现性，客户端专门的 mDNS 解析与多网卡无感切换尚未实机验收。初始下载地址内置当前管理电脑 IP，普通客户端不显示服务器监听地址。

热更新采用 Ed25519 签名清单 + 逐文件 SHA-256；白名单为 `app/web`、`app/backend/canvas-backend`、`app/skills` 和精确的 `SHIYIN AI.exe`。只在用户确认后下载，通过独立 helper 等待旧进程退出、记录替换日志、备份并应用，然后自动启动新版。新进程的后端与窗口就绪后写 ready 标记，90 秒未就绪则恢复旧版；异常中断日志在下次启动时先恢复。该 ready 标记不代表所有业务功能端到端自检。

普通安装目录不可写时 helper 通过系统 UAC 请求管理员权限；取消时主程序保持运行。此分支源码已接入，本机管理员环境没有覆盖非管理员 UAC 实测。

默认不悄悄回退到 GitHub 全量安装包。管理员手动导入的局域网全量包继续沿用既有安装器流程。模型沿用组件清单/Range/逐文件哈希及现有 worker 激活验证，当前不宣称模型下载清单采用客户端强制签名验证。

历史发布允许暂停/恢复；重新指向旧热更新不会让已安装更高序号的客户端降级。要回退业务内容，应将旧内容作为新的热更新序号发布。

## 同事首次接入

1. 保存并退出 SHIYIN AI。
2. 在同一局域网打开下载入口，运行 `SHIYIN-Hot-Update.exe`，选择包含 `SHIYIN AI.exe` 的安装目录。
3. 工具下载受信任的签名热更新，启动独立更新器并自动重启软件。
4. 后续直接在软件内收到热更新提示；点击“立即更新”后完成下载、安装和重启。暂缓不会下载或安装。

旧更新器不认识签名协议，因此旧 `/hot-update/manifest.json` 返回 409，避免静默应用新快照。本机已通过相同签名下载/独立会话完成首次迁移，不需要全量安装器。

## 控制面板外观与后台增强（2026-09-14）

- `theme` 支持system/dark/light，默认跟随系统；页面CSS与Windows原生标题栏同步。原生窗口使用64位HWND与DWM属性20（旧系统回退19），每秒检查Windows应用主题，不修改系统主题。页面监听prefers-color-scheme变更。
- `background_on_close` 控制关闭窗口是否收至系统托盘；顶部“后台运行”和托盘菜单可隐藏/恢复面板。关闭此选项时退出面板，独立下载服务仍保留，可用服务启停控制下载。
- `launch_at_login` 控制当前用户登录自启动，实际设置/移除HKCU Run；`start_hidden` 控制登录启动时是否隐藏到托盘。部署脚本尊重已保存开关，不再每次强制开启。
- 迁移旧的正常/乱码Startup快捷方式到 `.lnk.disabled`，避免自启动关不掉或重复运行。Windows PowerShell部署脚本改用UTF-8 BOM，修复中文快捷方式乱码。
- 控制面板增加单实例保护；重复启动会通过本机认证管理API恢复已有窗口。托盘无法初始化时保留可见窗口，不隐藏成无法恢复的进程。
- 新增 `distribution/desktop_settings.py`，修改 launcher/service/panel 和部署脚本，增加 `tests/test_distribution_desktop.py`。只升级分发中心组件，未编译SHIYIN AI全量安装包，也未重新发布固定模型。
