## 2026-09-16 新引擎资源加载卡住修复

用户现场截图显示进入画布已经很快，但所有图片节点长期停留在“资源加载中”。根因锁定在新引擎动态挂载/卸载节点后，旧媒体空间索引没有失效，媒体队列没有被立即唤醒；节点 DOM 已经出现并被 `CanvasResourceReady.monitor()` 标记为 pending，但队列候选仍可能来自旧索引，导致可见媒体不启动加载。

本轮修改 `static/js/canvas.js` 的 `CanvasEngineBridge.onNodeMount/onNodeUnmount`：节点挂载和卸载时将 `classicMediaSpatialGridEpoch` 置为失效并调用 `scheduleClassicMediaQueue()`，让新进入视口或重新挂载的节点立刻进入媒体队列。`static/canvas.html` 同步给 `canvas.js` 增加 `resource-loading=20260916.1` 缓存标记，避免 WebView 沿用旧脚本。新增 `tests/test_canvas_initial_load_performance.py::test_upstream_node_mount_wakes_media_queue` 锁定新引擎挂载生命周期必须唤醒媒体队列。

## 直接移植边界

上游没有独立的 npm 引擎包。可移植单元是 `infinite-canvas.tsx` 的视口容器、编辑页的可见节点筛选、`canvas-node.tsx` 的 React 节点挂载与 `canvas-connections.tsx` 的连线。只把容器嵌入当前页面，旧 `render()` 仍会全量重建 DOM，因此不符合用户要求。直接移植需把 React 渲染层作为唯一画布核心，停止经典/智能 `render()` 和 CSS transform 引擎直接操作画布根节点。

原有页面 shell、工具栏和浮层布局不迁移。现有工程数据仍是唯一持久化格式；React 层读取现有 `nodes`、`connections`、`viewport`，旧节点业务逻辑通过逐类型适配进入 React 节点组件。特殊节点的媒体、3D 舞台、提示词输入和端口必须在组件挂载/卸载生命周期中保留状态。布局 CSS 和 DOM 锚点通过截图及功能测试逐一核对。项目现已统一进入 `canvas.html`，历史智能画布 URL 重定向，旧数据由经典画布迁移；无需再替换已下线的独立智能编辑器入口。
