## 目标

将已完成技术验证的 Video Depth Anything 完整视频提取能力独立为 Windows 批量工具。用户可导入多个视频，按队列逐一生成深度视频，并输出到指定目录。

## 已确认方案

- 基于 `tools/video-depth-lab/` 的 Tauri 2、Rust 原生层和 Python worker 改造，复用 FFmpeg 解码、VDA 推理和 H.264 编码链路。
- 按后续确认，运行时与模型均不内置，首次使用从魔塔按设备下载并校验；独立工具不能依赖开发机 Python。
- 默认保留原始 FPS、全部帧和原始分辨率，批处理严格串行，避免显存并发竞争。
- 当前阶段交付可运行的 Windows 编译产物。

## 本轮实现与实测

- `worker/main.py` 新增 `batch` 命令，读取版本化清单后严格串行执行，每项独立输出、失败记录但不中断后续项、完成后写入 `batch-metadata.json`，并在每项后释放模型缓存。
- 真实输入：`runtime/inputs/full-1080p-8f.mp4`，1920×1080、30 FPS、8 帧。VDA Base 和 VDA Small 均输出完整 1920×1080、30 FPS、8 帧视频。
- 单项独立实测：VDA Base 20.538 秒，峰值预留显存约 4.22 GiB；VDA Small 7.229 秒，峰值预留显存约 2.04 GiB。
- 实际批处理回归：Base 6.66 秒、Small 2.843 秒，均写入独立目录；Base 使用主体增强参数完成 `depth-adjusted.mp4` 后处理编码。

### 历史原型

2026-09-21 组件安装修复：用户反馈 Windows PowerShell 5.1 的 `Join-Path` 报 drive 为空。已用实际 `powershell.exe` 复现：Rust canonicalize 传入 `\\?\E:\...` 路径导致 provider 无法解析。安装脚本入口还原本地/UNC 普通路径，所有 JSON 显式使用 UTF-8；SHA-256 使用 .NET 流式计算，避免子进程模块自动加载差异。新增 `test_component_bootstrap.py`，以中文空格目录、扩展路径和 UTF-8 清单覆盖离线包校验、分块合并、解压和入口替换，测试通过；现有 CPU 运行时的 Small/Base 准备检查通过。仅修脚本，原地更新用户便携目录和 ZIP，不替换 EXE，不动模型及输出。

- `tools/video-depth-lab/batch-prototype/`：无需后端即可打开的批量提取交互原型，包含队列、拖入/多选入口、单任务串行状态、暂停/恢复、输出位置、模型档位和魔塔首次下载状态，并新增选中任务的深度结果预览、播放状态、五项参数滑块与参数预设。
- 原型将每个队列视频的调参保存到本地存储；导出操作以原始相对深度数据重新编码调整版为目标，命名为 `原文件名_depth_adjusted.mp4`。全屏划像交互将复用主画布既有的对比播放逻辑。
