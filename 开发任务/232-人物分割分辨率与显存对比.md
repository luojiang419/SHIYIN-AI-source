## 同图实测

输入为任务 222 的 `A-pose.jpg`（1600×2000，SHA-256 `9f32a9e2554b766cda704ad40d88bc742f0be00968c42d75b143a84d6da57926`）。机器 RTX 4070 Ti SUPER，16,376 MiB 显存；实验前整卡约 10,450 MiB 已被其他程序占用。每档单独启动一个 Python 进程、同一模型与原图，采样 `nvidia-smi` 整卡峰值，同时读取本进程 PyTorch 峰值；耗时包含模型加载。四次依次运行，未并行。

| BiRefNet 输入 | 耗时 | PyTorch 峰值已分配 / 已预留 | 整卡基线 → 峰值（增量） | 相对 1024 的近似轮廓 IoU* | 平均灰度差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 256×256 | 9.44 s | 3110 / 3990 MiB | 10445 → 14692 MiB（+4247） | 0.9654 | 8.589 |
| 320×320 | 8.61 s | 3110 / 3990 MiB | 10454 → 14709 MiB（+4255） | 0.9873 | 1.166 |
| 512×512 | 8.41 s | 3110 / 3988 MiB | 10453 → 14711 MiB（+4258） | 0.9978 | 0.139 |
| 1024×1024 | 8.91 s | 3297 / 5730 MiB | 10457 → 15210 MiB（+4753） | 1.0000（参照） | 0 |

\* IoU 是把合成深度图中灰度大于 8 的像素当作近似人物区域，与 1024 档比较；它不是人工标注的真值精度，深度归一化变化也会影响数值。256 档在本图出现更明显边缘光晕和人物内部灰度差；320 档整体较接近参照，512 档更接近。此为单张样本，不能推定所有服装、头发和复杂背景。

另以真实轻量档运行同图：PPHumanSeg 192×192 + Depth Anything V2 Small ONNX，CPU 推理约 1.14 s；整卡 10178 → 10190 MiB（+12 MiB，属于同时运行程序的采样波动，模型本身走 CPU），输出 1600×2000。此输出与质量档模型不同，不宜直接用上表 IoU 表示模型精度。

## 512 worker 接入方案与验证

保持已安装 `person-depth` 的模型权重、`fixed-models.json` 和原 `person-depth-worker.exe` 不变。以正式安装版 worker（SHA-256 `91da583ab772dd40447e60e7ce749f50d64d3cc287749a031636513aaae07631`）为底，只把冻结 worker 脚本的唯一分割尺寸常量 1024 改为 512；其余 CArchive 成员字节相同。候选 `person-depth-worker-512.exe` SHA-256 `6743ce4531abfa7afe086cbc1fa92630ab35df52d6d8613bf87c9a5581f06a76`，64,901,075 字节。软件后端从热更新携带的小程序校验摘要后，将它原子复制到已安装组件 `runtime` 目录的新文件名旁，原 worker 留存；质量档使用新文件，轻量 CPU 档原链路不变。

真实本机验证：补丁 worker 在正式安装版权重与依赖旁运行，输出与实验 512 深度图 1600×2000 **逐像素相同**；源码后端经 worker 覆盖路径调用 `render_universal_person_depth`，同图也逐像素相同且 tier=`quality`。相关策略、配置、预提取与 worker 覆盖测试共 38 passed。仅当前本机与冻结候选验证通过，安装版用户端尚未接收热更新。
