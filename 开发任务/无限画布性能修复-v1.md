## 任务目标

在不改变画布数据模型和用户操作语义的前提下，降低大画布首屏主线程布局、媒体预览请求和缓存刷新压力，使轻量画布进入可交互时间接近 1.5 秒，中型画布优先显示视口内媒体，且重复进入不重复生成已有缩略图。

## 技术方案

### 阶段一：止血

- 经典画布只保留一个选中节点共享的图片快捷提示词面板；媒体操作统一使用现有 `selectionHub`，节点 DOM 不再常驻同类表单和工具栏。
- 预览 HTML 保留 `data-preview-src`，默认不设置网络 `src`，由显式队列按照节点世界坐标与当前视口计算优先级后限量注入；data/blob 资源仍立即显示。
- 选中节点、可视区和安全边界按优先级入队；平移/缩放/重绘时取消不可见的未开始任务。

### 阶段二：缓存与入口

- Service Worker 对同一 URL 的 refresh 去重并节流，预览缓存不随静态资源版本盲目删除。
- 用户点击画布时暂停其余 iframe 预热；后续评估真正的 `canvas.html` 预热和脚本拆分。

### 阶段三：大画布与观测

- 复用现有 LOD、节点索引和增量 render，补充智能画布按需工具栏。
- 记录导航、首次 render、首个预览和媒体队列阶段耗时，增加 435 节点真实数据回归。

## 验收标准

- 500 个图片节点 render 不再生成 500 个提示词面板和媒体工具栏。
- 首屏预览只为视口及安全边界注入有限数量请求，视频并发低于图片。
- 选中节点仍可使用提示词、模型、摄影机设置和图片快捷操作。
- 经典/智能画布 JS 通过 `node --check`，相关 pytest 全部通过。
- 任务完成前更新本文档、检查 Git 状态并提交清晰 commit。
