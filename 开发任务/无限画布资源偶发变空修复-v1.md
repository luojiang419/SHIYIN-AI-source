# 无限画布资源偶发变空修复

状态：已完成
当前阶段：4/4
最后更新：2026-08-31

## 当前状态

已确认画布资源使用视口优先媒体队列：节点 HTML 只写入 `data-preview-src`，由队列在节点进入视口或安全边界后设置真实 `src`。全量 `render()` 会重新调度队列，但经典/智能画布的增量节点渲染路径在替换或创建资源节点后没有调度队列。

这会导致节点 DOM 仍然存在，但新节点中的图片只有 `data-preview-src` 而没有 `src`，表现为资源突然变空；如果正在加载的旧媒体节点随后被替换，媒体请求完成回调在节点已脱离 DOM 时提前返回，也可能留下未继续排空的队列。重启后走全量加载路径，所以资源通常会恢复。

当前任务已完成。后续如再次出现资源空白，需要采集用户现场的 Network/Console 信息，确认是否为资源文件本身不可访问。

## 任务目标

修复无限画布中已有图片/视频资源偶发显示为空的问题，保证增量创建、替换、同步和资源加载请求被中断后，仍会按照当前视口继续加载资源；不改变画布数据模型和持久化内容。

## 当前项目现状

- `static/canvas.html` 是当前统一画布入口，加载 `static/js/canvas.js`。
- `static/smart-canvas.html` 保留旧智能画布兼容入口，加载 `static/js/smart-canvas.js`。
- 两套脚本都使用 `data-preview-src` + 有界视口队列，只有全量 `render()` 明确调用 `schedule*MediaQueue()`。
- 经典 `renderClassicMutation()` 和智能 `renderSmartMutation()` 在插入新媒体节点后没有调度媒体队列。
- 两套队列的完成回调在媒体节点已经脱离 DOM 时直接返回，未必会触发下一次队列排空。

## 技术方案

- 在 `renderClassicMutation()`、`renderSmartMutation()` 完成节点 DOM 更新和选中状态同步后调用对应的媒体队列调度函数；该操作只安排一帧队列扫描，不恢复大范围 DOM 重建。
- 在经典/智能 `start*PreviewImage()` 的完成回调中先递减活动计数，再无论节点是否仍连接都安排下一次队列扫描；仍连接时继续更新状态和性能记录。
- 保持全量 render、视口优先级、并发上限、失败状态和原图回退逻辑不变。
