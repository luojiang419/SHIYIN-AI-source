## 任务目标

用户进入画布后，画布节点结构和节点引用的图片/视频资源立即发起加载，并在受控并发下尽快完成；禁止浏览器 lazy 策略和重复预览生成造成长时间空白或陆续加载。

## 技术方案

- 后端 `/api/media-preview` 使用独立 `ThreadPoolExecutor(max_workers=4)`，不与默认 asyncio 线程池争用。
- 以真实文件绝对路径、mtime、size、宽度组成 keyed Future；同一预览的并发请求共享 Future，取消单个请求不会取消底层生成。
- 前端缩略图统一 `loading="eager" decoding="async"`；清理调用方传入的 lazy/decoding 属性，避免重复属性导致浏览器采用 lazy。
- 原图尺寸只在选中节点时读取，首屏使用缩略图完成显示和布局，减少一次完整原图网络/解码。

## 验收标准

- 同一媒体预览并发请求只执行一次实际 PIL/ffmpeg 生成。
- 进入经典或智能画布后，所有节点缩略图请求不再被 `loading="lazy"` 延迟。
- 首屏不为未选中节点批量请求原图尺寸。
- 相关测试、JavaScript/Python 静态检查通过。
- 安装包重新构建成功，packaged runtime smoke 通过。

## 已知问题

- 远程 HTTP 资源仍通过 `/api/download-output` 代理，尚未增加远程缩略图专用接口；远程大图/视频可能继续受上游下载速度影响。
- 本轮未改变 iframe 内整页导航和全量节点 DOM 构造，它们仍是中大型画布的后续优化项。
