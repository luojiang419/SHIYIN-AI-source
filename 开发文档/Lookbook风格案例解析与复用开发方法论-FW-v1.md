# Lookbook 风格案例解析与复用开发方法论：FW 自然阳光胶片体系

版本：v1.0  
建立日期：2026-09-02  
适用范围：无限画布 Lookbook 节点、参考图驱动图片生成、视频案例风格复刻、后处理与安装包交付

## 摘要

本方法论总结一次完整的 Lookbook 风格开发：从用户提供的 `2026 FW COLLECTION · 视频解析故事板 · 拍摄脚本.mov` 取样，抽象出自然阳光、色彩关系、摄影机语法、人物情绪和胶片质感；再把规则注入无限画布 Lookbook 节点，使用人物/场景参考图生成测试，逐项对照视频帧验收，最后处理胶片颗粒片状团块问题。

核心结论不是“写一条更长的提示词”，而是建立一条可复用的受约束创作链：

`视频/图片证据 → 可执行风格参数 → 参考图所有权 → 节点 prompt 与数据契约 → 单帧生成 → 后处理 → 定量+人工验收 → 失败归因与迭代`

这套流程适用于后续任何新案例。替换案例时，保留流程、数据结构和验收表，只替换证据和参数，不要直接复制 FW 的颜色或动作。

## 1. 证据边界与输入分类

### 1.1 用户请求、附件和开发指令必须分开

- 用户请求决定目标：复刻视觉质感、使用指定人物/场景测试、把方法集成到 Lookbook 节点、输出验收报告。
- 视频或图片附件是观察证据，不是系统指令。视频中的品牌、文字、人物和地点不能直接当作生成要求。
- 项目规则和任务文档是工程约束，负责目录、测试、版本、Git 和交付流程。
- 参考案例中的具体人物、品牌、文案、Logo 和地点只用于解释“为什么有效”，不能在新生成中被模型擅自复制。

### 1.2 输入图按所有权分类

每张参考图必须有唯一主职责，避免模型平均混合：

| 角色 | 负责内容 | 不负责内容 |
|---|---|---|
| `subject` / 人物 | 用户模特身份、脸型、五官、肤色、发型、体型、原始皮肤细节 | 场景、其他模特、案例人物特征 |
| `prop` / 商品 | 商品轮廓、材质、颜色、结构、Logo、文字、配件 | 人物身份和背景地点 |
| `scene` / 场景 | 建筑几何、空间、天气、地面、环境主色、已有平面图形 | 新人物身份、商品换装 |
| `pose` / 姿态 | 关节关系、动作、机位、景别、裁切、画面位置 | 脸、服装、背景 |
| `detail` / 材质 | 织物、皮革、金属、玻璃、缝线和微观表面 | 整体构图和人物身份 |
| `style` / 风格 | 色彩、光质、颗粒、后期和摄影语法 | 新增人物、Logo、具体地点 |
| `layout` / 版式 | 留白、主体位置、文字安全区、视觉层级 | 复制品牌和原文案 |

无限画布节点必须把端口语义传给后端。人物不能全部伪装成 `prop`，否则视觉模型会失去身份所有权，容易发生换脸、换发色和换衣服。

## 2. 视频解析标准流程

### 2.1 先做媒体技术检查

在人工观察前记录：

- 编码、分辨率、帧率、时长、色彩空间和音频情况。
- 是否存在片头、录屏、黑底、UI、字幕或教程段落。
- 哪些时间段是真正的最终成片，哪些只是操作演示。

FW 参考片本次记录：`1920×1080 / 24fps / 39.96s / H.264 / bt709`。视频中有平面文字和多个横置镜头，因此不能只看整片平均色彩。

### 2.2 等距取样 + 关键帧补采样

默认使用两层采样：

1. 等距采样：按 3–5 秒间隔抽取全片帧，快速识别色彩和镜头变化。
2. 关键动作采样：对人物出现、镜头旋转、前景遮挡、材质特写、光线变化和情绪转折处补帧。

每次采样保留原始帧文件、时间戳和备注。不要只保存一张拼接联系图，因为后续需要逐帧放大检查肤色、织物、颗粒和文字。

### 2.3 每帧使用同一张分析表

| 维度 | 必须记录的可见事实 | 可转成的生成参数 |
|---|---|---|
| 黑白点 | 黑位是否抬升、阴影是否保留、白色是否削平、最高光位置 | black floor、highlight shoulder、曝光策略 |
| 色彩 | 主色、辅色、强调色、面积比例、肤色偏移 | 60/30/10 色彩脚本、环境色与肤色隔离 |
| 光线 | 光源方向、硬/软边、反射补光、逆光、投影 | 直射太阳、天空反射、边缘光、阴影开度 |
| 摄影 | 地平线、机位高度、倾斜、景别、焦点、前景遮挡 | 环境广角、中景、近景、材质特写的镜头角色 |
| 人物 | 视线、肩膀、手指、重心、呼吸、动作前后状态 | 情绪主导的可观察微动作 |
| 材质 | 针织线圈、孔洞、褶皱、皮肤毛孔、发丝、金属反光 | 纹理保留、锐化限制、颗粒尺度 |
| 版式/文字 | 字体方向、留白、文字是否属于场景平面 | 文字所有权、禁止模型虚构文案 |
| 连续性 | 多帧保持什么、改变什么 | 系列一致性锁和每张图的 shot role |

### 2.4 FW 案例的证据摘要

- **色彩**：暖象牙、奶油白、浅柠檬黄为主体；青蓝/湖蓝为辅助；肤色暖中性；整体低饱和但不灰。
- **黑白点**：黑位略抬升但仍有结构性黑点；白色衣物和亮墙有细节；高光呈奶油滚降，不是纯白硬剪。
- **光线**：自然直射日光或薄云天光，亮部方向明确；阴影由天空/地面反射打开；发丝和针织边缘有暖色透光。
- **摄影**：倾斜/横置机位、非中心主体、栏杆或床品形成前景遮挡，广角环境与中近景交替。
- **人物**：闭眼微笑、低头、回望、倚靠、手臂搭靠、整理衣物等微动作；情绪通过视线、嘴角、手指和重心传达。
- **材质**：针织孔洞/线圈、织物褶皱、皮肤纹理、发丝和金属边缘可见；颗粒有粗细变化但不能成为大脏点。

## 3. 从观察结论转成参数，不要停留在形容词

### 3.1 色彩参数模板

不要只写“高级、电影感、复古”。至少写清：

```text
主场色：暖象牙/奶油白/浅柠檬黄，占画面约 60–70%
环境辅色：来自场景本身的褪色青蓝/青绿色，占约 20–30%
强调色：只取场景中的少量颜色，占约 5–10%
肤色：暖中性，禁止环境色污染
黑位：略抬升但保留一处真实黑点
高光：奶油 shoulder，白墙/白衣保留纹理
```

比例是控制关系，不是要求模型机械分区。场景改变时，重新从场景图取样主色和辅色，不要把 FW 的青蓝色硬套到红砖、夜景或深色棚拍。

### 3.2 光线参数模板

```text
光源：真实午后直射太阳，方向从画面左前/右后等可观察位置进入
空气：清透，有轻微暖色高光扩散，不使用雾化奶油滤镜
阴影：由蓝天或地面反射打开，深处仍可见材质
投影：树叶、栏杆、门框等实际物体形成软硬混合投影
高光：白衣、白墙和脸部不削平，发丝边缘允许微暖 halation
```

如果场景是浅色建筑，必须额外加入白墙高光 shoulder 和不过曝规则；如果场景是深色空间，应该保护阴影材质，不能强行套高键日光。

### 3.3 摄影机语法模板

一组四张图建议固定四种功能，而不是四次随机抽卡：

1. 环境建立：地点、人物尺度和光线方向清楚。
2. 动作经过：人物正在走、转、触碰或调整物品。
3. 情绪停顿：近景承载视线、呼吸、嘴角和手部状态。
4. 材质收束：针织、皮革、鞋、包、金属或商品与环境发生接触。

每张图明确：主体画面位置、景别、机位高度、地平线、前景遮挡、焦点和留白。不要用“换四个姿势”替代摄影决策。

### 3.4 人物表演模板

情绪不是抽象标签，而是可观察动作：

| 情绪目标 | 可观察行为 |
|---|---|
| 松弛 | 肩膀下沉、步伐未完全收住、手臂自然摆动 |
| 好奇 | 视线偏向画外、头部略转、动作暂时停顿 |
| 安静 | 低头、闭眼片刻、手指轻搭环境、呼吸平缓 |
| 专注 | 看向手中物件、整理衣物、触摸材质、嘴角不夸张 |

不要把参考视频中的具体动作逐帧复制；复用的是情绪逻辑、动作的松弛度和人与环境的关系。

## 4. Lookbook 节点的实现契约

### 4.1 前端 preset 必须保存完整执行规则

一个风格 preset 至少包含：

```js
{
  id: 'fw-cream-cyan-film',
  name: '2026 FW 奶油青蓝胶片抓拍',
  description: '一句中文用途说明',
  prompt: '可直接交给视觉模型执行的完整风格块',
  source: 'builtin'
}
```

`prompt` 不是展示文案，必须包含光线、色彩、摄影、人物、材质、连续性和失败约束。前端缓存版本必须在 preset 有实质变化时递增。

### 4.2 后端必须重新构建最终 prompt

后端不能只相信前端传来的简短 style 名称。最终 prompt 要合并：

`用户需求 + 风格 preset + 参考图事实分析 + 场景/商品所有权 + 系列数量 + 视觉研究 + art direction`

FW 风格至少需要这些硬锁：

- `USER-SUPPLIED MODEL`：用户模特是唯一身份来源，保持原始发色、五官、肤色、发型和可见皮肤细节；不凭空添加雀斑、痣、疤痕、妆容或年龄特征。
- `FW NATURAL SUN TRANSPARENCY`：真实直射阳光、透亮空气、方向性暖光、天空反射阴影和白色高光保护。
- `FW SCENE IMMUTABILITY LOCK`：场景图是确切地点和建筑集合，不得替换成海滩、咖啡馆、泛化街道或棚拍。
- `FW SINGLE-FRAME OUTPUT LOCK`：每次 API 输出只有一幅完整照片；系列节拍由多个独立请求产生，不能在一张图里排版四格。
- `FW ANALOG FINISH`：颗粒必须 point-like、emulsional、非周期，禁止 blotches/clouds/stains/mottled islands。

### 4.3 输入端口必须传递真实角色

无限画布连接层应保持如下映射：

```text
lookbook-person   → reference_type=subject
lookbook-product  → reference_type=prop
lookbook-scene    → reference_type=scene
lookbook-material → reference_type=detail
lookbook-pose     → reference_type=pose
lookbook-logo     → reference_type=style 或独立 logo 所有权
lookbook-layout   → reference_type=style/layout
```

如果所有输入都传 `prop`，后端无法可靠隔离人物、场景和商品，视觉模型会把它们当成同级装饰素材。

### 4.4 自动模式的安全边界

自动模式可以选择风格，但不能平均混合风格：

1. 先分析参考图事实。
2. 再根据需求、场景光线和材质从 taxonomy 选择一个风格。
3. 保存 `selected_style_id`、理由、置信度和 art direction。
4. 最终生成只执行一个选定风格。

自动模式没有可用视觉模型时，应安全回退到参考图优先的默认风格，不应静默添加新地点、新服装或新人物。

## 5. 胶片颗粒实现：正确路径与失败路径

### 5.1 为什么“film grain”文字本身不够

生图模型常把 film grain 解释成：

- 规则点阵或网格
- 均匀电视噪声
- 大面积灰黄/灰蓝云斑
- 过度锐化的脏污纹理

因此 prompt 只能约束意图，不能保证颗粒物理分布。需要在输出后增加受控 finish。

### 5.2 失败实现

最初的实现使用较大尺寸低频随机场，再与高频颗粒混合，并用宽幅随机密度做结团。结果虽然不是规则网格，但形成了连续片状团块，视觉上像大脏点。

失败原因：

- 低频随机场的空间尺度太大。
- 低频权重过高。
- 结团密度调制扩大了连续亮暗区域。
- 已经烘焙进输出的中频黄蓝云斑没有被处理。

### 5.3 当前推荐实现

颗粒处理分三步：

1. **低频去斑**：在低纹理区域压低中频色度和亮度云斑，使用局部梯度保护建筑边缘、头发、手和织物。
2. **高频颗粒**：只使用逐像素独立随机场，颗粒强度随亮度变化，中间调/阴影略明显，高光更轻。
3. **轻微色彩响应**：给 RGB 增加极弱、不一致的颗粒响应，避免灰度数字噪声，但不得形成连续色块。

推荐伪代码：

```python
rgb = image_rgb / 255.0
blur = gaussian_blur(rgb, radius=5.5)
broad = gaussian_blur(rgb, radius=15.0)

# 低纹理区域才去除中频云斑，边缘由 gradient mask 保护
medium = blur - broad
flat_mask = edge_aware_flat_mask(blur_luma)
rgb -= medium * flat_mask * 0.34
rgb -= (blur_luma - median(blur_luma)) * flat_mask * 0.12

# 不生成 coarse field / clump map
fine = normal_random_per_pixel()
grain = fine * brightness_bias(rgb_luma) * amount
rgb.r += grain + tiny_chroma_variation
rgb.g += grain
rgb.b += grain - tiny_chroma_variation
```

### 5.4 颗粒验收标准

- 局部放大能看到独立颗粒，但看不到连续大片亮/暗团。
- 颗粒大小和密度有自然变化，但不形成周期纹理。
- 天空、墙面、白衣和阴影都可见颗粒，肤色不被染脏。
- 颗粒不覆盖 Logo、文字、发丝和针织真实纹理。
- 颗粒是 finish，不应改变人物身份、场景几何和产品轮廓。

## 6. 生成验证流程

### 6.1 一次请求只生成一张照片

这是本案例最重要的工程规则之一。不要在一个 prompt 里写“生成四个镜头并排”。许多模型会将它理解为四宫格、接触表或故事板。

正确做法：

- 节点数量为 4 时，提交 4 个并发的 `count=1` 请求。
- 每个请求只描述一个情绪主导瞬间。
- 每张图使用同一身份/场景/风格锁，只改变 shot role。
- 输出节点按请求完成顺序收集，但最终按 shot role 或请求索引排序。

### 6.2 测试矩阵

至少覆盖两种场景亮度：

| 测试组 | 目的 |
|---|---|
| 深色/高饱和场景 | 检查阴影、环境色污染、人物轮廓和黑点 |
| 浅色/白墙场景 | 检查白点、过曝、树影、高光 shoulder 和透亮空气 |
| 只有人物 | 检查用户模特身份、原始服装和普通皮肤细节 |
| 人物+场景 | 检查尺度、脚底接触、投影、遮挡和地点忠实度 |
| 人物+商品 | 检查佩戴/手持关系和 SKU 结构 |
| 商品+材质 | 检查纹理、Logo、文字和颗粒不互相污染 |

### 6.3 每轮生成必须保存

- 输入图路径和角色映射。
- 最终 prompt 或 prompt hash。
- provider、model、画幅、分辨率、质量和数量。
- 每张输出路径、请求时间、失败原因。
- 使用了哪一版后处理参数。
- 人工验收和定量指标。

不要只保存“看起来最好的一张”，否则下一轮无法解释为什么成功或失败。

## 7. 参考帧与生成图的验收方法

### 7.1 黑白点检查

使用缩放后的 luminance 统计作为辅助：

- P1：判断黑点是否压死。
- P50：判断整体曝光是否偏暗或偏亮。
- P99：判断白墙、白衣和太阳高光是否顶死。

统计不能替代人工审片。参考视频如果本身包含不同曝光镜头，应比较范围而非追求单个数字相等。

### 7.2 粗颗粒检查

建议记录高频残差代理值：原图减去轻微 Gaussian blur 后的标准差。它只能说明颗粒存在，不能证明颗粒自然；必须结合局部放大检查：

- 是否有片状连续团块。
- 是否有规则网格或重复点。
- 是否出现彩色脏斑。
- 是否吞掉针织线圈、毛孔、发丝或文字。

### 7.3 阳光氛围检查

必须逐项回答：

- 光从哪里来？画面中能否看出方向？
- 发丝、衣物边缘和物体是否有自然透光？
- 阴影侧是否由天空/地面反射打开？
- 白墙/白衣是否保留纹理？
- 是否只是整体套了米黄色滤镜？

### 7.4 人物动作与情绪检查

动作不是“像视频里的动作”，而是情绪是否驱动了动作：

- 视线是否有目标？
- 手指、肩膀、髋部和脚步是否形成因果关系？
- 表情是否过度商业化或机械微笑？
- 人物是否正在做事，而不是展示衣服？
- 动作是否符合场景接触、重力和遮挡？

### 7.5 统一验收表

| 指标 | 通过条件 | 常见失败 | 修复动作 |
|---|---|---|---|
| 身份 | 用户模特五官、发色、肤色、发型稳定 | 换脸/新雀斑/发色漂移 | 修正 `subject` 角色和身份锁 |
| 服装 | 原始服装、鞋、包、配饰保留 | 模型换成更“时尚”的衣服 | 增加 wardrobe immutable |
| 场景 | 建筑/地点/平面图形可识别 | 换成泛化地点 | 增加 scene immutability |
| 光线 | 有方向、投影、透光和反射补光 | 米色滤镜/棚拍软光 | 写明自然光源和曝光关系 |
| 黑白点 | 黑位有结构、白点不削平 | 死黑或纯白大片 | 调整 tone curve/shoulder |
| 颗粒 | 独立不规则颗粒，无大片团 | 云斑、脏点、网格 | 去低频，保留高频颗粒 |
| 动作 | 情绪主导、接触可信 | 站桩/电商微笑 | 改写为可观察物理动作 |
| 摄影 | 景别和机位有功能差异 | 四张同构图 | 分配 shot role |
| 系列 | 色彩、身份、地点连续 | 每张风格漂移 | 固定 continuity block |

验收结果建议分为：`达成`、`基本达成`、`部分达成`、`未达成`，不要用“感觉不错”作为结论。

## 8. 失败模式与避坑清单

### 8.1 把系列节拍写进一张图

**表现**：模型输出四宫格、接触表、故事板。  
**根因**：一个请求中描述多个画面。  
**方案**：每次 API 请求只生成一张，数量由并发请求表达。

### 8.2 场景被替换

**表现**：绿色报刊亭变成海滩/咖啡馆，白墙变成棚拍。  
**根因**：场景只被描述为“灵感”，没有 exact set 锁。  
**方案**：把建筑几何、主色、平面图形和允许变化范围写入 `scene` 所有权。

### 8.3 模特被美化或改脸

**表现**：发色、脸型、肤色漂移，出现用户图中不存在的雀斑/妆容。  
**根因**：只写“真实模特”而没有把用户图设为唯一身份来源。  
**方案**：`subject` 端口 + `USER-SUPPLIED MODEL`，只保留可见事实，不主动补特征。

### 8.4 四张图都是电商站姿

**表现**：中心站立、正对镜头、没有环境接触。  
**根因**：只有“高级时尚”形容词，没有情绪目标和动作因果。  
**方案**：为每张图指定情绪、视线目标、手部动作、重心变化和环境接触。

### 8.5 只写“低对比”导致灰雾

**表现**：画面没有阳光方向，颜色脏灰。  
**根因**：把光线当成全局滤镜，而不是现场光源。  
**方案**：写明太阳方向、反射补光、投影边缘和高光保护。

### 8.6 低频颗粒团块

**表现**：片状灰黄/灰蓝大脏点，像脏污或水彩。  
**根因**：低频随机场、结团密度或模型烘焙云斑。  
**方案**：删除低频颗粒源；边缘保护去斑；只保留高频逐像素颗粒。

### 8.7 只看联系图不看原图

**表现**：缩略图看似成功，放大后手指、针织、文字和颗粒全坏。  
**根因**：没有局部放大和原图级检查。  
**方案**：每组至少放大检查脸、手、服装纹理、商品 Logo、场景文字和阴影。

### 8.8 质量门只做代码不做真实调用

**表现**：quality gate 逻辑存在，但视觉终审接口 502 时无人知晓。  
**根因**：把接口可用性当成必然条件。  
**方案**：质量门返回 `succeeded/skipped/failed`，报告中明确记录；不能把未执行说成已通过。

## 9. 后处理与生成模型的边界

### 生成模型适合负责

- 人物与场景的空间关系。
- 情绪和动作的语义表达。
- 摄影机机位、景别、遮挡和透视。
- 服装、商品、建筑和材质的结构生成。

### 本地后处理适合负责

- 轻微色彩/曝光统一。
- 低频云斑抑制。
- 颗粒、扫描纹理和有限 halation。
- 输出格式、尺寸和元数据归一化。

### 不应交给后处理的内容

- 重建人物脸和身体。
- 修正错误的服装结构。
- 改变建筑几何或商品 Logo。
- 用全局滤镜掩盖错误构图。

如果人物或场景事实错误，应重新生成或做受控编辑；不要用颗粒和调色把错误“藏起来”。

## 10. 测试、文档和 Git 工作流

### 10.1 最低测试集

每次风格修改至少运行：

```text
python -m py_compile main.py canvas_core/ecommerce.py
node --check static/js/canvas.js
node --check static/js/canvas-lookbook-node.js
python -m pytest -q tests/test_lookbook_premium.py tests/test_lookbook_node_frontend.py
python -m pytest -q tests/test_ecommerce.py
git diff --check
```

涉及公共输入角色、后端任务或生成批次时，必须补充回归测试；只改文案也要更新静态缓存版本和对应断言。

### 10.2 任务文档和方法文档职责

- `开发任务/`：记录当前一次开发做到哪里、下一步是什么、验证结果是什么。
- `开发文档/`：记录可跨任务复用的方法、数据契约和失败模式。
- `避坑指南/`：记录具有普适性的环境/构建/API 陷阱。
- Git：记录具体代码差异和历史。
- `输出/`：保存可复核的测试图、联系图、报告和指标。

不要把完整方法论复制到每个任务文档；任务文档只引用本方法论文档。

### 10.3 安装包交付

当风格功能需要进入桌面安装包：

1. 先提交源码和测试。
2. 同步 `VERSION`、package、Tauri、Cargo、后端和 release notes。
3. 构建暂存目录并检查 `canvas-lookbook-node.js`、`canvas.js`、Lookbook Skill 是否进入包。
4. 运行桌面 runtime smoke；已有正式客户端实例时先关闭。
5. 编译 Inno Setup，校验文件名、大小、SHA-256、PE 版本和签名状态。
6. 在任务文档中记录跳过项，例如没有提供 DWPose 真人输入或视觉终审接口不可用。

## 12. FW 案例的最终可复用经验

1. 先取证，再命名风格；不要先写“高级感”。
2. 把黑白点、光源方向、色彩比例、镜头角色和人物动作写成参数。
3. 人物、场景、商品和姿态必须有明确所有权，并在无限画布端口层传递真实语义。
4. 一次请求只生成一张照片，系列靠并发批次而不是一张拼图。
5. 模特身份优先于“更精致”；只保留用户图可见特征，不主动补雀斑或其他瑕疵。
6. 自然阳光必须有方向、投影、透光和反射补光，不能用米色滤镜代替。
7. 胶片颗粒要以高频独立颗粒为主；任何低频场、结团密度和云斑都应默认怀疑。
8. 生成后必须同时做视觉对照和数值辅助，报告中诚实区分达成、基本达成和遗留差距。
9. 失败要归因到身份、场景、构图、光线、颗粒或接口，而不是笼统重抽。
10. 把成功流程写成方法文档，把失败写成避坑规则，下一种风格只替换证据和参数。
