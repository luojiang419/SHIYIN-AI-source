# 无限画布性能优化开发文档 v1

创建日期：2026-08-24

适用版本基线：`main@3fa3779941a2a36d8bfcdb534f915d2cab6a3649` / `1.0.281`

适用范围：经典无限画布、智能无限画布

开发状态：分析完成，等待模块 A（性能基线）实施

## 一、用户目标

当前无限画布在节点数量达到上百后，节点拖动、画布平移/缩放、端口连线、框选和其他操作出现明显卡顿。本项目的目标是在不破坏、不削弱现有任何功能的前提下，降低大场景主线程负担，使交互反馈稳定在可接受帧预算内。

本开发任务采用小模块、可验证、可回滚的方式推进。任何模块没有通过专项测试和大场景验收，不进入下一模块。

## 二、不可违反的功能约束

- 不删除或改变现有节点、连线、分组、特殊节点和媒体数据结构。
- 不牺牲端口命中、连线显示、删除连线、刀切连线和小地图定位能力。
- 不破坏文本输入、输入法组合态、焦点恢复和远程同步。
- 不改变图片、视频、音频预览、播放状态、输出节点和生成任务状态。
- 不改变撤销/重做、复制、粘贴、导入导出和保存冲突处理语义。
- 不以降低图片质量、删除连线、关闭可见反馈或强制禁用功能换取帧率。
- 所有高风险优化必须有开关或安全兜底；增量 patch 失败时允许回退到现有全量 `render()`。

## 三、当前代码结构与证据

### 3.1 经典画布

- 主渲染入口：[static/js/canvas.js](../static/js/canvas.js) 的 `render()`。
- 连线入口：`renderLinks()`；当前已有 `classicLinkDom` 和 `classicLinkControlDom` 增量 DOM 映射，但每次刷新仍会遍历全部连接并重新测量端口。
- 节点拖动已经使用 rAF 合并连线刷新。
- 画布平移/缩放时仍存在额外的连线刷新候选，需要验证是否可以只变换 world 而不重算世界坐标几何。

### 3.2 智能画布

- 主渲染入口：[static/js/smart-canvas.js](../static/js/smart-canvas.js) 的 `render()`。
- 连线入口：`renderConnections()` 和 `refreshConnectionLayer()`；当前会重新拼接完整 SVG、替换整个连线层并重新绑定事件。
- 节点拖动已使用交互层 rAF，但每帧仍可能触发完整连接层重建。

### 3.3 当前 LOD 限制

经典画布和智能画布目前只对节点内部 body 使用 `content-visibility:auto`，节点外层和端口仍保持完整 DOM。这是为了避免外层 paint containment 裁剪外伸端口，相关经验记录见：

[进度快照/614-无限画布端口与内部LOD兼容.md](../进度快照/614-无限画布端口与内部LOD兼容.md)

因此不能直接把节点外层全部做成粗暴的视口删除；后续必须采用保留轻量外壳/端口、延迟内部内容的安全策略。

## 四、已确认的性能根因

### P0：全量连线几何和 SVG 重建

智能画布每次连接层刷新都会重新生成整张 SVG。经典画布虽然复用路径 DOM，但仍会遍历所有连接并读取端口几何。节点和连接数同时上升时，连线成本会在线程中放大。

### P0：高频路径仍会触发全量 render

两个画布仍有大量操作调用全量 `render()`。全量渲染包含节点 HTML/DOM、事件绑定、媒体状态恢复、图标刷新、图片兜底、小地图和连线等多个阶段。

### P1：小地图重复遍历全量节点

小地图节点位置和尺寸计算会反复调用节点布局函数并重建小地图 DOM，拖动和结构变化时会与主画布竞争主线程。

### P1：索引和几何缓存覆盖不完整

代码中仍存在高频 `nodes.find()`、`nodes.filter()`、`querySelector()` 和 `getBoundingClientRect()`。已有索引应扩展到节点 DOM、端口和节点矩形，并按结构/几何版本失效。

### P1：视口 LOD 尚未真正减少 DOM 数量

当前 LOD 主要减少节点内部绘制，不能减少节点外壳、端口、连线命中路径和小地图负担。

### P2：媒体和持久化与交互争用主线程

全量 render 会处理媒体播放状态、图片尺寸测量和图标；保存时会对完整节点/连接模型执行序列化。规模扩大后可能形成短时长长任务。

## 五、实施模块与状态

| 模块 | 内容 | 风险 | 状态 |
|---|---|---:|---|
| A | 性能基线、fixture、交互区间和长任务观测 | 低 | 待开始 |
| B | 热路径索引、几何缓存、平移/缩放冗余刷新清理 | 低 | 待开始 |
| C | 经典/智能增量连线渲染器 | 中 | 待开始 |
| D | 安全视口 LOD 和节点内部延迟渲染 | 中高 | 待开始 |
| E | 小地图 Canvas 化与脏区域更新 | 中 | 待开始 |
| F | 保存序列化、媒体测量与交互层隔离 | 高 | 待开始 |

### 模块 A：性能基线

先不改业务行为，建立 100/300/500/1000 节点及不同连接数的可重复 fixture。测量节点拖动、画布平移、滚轮缩放、端口连线、框选、新建节点和小地图拖动的 p50/p95/p99、帧间隔和 long task。

验收：同一浏览器、同一 fixture 可以重复得到可比较数据；记录全量 render、连接层刷新、小地图刷新和保存序列化的耗时。

### 模块 B：低风险热路径优化

- 建立并复用 `nodeId → node`、`nodeId → DOM`、`nodeId/portRole → geometry` 索引。
- 节点移动只标记受影响节点和相邻连线。
- 平移/缩放只更新 world transform、选择枢纽和小地图视口；验证不再重算世界坐标连线。
- 小地图移动只 patch 对应节点。
- 保留全量 render 作为兜底。

验收：不改变节点位置、端口位置、连线命中和保存结果；专项性能测试和功能回归全部通过。

### 模块 C：增量连线渲染

统一维护 `connectionId → path/hit/control`。新增、删除、移动和状态变化只更新受影响连接；临时连线使用独立 path。智能画布不再在普通交互帧替换整张 SVG。

验收：连线视觉、命中、删除、刀切、选中状态与基线一致；500 节点/1000 连线交互不出现持续长任务。

### 模块 D：安全视口 LOD

节点模型始终保留。选中、拖动、连接中、特殊节点和分组节点保留完整 DOM；普通画布外节点只降低内部媒体/表单内容，不直接删除承载端口的外层。

验收：进入视口立即恢复完整内容；端口不裁剪；文本输入、拖动、远程同步和特殊节点保持正常。

### 模块 E：小地图 Canvas 化

以单个 Canvas 绘制节点矩形，DOM 只保留视口框和必要交互层；节点移动时只重绘小地图数据。

验收：小地图定位、拖动、选中提示和整理按钮行为不变。

### 模块 F：保存和媒体隔离

引入 revision 单飞保存队列，避免连续操作重复序列化；自然尺寸测量、媒体解码和非关键图标处理移到空闲阶段，并防止旧快照覆盖新编辑。

验收：保存冲突、刷新恢复、远程同步和媒体播放状态与基线一致。

## 六、统一验收指标

- 100～300 节点下拖动、平移、缩放无明显连续掉帧。
- 500 节点/1000 连线下热路径 p95 帧耗时目标 ≤ 16.7 ms，p99 ≤ 33 ms。
- 热路径不出现超过 50 ms 的长任务；结构性变更产生的长任务必须可解释、可记录。
- 端口连线松手后 100 ms 内显示结果。
- 新节点外框 100 ms 内可见，媒体内容允许异步加载。
- 文本/输入法交互 p95 延迟 ≤ 50 ms。
- 全量 `render()` 仅用于初始化、结构性变更、撤销恢复或增量失败兜底。

功能回归至少覆盖：节点增删改、拖动、缩放、多选、框选、分组、复制粘贴、撤销重做、端口连接/删除/刀切、图片视频音频预览、生成任务、输出节点、导入导出、远程同步、文本输入和小地图。

## 七、开发与进度接力规则

### 开始任何后续开发前

1. 在仓库根目录 `进度快照/` 中按纯数字前缀查找最新快照。
2. 只读取最新快照，不重复读取全部历史快照。
3. 读取本主文档对应的“当前模块、已完成内容、待办清单、下一步”。
4. 检查 Git 状态、当前提交和是否存在未完成修改。
5. 从最新快照的“下一步”继续，不重新实现已完成内容。

### 每完成一个模块后

1. 运行该模块对应的专项测试、语法检查和 `git diff --check`。
2. 生成新的 `进度快照/<递增序号>-<简要描述>.md`。
3. 快照必须包含：已完成内容、当前模块、具体代码前后对比、验证命令和结果、未完成待办、下一步、已解决的踩坑点。
4. 大模块完成后再生成 `backup/` 源码差异备份；小修补不创建大模块备份。
5. 遇到并解决构建、运行、依赖或工具问题时，追加到 `避坑指南/`。
6. 不修改旧快照文件名，不回收旧序号。

### 上下文接力

当上下文接近 60%～65% 或任务进入长开发阶段时，先生成完整快照，再创建接力任务。接力任务必须明确要求：读取指定最新快照后继续、保持中文沟通、遵守本开发文档和进度规则、不要重复已完成工作。
