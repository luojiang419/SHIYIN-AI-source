## 1. 任务目标

修复以下随节点、连线和媒体数量增长而放大的交互卡顿：

- 空白处右键打开创建菜单。
- 选中图片或分组后显示悬浮功能菜单。
- 点击悬浮菜单创建批量处理、三视图、视频、灯光、动作提取等节点。
- `Ctrl/Cmd+C` 复制一个、多个或全部节点。
- `Ctrl/Cmd+V` 粘贴内部节点和系统媒体。
- 操作完成后由撤销快照、全量连接校验、全局索引重建和保存序列化引起的二次停顿。

本轮不以删除功能、降低媒体质量、减少可见连线、缩短撤销语义或关闭保存换取速度。

## 2. 已确认根因

### P0：经典右键菜单执行全页图标刷新

`openCreateMenu()` 在两次同步布局读取后调用无作用域 `refreshIcons()`；经典页面即使没有画布节点，也常驻大量隐藏面板、按钮和图标。菜单显示成本与整页 DOM 相关，而不是只与菜单相关。

### P0：高频创建动作同步制作整张画布撤销快照

经典 `classicHistorySnapshot()` 对全部节点和连线执行 `JSON.stringify + JSON.parse`，最多保存 30 份且没有总字节限制。智能 `snapshotForUndo()` 同样先完整序列化和解析，再按 16 MiB 上限淘汰旧历史。节点数据越多，点击悬浮菜单和粘贴前的主线程阻塞越长。

### P0：复制没有复用现有节点/连接索引

两套画布均使用 `selectedIds.map(id => nodes.find(...))`，再扫描全部连接。多选复制复杂度接近 `选中数 × 总节点数 + 总连接数`，全选时可能接近平方增长。

### P0：经典粘贴执行全连接校验和全生成器输入同步

粘贴会调用 `sanitizeConnections()`；其对每条连接调用 `canConnect()`，后者再次通过 `nodes.find()` 查找两端，并可能递归扫描连接检查环路。随后 `syncGeneratorInputs()` 遍历全部生成器及其来源。

### P1：所谓增量渲染仍重建全局索引和连接层

经典 mutation 仍执行 `rebuildCanvasDomIndexes()`、选择反馈、几何刷新和全场图片分辨率扫描。智能 mutation 仍扫描全部节点 DOM、重建整张连接 SVG、连接索引和节点几何索引。

### P1：保存仍在主线程完整序列化

保存已经空闲合并和单飞，但真正执行时仍同步序列化全部节点、连接和日志。大画布操作完成约数百毫秒后可能发生第二次可见停顿。

### P2：经典节点粘贴有固定 90 ms 等待

快捷键路径使用 `setTimeout(..., 90)` 区分系统媒体粘贴和内部节点粘贴。这不是几秒卡顿的主因，但构成空画布上的固定延迟。

## 3. 设计原则

1. 吸收 ComfyUI 的状态驱动、脏区更新和按帧提交机制，不整体迁移 LiteGraph。
2. 保留 DOM 节点、媒体、表单、输入法和复杂编辑器能力。
3. 菜单使用单独 Overlay，菜单打开只更新菜单自身。
4. 普通交互只处理受影响节点和相邻连接，不默认调用完整 `render()`。
5. 撤销优先记录结构差异；只有无法安全表达的高风险操作才保留完整快照兜底。
6. 保存、媒体测量、小地图和非关键图标不能占用直接交互帧。
7. 每项优化必须保留明确回退路径或用契约测试锁定行为。

## 5. 逐模块实施方案

### 模块 0：方案与基线

目标：建立本专项唯一主文档，并补齐能证明当前测试缺口的契约。

任务：

- 记录当前代码证据、版本和已安装运行版本差异。
- 建立菜单、复制、粘贴、撤销快照的性能契约测试入口。
- 明确现有测试只检查 `structuredClone` 存在，不检查复杂度和真实交互耗时。
- 不在本模块重构业务逻辑。

验收：方案完整；测试基线可重复；工作区无无关修改。

### 模块 1：菜单显示热路径

目标：菜单显示不再扫描或重绘整页。

任务：

- 经典 `openCreateMenu()` 改为 `refreshIcons(createMenu)`。
- `openLinkCreateMenu()`、节点端口菜单、图片菜单和输出菜单分别只刷新自身容器。
- 评估并合并创建菜单的两次强制布局读取；不能破坏上下翻转和双列布局。
- 经典创建菜单、子菜单和 selection hub 在热路径关闭 `backdrop-filter`，使用不透明主题背景保持可读性。
- 增加经典/智能菜单范围和 CSS 合成回归测试。

验收：空画布和 500 节点下菜单均不调用全局 `refreshIcons()`；菜单位置、子菜单翻转、深浅主题正常。

### 模块 2：复制粘贴查找和连接局部处理

目标：复制复杂度降为 `O(选中节点 + 相关连接)`，粘贴不校验无关连接或同步无关生成器。

任务：

- 两套复制路径使用 `canvasNodeIndex/smartNodeIndex`。
- 维护或复用 `nodeId -> connectionIds` 邻接索引，只收集选中集合内部连接。
- 经典粘贴只验证新增连接；已有连接不重复 `sanitizeConnections()`。
- `syncGeneratorInputs()` 增加目标 ID 版本，只同步新增连接影响的生成器。
- 用同一事件周期的 paste 标记替代固定 90 ms 等待；保持系统图片粘贴优先。
- 为单节点、多选、全选、含组节点和系统媒体粘贴补回归测试。

验收：复制不出现 `ids.map(...nodes.find...)`；节点粘贴没有固定 90 ms；无关连接和生成器不被扫描。

### 模块 3：增量撤销历史

目标：创建类操作和粘贴不再同步深拷贝整张画布。

任务：

- 定义历史条目联合类型：`snapshot` 与 `transaction`。
- `transaction` 记录创建、删除、替换的节点/连接，以及操作前后选择状态。
- 先覆盖粘贴、悬浮菜单创建、右键创建等纯结构操作。
- `performUndo/performRedo` 同时支持旧快照和新事务。
- 经典撤销栈增加总字节上限；智能栈继续沿用 16 MiB 限制。
- 无法安全表达的复杂操作继续使用 snapshot 兜底。

验收：创建和粘贴热路径不调用全画布 `JSON.stringify`；撤销/重做结果与现状一致；跨类型历史顺序正确。

### 模块 4：真正增量渲染

目标：新增少量节点时，成本与总节点数基本解耦。

任务：

- mutation 直接更新节点 DOM、节点索引、端口索引和矩形缓存，不全量 rebuild。
- 连接层只插入新增连接并更新相邻连接，不重建完整 SVG。
- 选择高清图同步只处理旧/新选择节点。
- 媒体状态采集只覆盖将被替换的节点。
- 小地图只提交创建/删除节点脏区。
- 增量失败时记录原因并回退完整 render。

验收：新增一个节点不得扫描全部节点 DOM 或重建全部连接；500 节点/1000 连线行为与小画布一致。

### 模块 5：保存序列化和性能验收

目标：操作后的保存不再产生第二次明显长任务。

任务：

- 优先评估后端增量 patch 协议；若不扩展协议，则评估 Worker 快照和 revision 顺序保护。
- 保存只包含持久化字段，避免重复复制运行时和临时状态。
- 为 `menu-open`、`toolbar-action`、`copy`、`paste`、`undo-snapshot`、`save.serialize` 增加统一测量。
- 使用 100/300/500/1000 节点 fixture 采集 p50/p95/p99 和 long task。

验收：直接交互帧与保存序列化解耦，旧保存响应不能覆盖新编辑。

## 7. 验收标准

功能标准：

- 菜单位置、菜单内容、子菜单方向、悬浮按钮和快捷键行为不变。
- 复制粘贴保留节点全部持久化字段、组成员关系、内部连接和位置偏移。
- 系统图片/视频/音频粘贴优先级不变。
- 撤销/重做、远程同步、保存冲突、媒体播放和输入法行为不回归。

性能标准：

| 场景 | 目标 |
|---|---:|
| 空画布右键菜单首帧 | p95 <= 50 ms |
| 500 节点右键/悬浮菜单首帧 | p95 <= 80 ms |
| 复制单节点 | p95 <= 30 ms |
| 复制 100 节点 | p95 <= 80 ms |
| 500 节点画布粘贴单节点 | p95 <= 100 ms |
| 500 节点画布悬浮菜单创建节点 | p95 <= 100 ms |
| 直接交互长任务 | 不得出现 > 50 ms，结构兜底需单独标记 |

目标值必须在真实桌面 WebView 或同版本 Chromium 中验证；静态契约测试不能替代性能结论。

## 8. 风险与回退

- 增量撤销最容易破坏历史顺序和复杂节点字段，必须先覆盖纯创建事务。
- 连接局部校验必须保留环路和端口角色约束，只能缩小输入集合，不能绕过规则。
- 系统媒体粘贴与内部节点粘贴存在事件竞争，移除 90 ms 前必须有专项测试和真实浏览器验证。
- 增量索引发生不一致时，允许记录警告并执行一次完整 rebuild。
- 保存协议若需要后端变更，必须保持旧客户端全量 PUT 兼容。
