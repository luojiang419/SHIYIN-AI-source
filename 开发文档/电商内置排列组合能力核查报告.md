# 电商专用内置排列组合能力核查报告

- 核查日期：2026-08-29
- 核查范围：`canvas_core/ecommerce.py`、`static/js/ecommerce.js`、`main.py`、`tests/test_ecommerce.py`

## 一、核查结论

软件确实内置了大量组合能力，但需要区分三个层次：

1. **业务操作类型**：当前明确提供 6 类。
2. **自动合成模式**：运行时归并为 4 类；自由提示词是单独的手动模式。
3. **参考角色排列组合**：全能模式支持 13 种角色，按角色约束动态生成大量组合，而不是为每种组合写一个固定模式名。

在“每种角色最多一张、细节图自动绑定到唯一商品、忽略图片上传顺序”的计算口径下，13 种角色可以形成 **5,080 个有效角色集合**；如果不把细节图纳入，仍有 **2,552 个有效角色集合**。这些数字是当前规则引擎可解析的角色集合数量，不代表 5,080 个独立 UI 按钮或 5,080 套完全不同的提示词模板。

## 二、当前明确内置的业务操作

`OPERATIONS` 中有 6 类：

| ID | 功能 |
|---|---|
| `try_on` | 自由换衣 |
| `pose_transfer` | 动作迁移 |
| `prop_replace` | 道具替换 |
| `angle_change` | 角度修改 |
| `background_change` | 背景修改 |
| `universal` | 全能模式 |

对应的提示词主分支共有 9 个：5 个固定操作分支，加上全能模式的 4 个自动合成配方。

## 三、全能模式的角色与排序

当前共有 13 个角色：

```text
主体、模特形象、上装、下装、连衣裙/套装、鞋靴、首饰/配饰、
手持/携带物、场景道具、细节图、动作参考、场景/背景、风格/光影
```

规范化顺序为：

```text
主体
→ 模特形象
→ 上装
→ 下装
→ 连衣裙/套装
→ 鞋靴
→ 配饰
→ 道具
→ 场景道具
→ 细节图
→ 动作
→ 场景
→ 风格
```

因此用户上传 `场景 → 产品 → 动作 → 人物主体` 时，实际会按角色重排为 `主体 → 产品 → 动作 → 场景`。

当前源码中的 `resolve_universal_reference_plan()` 已明确写入：用户指定的参考类型是唯一的路由权威，视觉分析不能改变 owners、fallbacks 或 ordering。

## 四、运行时自动合成模式

| 模式 | 触发条件 | 参考所有权 |
|---|---|---|
| `subject_edit` | 存在主体角色 | 主体提供身体和基础画布；产品、动作、场景按角色局部替换 |
| `visible_model` | 没有主体，但有模特形象 | 系统提供身体；模特形象只提供脸部身份 |
| `invisible_outfit` | 没有主体/模特形象，但有服装和动作 | 隐形人台或无脸身体，动作参考控制空间关系 |
| `product_showcase` | 没有人物主体，但存在商品角色 | 商品展示，不生成无关人物 |
| `manual_prompt` | 全能模式自由提示词策略 | 直接使用用户提示词，不走自动参考组合 |

其中 `manual_prompt` 不属于自动组合模式，而是显式的自由创作路径。

## 五、角色组合数量的计算口径

使用当前 `resolve_universal_reference_plan()` 对 13 个角色做集合枚举：

- 独占角色：主体、模特形象、上装、下装、连衣裙/套装、鞋靴、动作、场景、风格，每种最多一张。
- 非独占角色：配饰、道具、场景道具、细节图，可以与其他商品角色叠加。
- 连衣裙/套装不能与上装或下装同时作为主服装。
- 场景和摄影棚预设同时存在时会产生冲突。
- 细节图只有绑定商品后才是完整有效组合；本次统计按唯一商品自动绑定到第一件商品。
- 至少需要主体、模特形象或商品/服装目标之一。

统计结果：

| 统计口径 | 有效角色集合 |
|---|---:|
| 含细节图，细节自动绑定唯一商品 | 5,080 |
| 不含细节图 | 2,552 |
| 当前自动合成模式 | 4 |
| 全能模式角色数 | 13 |

如果允许同一非独占角色上传多张图片，或把 14 张参考图的数量变化也纳入计算，实际输入组合数量会继续增加。因此“几十种”是保守说法，当前规则可解析空间实际上远大于几十种。

## 六、已经明确覆盖的常见组合

测试矩阵中至少明确覆盖以下常见路径：

- 仅模特主体。
- 主体 + 服装。
- 主体 + 模特形象 + 服装。
- 仅模特形象。
- 模特形象 + 服装。
- 服装 + 动作。
- 服装 + 动作 + 场景。
- 仅成套服装。
- 商品 + 场景。
- 商品 + 摄影棚。
- 主体 + 多件服装、鞋、配饰、道具、细节图、动作、场景和风格。
- 乱序上传后保持相同规划结果。
- 视觉分析内容与用户角色不一致时仍保持用户角色权威。

`tests/test_ecommerce.py` 当前有 131 个电商测试方法，其中 37 个直接覆盖 universal/全能模式行为；全量测试最近一次结果为 895 passed。

## 七、参数维度带来的额外组合

除角色组合外，页面还内置以下参数维度：

- 动作预设：8 种。
- 背景预设：8 种。
- 摄影棚预设：8 种。
- 画幅：跟随原图 + 8 种固定比例，共 9 种。
- 分辨率：自动、1K、2K、4K，共 4 种。
- 质量：自动、低、中、高，共 4 种。
- 生成数量：自动、1、2、3、4，共 5 种选项。

这些参数与角色组合可以交叉，但并不是每个交叉都应该被当成独立提示词模板；规则引擎会根据操作类型锁定不应改变的区域。

## 八、当前发现的边界

当前实现已经覆盖大量角色组合，但“全部排列组合”不等于“所有任意输入都强行生成”：

1. 独占角色重复会被拒绝。
2. 连衣裙/套装与上装、下装同时存在会被拒绝。
3. 多商品下的细节图必须指定绑定商品。
4. 场景参考图和摄影棚预设不能同时作为最终场景。
5. 全能模式最多 14 张参考图。
6. 非全能模式仍使用固定输入槽位，组合自由度低于全能模式。

这些限制是为了避免串脸、串服装、串背景和错误的空间关系，并不是遗漏。

## 九、建议

建议后续不要简单地新增几十个硬编码模式名，而是把当前规则引擎的规划结果展示给用户：

```text
用户类型：全能模式
识别角色：主体 / 产品 / 动作 / 场景
归一化顺序：主体 → 产品 → 动作 → 场景
自动组合：subject_edit
提示词版本：...
```

这样既保留当前数千种动态组合能力，也能让用户知道系统到底选择了哪种组合；如需扩展，只需增加角色约束或规则测试，不必复制整套提示词模板。
