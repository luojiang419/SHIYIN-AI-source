# 电商专用页面接入视觉模型与 Nano Banana Pro 可行性论述报告

- **报告日期**：2026-08-29
- **项目**：SHIYIN-AI
- **范围**：电商专用页面的“无提示词生成”增强，不包含本报告之外的自动发布或自动审核。

## 一、结论

方案可行，建议采用“视觉模型分析 + 规则化合成规划 + Nano Banana Pro 生图”的两阶段流水线，而不是让一个模型同时猜测图片类型、决定合成关系并直接生成结果。

当前项目已经有可复用基础：

1. `main.py` 已提供 `caption_image_with_provider()`，能把本机参考图和 JSON 约束发送给视觉聊天模型。
2. `configured_ecommerce_vision_route()` 会从已启用且有 Key 的平台中筛选视觉模型，并优先使用 `local-vision`。
3. 全能模式已有 `analyze_ecommerce_universal_references()`、缓存和 `enrich_ecommerce_snapshot_with_universal_analysis()`，会按用户指定角色提取材质、动作、构图、文字等证据，再交给 `canvas_core/ecommerce.py` 生成有引用顺序和所有权锁定的提示词。
4. `canvas_core/ecommerce.py` 已内置 Nano Banana Pro 的多参考图、商业摄影、品牌文字、材质保真和 4K 质量约束。

因此不是从零开发，主要工作是把现有后端能力产品化为可观察的“分析阶段”，扩展到所有电商操作，并为 Nano Banana Pro 建立独立且明确的生成路由。

## 二、需要先澄清的产品语义

用户选择的“类型”应当是**意图约束**，视觉模型负责识别图片内容、补全子类型和提出冲突提示，不应无提示地推翻用户选择。例如用户选择“自由换衣”，模型可以判断“上装/下装/连衣裙”，但不能把任务静默改成“背景替换”。

推荐行为：

- 用户选择类型后，先提交图片和类型给视觉模型。
- 模型返回 `detected_subtypes`、证据、置信度和冲突项。
- 若冲突影响合成方式，页面显示“建议采用 X 方案”，由用户确认；低风险子类型可以自动采用。
- 最终路由以“用户类型 + 已确认的角色”作为权威，视觉模型只提供证据。

## 三、目标执行流程

```text
上传图片与选择类型
        |
        v
视觉分析（并发、可缓存）
  - 图片内容与质量
  - 参考角色证据
  - 可见文字/Logo/材质
  - 姿势、视角、构图
  - 置信度与冲突
        |
        v
规则引擎选择合成方案
  - 用户类型优先
  - 角色所有权与引用顺序
  - 参考图数量与模型能力校验
  - 输出比例、分辨率、候选数
        |
        v
Nano Banana Pro 提示词编译器
  - 有序参考图地图
  - 保留区/修改区
  - 商业摄影和品牌保真约束
  - 用户补充指令
        |
        v
图片生成 API（Gemini 3 Pro Image / Nano Banana Pro）
        |
        v
候选图 + 分析摘要 + 使用的合成方案 + 可重试信息
```

## 四、视觉分析输出协议

建议新增版本化结构 `ecommerce_vision_analysis_v1`，每张图一个结果：

```json
{
  "reference_id": "ref_01",
  "user_role": "upper_garment",
  "detected_subtypes": ["针织开衫"],
  "subject_presence": "garment_only",
  "visual_details": "米白色粗针织、金属纽扣、左胸刺绣文字……",
  "material_signature": "针织圈结构、纱线方向、局部起毛……",
  "brand_text": ["可辨识的原文"],
  "pose": {},
  "composition": {},
  "confidence": 0.92,
  "conflicts": [],
  "model": "视觉模型名",
  "cached": false
}
```

约束：

- `user_role` 不由模型改写；模型只能补充 `detected_subtypes` 和证据。
- 不清晰的文字必须留空或标记“不可辨识”，不能猜 Logo、价格、尺码或口号。
- 姿势证据只允许来自 `pose` 或 `subject` 角色；商品图中的人物不能成为姿势来源。
- 分析失败时保留明确状态并允许用户继续手动生成，不应静默使用空提示词。

## 五、合成排列组合规则

规则引擎按以下优先级匹配方案：

| 组合条件 | 推荐方案 | 主要约束 |
|---|---|---|
| 主体图 + 模特形象 + 任意商品 | `subject_edit` | 主体提供身体、发型、背景；模特形象只提供脸部 |
| 模特形象 + 商品/服装 | `visible_model` | 系统生成身体；模特形象只锁定脸部 |
| 服装 + 动作参考、没有真人主体 | `invisible_outfit` | 隐形人台/无脸模特，动作参考控制空间关系 |
| 只有商品/配饰/鞋靴 | `product_showcase` | 商品是唯一主体，选择棚拍或生活方式场景 |
| 只有文字要求 | `manual_prompt` | 保留用户提示词，不虚构参考图 |

额外规则：

- 同一独占角色（主体、模特形象、姿势、场景等）只能有一个；多件商品按上装、下装、连衣裙、鞋、配饰、道具顺序排列。
- 细节图必须绑定一个商品；多商品时要求明确绑定，避免材质串图。
- 场景参考图与摄影棚预设二选一。
- 生成前校验参考图数量、模型最大参考数、比例和分辨率；超过能力时给出可操作的拆分建议。

## 六、Nano Banana Pro 提示词策略

Google 官方建议使用详细的主体、场景、风格、光线和镜头描述，并通过逐步迭代控制结果；官方还建议把目标文字放在引号中、明确字体、直接指定画幅/输出格式、为参考对象命名以保持一致性。详见 [Google DeepMind Nano Banana 提示词指南](https://deepmind.google/models/gemini-image/prompt-guide/)。

Gemini API 官方文档给出了可复用的“主体 + 场景 + 光线 + 相机角度/镜头 + 画幅”模板，并将 Nano Banana Pro（Gemini 3 Pro Image）定位为复杂指令、专业资产和最高 4K 输出场景；详见 [Gemini API 图片生成与编辑文档](https://ai.google.dev/gemini-api/docs/image-generation)。

在项目内建议固定使用以下提示词层次：

1. **Reference map**：按 `Image 1/2/...` 写明每张图的唯一角色和权限。
2. **Task**：先写最终商业图片类型，再写主体、商品、场景、动作和构图。
3. **Camera / lighting**：明确景别、视角、焦段倾向、光线方向、色温和接触阴影。
4. **Preservation locks**：列出不允许改变的脸、身体、SKU 结构、颜色、Logo、文字、背景区域。
5. **Material evidence**：将视觉分析中的织纹、走线、光泽、透明度和印花对位作为材质锚点。
6. **Text and brand**：只有用户明确要求时生成新文字；已有文字按原文、方向、位置和字距保留。
7. **Quality gate**：要求 100% 放大可读、无重影、无额外物体、无水印、无镜像文字。
8. **User supplement**：最后附加用户指令，并仅在明确冲突时覆盖默认规则。

开源方案可作为模板回归测试和提示词样例来源，例如 [nanobanana-image-prompts](https://github.com/ljh-it/nanobanana-image-prompts) 的结构化示例（主题、风格、光线、相机、细节、构图）。开源内容应作为实验样例，不能替代 Google 官方 API 参数和安全政策。

## 七、API 与模块执行方案

### 阶段 A：分析预览层

- 新增 `POST /api/ecommerce/analyze`，输入操作类型、参考图、用户标签和可选补充说明。
- 复用 `caption_image_with_provider()`、`configured_ecommerce_vision_route()` 和现有缓存；将每张图分析结果返回前端。
- 前端在“开始生成”按钮前显示分析状态、置信度、冲突和建议合成方案。
- 允许用户修改角色或确认建议，保存到任务快照。

### 阶段 B：规则规划层

- 将 `resolve_universal_reference_plan()` 扩展为所有操作通用的计划接口。
- 输出 `composition_mode`、`ordered_reference_ids`、`owners`、`fallbacks`、`conflicts` 和 `prompt_version`。
- 规划结果写入电商任务，便于历史复现、审计和问题定位。

### 阶段 C：Nano Banana Pro 路由层

- 在 API 设置中增加“视觉分析模型”和“图片生成模型”两个角色，不把视觉聊天模型和图片生成模型混为一类。
- 生成路由优先匹配 `gemini-3-pro-image-preview`（Nano Banana Pro）；不支持多参考图时按能力表回退，并在任务中记录实际路由。
- 若供应商只提供 OpenAI 兼容接口，需验证其是否真正支持 Gemini 图片输入/输出协议，不能仅依据模型名称判断。

### 阶段 D：可观测性与质量门

- 任务记录分析耗时、生成耗时、缓存命中、模型、参考图数量和失败原因。
- 在结果页展示“分析摘要”和“使用的合成方案”，支持重新分析、重新编译提示词和仅重试生成。
- 继续保留现有人工质量检查和导出审批；视觉模型不能替代上架前人工验收。

## 八、风险与控制

| 风险 | 控制措施 |
|---|---|
| 视觉模型误识别或串图 | 用户角色优先、单图所有权、置信度/冲突提示、可人工确认 |
| Logo/文字幻觉 | 只保留可读原文；生成后人工检查；禁止模型猜测 |
| 多参考图超限 | 生成前按模型能力校验并建议拆分 |
| 延迟和费用上升 | 并发分析、按文件哈希缓存、只分析实际参与生成的图片 |
| 供应商协议不一致 | provider 能力矩阵、端到端冒烟测试、记录实际模型与协议 |
| 隐私与版权 | 本机路径校验、最小化上传、提示用户确认图片使用权；遵守供应商政策 |
| 失败导致重复扣费 | 分析阶段与生成阶段分离，任务状态可恢复，不自动重复提交不确定请求 |

## 九、分阶段验收标准

1. 选择每种电商类型并上传 1～5 张图片后，页面能看到逐图分析结果、置信度和合成建议。
2. 用户确认或修改角色后，生成请求中的参考图顺序、角色所有权和提示词版本可追溯。
3. Nano Banana Pro 路由能完成单图、多图、文字/Logo、比例和 2K/4K 的最小回归集。
4. 分析失败、模型不支持、参考图超限时，页面给出明确错误和下一步，而不是生成空结果。
5. 历史任务能复现当时的分析结果、规则计划、提示词和实际生成路由。
6. 不改变现有人工质量检查、审批和导出流程。

## 十、建议的实施顺序

先实施“分析预览层 + 统一规划输出”，再接入 Nano Banana Pro 专用生成路由，最后补齐评测集和 UI 质量门。这样可以先验证“自动匹配合成方式”是否准确，再扩大模型和供应商覆盖，避免把识别错误直接放大为生成成本。

在进入阶段 A 的代码开发前，建议确认一个产品决策：当视觉模型判断与用户所选类型冲突时，是否始终要求用户确认，而不是自动改类型。推荐默认采用“用户类型不可被模型覆盖”的策略。
