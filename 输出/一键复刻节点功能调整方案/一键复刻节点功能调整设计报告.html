DESIGN DECISION

把“一键复刻”升级为深度优先的多参考图编排节点

保留原有骨架路径作为兼容模式，新增节点级平台与模型选择；通过四个稳定输入角色、一个内部控制图和版本化固定模板，让常见组合零 AI 调用，只有用户写了额外需求时才调用一次 AI 助手。

01 / CURRENT STATE

现状与问题定位

结论来自当前仓库代码，不是脱离实现的概念设计。经典画布与智能画布共享节点 UI，但生成参数和任务提交各自维护。

1

控制图只有骨架

节点连接动作参考后自动调用 DWPose，内部只保存 poseSkeletonUrl，缺少深度图分支与模式状态。

2

节点级模型缺失

当前只显示画幅、分辨率。经典画布取第一个可用图片平台/模型，智能画布继承全局或节点运行设置，结果不可预测。

3

角色只有两个

外部输入仅有 pose-reference 和 target-image，无法显式表达“身份来自谁”和“最终场景来自谁”。

4

提示词会被重复优化

图片任务当前默认启用 AI 助手优化。如果直接放入固定提示词，仍可能多一次调用并发生二次改写，不符合“无文本快速生成”。

可复用基础：项目已有 /api/depth/estimate 快速深度接口、DWPose 路径、统一图片任务入口和 AI 助手多模态优化器。本次无需重建生成系统，只需补齐节点状态、角色路由和专用提示词编译层。

04 / LOGIC CHAIN

从连线到 API 的完整逻辑链条

核心原则是先锁角色与控制图，再决定是否需要 AI。无文本路径不经过语言模型，减少延迟、成本和提示词漂移。

01读取端口

按 inputRole 收集 A/T/M/S，拒绝错误媒体类型。

02校验组合

A 与 T 必需；M、S 可选；稳定计算 scenarioId。

03生成控制图

depth 调用深度接口；skeleton 走现有 DWPose。

04编译提示词

固定模板 + 模式片段 + 组合片段 + 硬约束。

05按需 AI

仅有用户文本时规范化增量，固定模板不调用。

06提交任务

带明确 provider/model/size 与有角色的 refs。

07记录结果

保存模板版本、原始文本、最终 prompt 与任务快照。

状态机

idle

等待动作参考和目标图。可选端口不影响基础可运行性。

preparing-control

正在提取深度图或骨架图。动作参考变化会使旧控制图立即失效。

compiling-prompt

选择固定组合模板；有用户文本时进入 AI 助手规范化。

submitting

创建独立输出节点并提交图片任务，允许重复点击并发抽卡。

running

任务已进入后端队列，输出节点负责轮询与恢复。

failed

区分控制图失败、提示词失败、配置失败和生成失败，提供对应重试入口。

05 / PROMPT SYSTEM

提示词系统设计

用户验证过的三图提示不应散落在前端常量中。建议服务端版本化管理，以“基础模板 + 模式片段 + 组合片段 + 用户增量”编译最终提示词。

P0端口角色与引用图所有权代码生成 · 不允许 AI 改写
P1身份、姿势、服装、场景与禁止事项版本化固定模板
P2用户明确输入的额外需求有内容时保留原意
P3AI 助手补全的可执行表达仅补足，不改所有权
P4通用质量与输出约束固定尾段

无用户文本

0 次 AI 调用

根据 mode + hasModel + hasScene 直接选中组合模板，插入稳定图片编号和角色片段后提交 Nano Banana Pro。

有用户文本

1 次 AI 调用

AI 助手收到固定角色映射、硬约束、用户原文和模型 profile，只输出规范化的“用户意图增量”；服务端再与固定模板合并。

建议保存为 pose-replicate.v2.base-depth.zh-CN 的验收基线。正式实现只做变量化，不改动其角色优先级与禁止事项。

请以图1为唯一编辑底图，对图1中的模特进行高保真局部换装：保留原模特、原姿势、原配饰和原背景，只把原来的上装替换为图3中的上装。

【三张图片的用途】

图1：原始人物照片，也是最终结果的基础图。

严格保留图1中的：

- 同一位模特及其面部身份
- 五官、脸型、肤色、妆容和表情
- 发型、发色、发丝、耳朵和耳饰
- 身材比例、站立姿势和身体重心
- 头部角度、视线方向和肩线
- 双臂弯曲方式、双手及手指位置
- 手持眼镜的动作
- 手袋、包带、裤装和其他配饰
- 人物在画面中的位置、大小与比例
- 原始街景、店面、建筑、地面和全部背景
- 原始镜头视角、透视、构图、裁切、光线、阴影、色温和景深

除原上装区域及其产生的必要阴影外，不要修改图1的其他任何区域。

图2：图1人物对应的深度图，只用于辅助锁定空间结构。

图2中的白色表示靠近镜头，灰色表示中间距离，黑色背景没有场景信息。使用图2保持：

- 头部、肩部、躯干和双臂的空间位置
- 身体姿势、人物体积和透视
- 手、眼镜、手袋、头发与服装之间的前后遮挡关系
- 人物在画面中的位置、大小和裁切范围

图2不提供人物身份、服装款式、服装颜色、服装纹理或背景。尤其不要照搬深度图中原上装的表面和具体外轮廓；上装的新版型应以图3为准。

图3：新上装的唯一设计参考。

无论图3是服装平铺图，还是另一位模特的上身穿着图，都只提取其中上装本身的设计，准确保留：

- 上装类别、整体款式和版型
- 领口、肩部、袖型、袖口和衣长
- 门襟、纽扣、拉链、口袋和下摆
- 面料、颜色、图案、印花和纹理
- 缝线、褶皱、装饰及其他可见细节
- 宽松度、厚度、垂坠感和结构感

如果图3由另一位模特穿着，只参考其上装；不要复制该模特的脸、头发、肤色、身体、手部、姿势、背景或拍摄角度。

如果图3是平铺服装图，请把平面的服装结构合理转换成真实穿着状态，不得擅自改变衣领、袖型、长度、图案、颜色或关键设计。

【具体换装任务】

完整移除图1模特原来的豹纹上装，将图3中的上装真实、自然地穿在图1的原模特身上。

新上装必须适应图1模特原有的身体姿势、肩部角度、手臂弯曲和手部动作，同时保持图3服装自身的真实版型。允许服装外轮廓按照图3的款式发生合理变化，但不得改变人物的身体姿势和比例。

如果图3是短款、修身或轻薄上装，不要强制保留原豹纹外套的宽大轮廓。

如果图3是宽松、厚重或廓形上装，应准确表现其真实体积、厚度和下摆形状。

根据图1人物动作生成符合物理规律的面料拉伸、挤压、褶皱和垂坠。腋下、肘部、胸腹、袖口和腰部的褶皱必须自然。

新上装的光照方向、亮度、色温、阴影、清晰度和环境反射必须与图1完全一致，让结果看起来像模特在原拍摄现场真实穿着该服装，而不是后期粘贴。

【遮挡与边缘】

严格保留图1中的正确遮挡关系：

- 头发应自然覆盖服装领口和肩部
- 双手和手指应位于服装前方
- 手持眼镜必须保持原来的位置、角度和形状
- 手袋与包带必须保持原来的位置和遮挡关系
- 新袖口应自然衔接手腕，不得覆盖或吞没手指
- 服装边缘不得出现发光、灰边、重影或抠图痕迹

【执行优先级】

1. 图1控制模特身份、面部、姿势、动作、配饰、背景、构图和光线
2. 图3控制新上装的款式、版型、颜色、面料和细节
3. 图2辅助控制身体结构、空间深度和遮挡关系
4. 只允许原上装区域及其必要阴影发生改变

【禁止事项】

不要改变模特的脸、五官、妆容、表情、发型、肤色、身材或年龄感。

不要改变人物的头部方向、视线、姿势、手臂角度、手指位置或手持动作。

不要替换或改变裤装、眼镜、耳饰、手袋、包带及其他配饰。

不要改变背景、街道、店面、招牌、透视、镜头角度、人物位置和画面裁切。

不要保留原豹纹上装的豹纹、颜色、面料、领型、纽扣或款式。

不要复制图3中其他模特的身份、身体、姿势和背景。

避免脸部重绘、身份漂移、身体变形、肩部错位、多余肢体、多余手指、手指粘连、服装粘在皮肤上、图案扭曲、错误遮挡、包带断裂、眼镜变形、边缘光晕、重影和拼贴感。

只输出一张完成换装后的最终彩色照片，不要输出深度图、蒙版、灰度图、分屏图、过程图、对照图或文字说明。
必须变量化的样例词：原文中的“豹纹上装”“眼镜”“手袋”等是该验证样本的具体事实，不能在任意图片上硬编码。实现时应把这些词拆为视觉解析变量；无法可靠识别时退回“原服装/现有配饰”的通用表达，绝不编造样本不存在的物件。

07 / COMPATIBILITY

兼容迁移与错误策略

新默认只作用于新建节点。存量画布必须保留原骨架语义和原始默认画幅，防止打开旧项目后无操作即改变输出。

新建节点

nodeSchemaVersion: 2
depth / shiying / gemini-3-pro-image-preview / 2k / 16:9。

存量节点

没有 poseReplicateMode 且 schema < 2 时迁移为 skeleton；画幅缺失仍按 1:1，模型沿用旧解析。

平台或模型不可用

节点显示“默认模型未配置”，生成按钮禁用；用户必须显式选择可用模型，不静默切到第一个平台。

控制图失败

保留动作参考，显示失败阶段和“重新提取”；切换模式后重新计算签名，不复用另一模式缓存。

AI 助手失败

仅阻塞有用户文本的任务；保留用户原文，不降级为忽略用户文本的固定模板生成。

比例冲突

16:9 与“保持原裁切”存在潜在冲突。首轮真实 API 回归必须覆盖非 16:9 动作参考，决定是否允许最小背景扩展。

08 / DELIVERY PLAN

建议开发阶段

按可独立验证的模块推进，先稳定模板与服务端契约，再落 UI 和双画布，最后做真实图片回归。

阶段 1

提示词编译器与契约测试

新增 canvas_core/pose_replicate_prompts.py，实现八条路由（2 模式 × 4 组合）、稳定参考编号、固定模板零 AI、有文本单 AI 和冲突过滤。

阶段 2

服务端专用任务入口

新增请求模型与任务接口，内部复用现有图片生成执行器；记录 prompt_source、模板版本和最终参考图顺序。

阶段 3

共用节点 UI 与控制图模式

调整 canvas-special-nodes.js 和样式，增加四输入预览、模式/平台/模型/分辨率/画幅控件，接入 depth 与 DWPose 两条准备路径。

阶段 4

经典与智能画布接线

分别补齐端口 HTML、连线合法性、角色取图、节点状态持久化、运行快照和输出恢复；公共规则保持同一份。

阶段 5

自动化与真实生成回归

覆盖旧画布迁移、两模式、四组合、平台切换、空/非空文本、并发生成、失败恢复和非 16:9 输入；使用已验证样例做 Nano Banana Pro 端到端验收。

09 / ACCEPTANCE

可执行验收标准

以下条件全部满足后，才可以把功能标记为完成。

  1. 新建一键复刻节点默认显示深度图、shiying、gemini-3-pro-image-preview、2K、16:9。
  2. 存量节点打开后仍走骨架模式，不发生自动默认值漂移。
  3. 动作参考变化会清除旧控制图并重新提取；模式切换不会误用另一模式缓存。
  4. 四种端口组合都生成稳定且可审计的 reference_order 与 scenarioId。
  5. 无用户文本时 AI 助手调用次数为 0，最终提示来自版本化固定模板。
  6. 有用户文本时 AI 助手只调用 1 次，且不能改变身份、服装、姿势和场景归属。
  7. 经典画布与智能画布提交同一组合时，生成请求语义和参考顺序一致。
  8. 平台/模型选项来自真实配置；默认模型不可用时明确阻止提交。
  9. 任务快照能还原原始需求、最终提示词、模板版本、模型参数与全部引用角色。
  10. 已验证三图样例、完整四图扩展、非 16:9 输入和失败重试均完成真实 API 回归。
建议先确认的唯一产品口径：“目标图”在扩展模式中定义为服装来源，而不是结果底图；“模特主体”一旦连接就成为最终身份来源。这个口径与用户描述最一致，也能避免目标图和模特主体争夺身份控制权。
