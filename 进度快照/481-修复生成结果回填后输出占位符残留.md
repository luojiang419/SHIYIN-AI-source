# 修复生成结果回填后输出占位符残留

## 任务目标

- 修复图片或视频已经生成成功并回填真实媒体后，普通画布输出节点仍残留转圈等待占位符的问题。
- 保证正常运行中的任务、可恢复失败任务和并发提交窗口不会被误清理。

## 已完成内容

- 定位普通画布输出节点的 `images` 与 `_pending` 为两套独立状态；真实媒体成功回填并不必然清除历史孤儿 `_pending`。
- 确认孤儿占位来自任务提交前的保存窗口：占位已创建，但尚未取得 `canvasTaskId`，重载后既无法恢复轮询，也无法被完成回调命中。
- 为 `pruneCanvasRuntimeCollections` 增加显式 `dropOrphanPending` 模式。
- 新建和打开普通画布时，清理没有 `canvasTaskId`、也没有 `recoverTaskId` 的不可恢复占位。
- 新增 `pruneCompletedOrphanOutputPending`：当来源生成节点明确完成时，即时清理结果回填后残留的无任务 ID 占位。
- 输出节点局部刷新使用跳过二次清理的参数，避免定时清理与局部刷新互相递归。
- 保持远端增量同步的保守行为，不清理可能正处在提交窗口的活跃占位。
- 新增 3 项专用回归测试，覆盖加载清理、完成态清理、正常/可恢复任务保护和防递归刷新契约。
- 新增避坑文档 `避坑指南/2026082301-生成占位必须具备可恢复任务身份.md`。

## 当前模块与文件

- 当前模块：普通画布生成输出等待态生命周期。
- `static/js/canvas.js`：孤儿占位识别、加载边界清理、完成态清理与刷新防递归。
- `tests/test_canvas_output_pending_cleanup.py`：输出占位清理回归测试。
- `避坑指南/2026082301-生成占位必须具备可恢复任务身份.md`：根因与后续开发规则。
