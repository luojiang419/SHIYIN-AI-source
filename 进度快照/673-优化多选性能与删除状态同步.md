# 优化多选性能与删除状态同步

## 已完成内容

- 修复作品管理多选拖拽卡顿：原逻辑每次 `mousemove` 都调用 `renderVirtual(true)`，反复销毁/重建全部图片、视频和事件监听；现在通过 `syncSelectionVisuals()` 只更新当前卡片的选中 class、`aria-selected`、checkbox 和批量工具栏。
- 框选更新使用 `requestAnimationFrame` 合帧，最多按浏览器绘制节奏计算一次矩形相交，避免高频鼠标事件堆积。
- 修复批量删除黑屏：删除请求期间不再调用 `loadWorks({reset:true})` 清空 `state.works`，保留现有作品卡片并显示“正在删除”状态，锁定批量按钮。
- 删除成功后直接从内存列表移除选中 id，修正总数并重新渲染结果；收藏和移到回收站也直接更新当前作品对象，无需手动刷新。
- 删除失败时恢复批量操作按钮和选中提示，保留选择以便重试。
- 版本号已递增至 `1.0.300`。

## 修改文件

- `static/js/works.js`：选择状态增量同步、拖拽合帧、批量操作忙状态和乐观列表更新。
- `static/css/works.css`：新增批量处理中样式。
- `tests/test_works.py`：增加“不能在选择更新中重建虚拟列表”和“批量操作保留列表并增量更新”契约断言。
- `release-notes/current.md`：增加性能与删除体验说明。

## 关键前后对比

```text
之前：mousemove -> updateSelectionRect -> renderVirtual(true) -> innerHTML 全量替换 -> 重新绑定所有卡片事件
现在：mousemove -> requestAnimationFrame -> updateSelectionRect -> syncSelectionVisuals -> 只改已有卡片状态
```

```text
之前：删除请求 -> loadWorks(reset=true) -> state.works=[] -> 黑屏/加载空区域 -> 请求结束后重新请求列表
现在：删除请求 -> 保留现有列表并锁定按钮 -> 请求成功 -> 从 state.works 移除选中项 -> 立即渲染结果
```
