# 局域网热更新避免散文件下载

## 表现

应用热更新包含约 1000 个文件时，客户端需要建立约 1000 次 HTTP 请求。局域网服务或连接只要在任意一次请求中断，旧客户端就会显示 `下载失败：io: Peer disconnected`；重试整次操作仍可能在另一个文件处失败。

## 根因

逐文件哈希可以保证内容完整，但不应等同于逐文件网络传输。大量短连接扩大了服务进程退出、网卡抖动、端点安全软件扫描和请求固定开销的影响面。改成自解压 EXE 也会增加 SmartScreen、杀毒软件、UAC 和代码签名问题。

## 解决方法

- 网络层只分发一个 `.shiyin-update` 数据包，内部使用 ZIP 压缩。
- Ed25519 签名清单同时记录整包 SHA-256、包大小和完整目标文件清单。
- 客户端先用 Range 断点续传下载整包，再校验整包哈希，然后安全解包并逐文件校验。
- 解包拒绝目录、重复路径、路径越界、清单外文件以及大小或哈希不符；全部通过后才进入原有事务替换和回滚流程。
- 旧客户端先通过独立的 v2 `hot-bootstrap` 发布线下载单个新版 `SHIYIN AI.exe`；新版客户端通过 `X-Shiyin-Capabilities: package-v3` 获取 v3 正式包。
- 托盘面板连续探测不到独立服务时限频自动拉起，客户端重试窗口覆盖服务恢复时间。

## 验证

分别请求 `/v1/catalog`：无能力头应得到单 EXE 协议 v2，引入 `X-Shiyin-Capabilities: package-v3` 应得到协议 v3 单包。对包预置部分 `.download-part` 后运行更新 CLI，服务监控应记录非零 `offset` 且最终为 `completed`；客户端结果必须为 `ok:true`，解包文件数和哈希应与签名清单一致。
