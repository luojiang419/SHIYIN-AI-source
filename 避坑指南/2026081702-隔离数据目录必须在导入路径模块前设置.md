# 隔离数据目录必须在导入路径模块前设置

## 问题现象

本地 UI 回归用 `python main.py --data-dir <隔离目录>` 启动后，页面仍显示默认数据目录里的真实画布。

## 根因

`main.py` 先导入 `canvas_core.paths.APP_PATHS`，之后才导入 `canvas_core.runtime` 解析命令行参数。仅使用 `--data-dir` 时，`APP_PATHS` 已在参数写入环境变量前完成初始化。

## 当前安全测试方式

在启动 Python 进程前先设置任务专用环境变量：

```powershell
$env:CANVAS_DATA_DIR='G:\绝对路径\隔离测试数据'
python main.py --desktop-token <临时令牌> --port <测试端口>
```

这样路径模块首次导入时就能读取隔离目录。

## 后续规避

- UI 自动化不得只依赖当前 `--data-dir` 参数隔离数据。
- 打开页面后先确认画布数量为 0，再创建测试画布。
- 测试结束停止服务并清理明确验证过的隔离目录，不操作真实 `data`。
- 若未来调整启动架构，应让 runtime 参数解析发生在 `APP_PATHS` 导入之前，并增加启动顺序测试。

## 2026-08-25 再次验证与恢复

- 菜单性能浏览器回归再次证明：仅传 `--data-dir` 时，隔离目录只有 `run/backend.json`，页面仍读取项目默认画布数据。
- 一旦发现画布列表并非预期的空列表，立即停止继续创建测试数据；若已经创建，只能按“测试标题 + 精确画布 ID”双重校验目标。
- 清理时通过正式画布 API 先软删除、再调用 `/api/canvases/{id}/purge`，最后同时检查活动列表和回收站均不存在目标 ID；不得直接批量删除数据库或画布目录。
- 本轮创建的两个 QA 画布已经按上述流程彻底清除，剩余目标数为 0；测试端口和临时运行目录也已关闭并删除。
