# 增量同步媒体 URL 必须包含内容指纹

## 问题

桥接图片原先按 `frame_0001.png` 这类固定序号命名。再次接收同一故事板时，即使文件内容已被覆盖，画布节点的 URL 仍完全相同，浏览器、WebView 或中间缓存可能继续显示旧图。此时数据库内容与用户看到的画面不一致，且无法仅通过节点 diff 判断媒体是否更新。

## 原因

“稳定节点标识”与“稳定媒体 URL”被错误地当作同一概念：

- 节点 ID 应跨同步保持稳定，用来保存布局和连线。
- 媒体 URL 必须随内容变化，用来触发资源重新加载。

## 解决

桥接落盘文件名同时包含稳定帧 ID 的哈希与真实文件 SHA-256：

```text
frame_<stable-id-sha20>_<content-sha16>.png
```

同步比较使用桥接包已验证的 `checksums[relative_path]`；相同内容得到相同 URL，变化内容得到新 URL。画布 image 节点继续复用原 ID 和坐标，只更新 URL。

## 后续规则

1. 所有需要原位更新的媒体节点都必须分离“实体稳定 ID”与“内容版本指纹”。
2. 不要依赖查询参数时间戳作为长期方案；它无法去重且会持续制造无意义缓存条目。
3. 旧节点缺少内容指纹时，第一次同步应视为变化并补齐，而不是假定未变化。
4. 测试必须同时断言：变化帧 URL 改变、未变化帧 URL 不变、两者节点 ID 都不变。
