# 异步确认流程必须保留输入签名

## 问题

建筑多视图在“等待确认线稿 / 等待确认正面”期间，用户可能修改节点内提示词、连接提示词或参考图。如果输入变更处理把旧的 `buildingInputSignature` 直接清空，确认处理会把“没有签名”误判为可以继续，导致旧图在新需求下被确认并继续消耗图片 API。

## 原因

确认阶段同时存在两类状态：

- 当前输入已经变化，因此 UI 应回到可重新生成状态。
- 上一次生成所依据的输入签名仍需要保留，用于拒绝尚未刷新的旧确认按钮。

只重置阶段而清空签名，会丢失第二类状态。

## 正确做法

1. 输入变化时重置 `buildingStage` 和规划结果，但保留上一次 `buildingInputSignature`。
2. 用户点击旧确认按钮时，重新计算当前签名并与旧签名比较；不一致就中止并要求重新规划。
3. 生成任务完成时再次比较签名，防止连接节点在异步请求期间变化。
4. 忙碌阶段禁用节点内提示词和模型设置，减少可避免的中途变更。
5. 新一轮正式运行开始时，才用当前输入覆盖 `buildingInputSignature`。

## 回归检查

- 等待确认时修改提示词后，旧确认操作不能继续生成。
- 连接提示词节点在生成期间更新后，旧任务结果可保留预览，但流程必须要求重新开始。
- 四张实景输入齐全时，缺失目标检查必须早于图片模型检查，确保图片 API 调用数为 0。
