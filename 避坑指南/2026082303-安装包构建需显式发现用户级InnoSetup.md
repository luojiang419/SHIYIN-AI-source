# 安装包构建需显式发现用户级 Inno Setup

## 现象

`tools/build-installer.ps1` 在最后阶段执行 `Get-Command ISCC.exe` 失败，但 `winget list --id JRSoftware.InnoSetup --exact` 显示 Inno Setup 已安装。

## 根因

Inno Setup 6.7.3 安装在用户级目录：

```text
C:\Users\Administrator\AppData\Local\Programs\Inno Setup 6\ISCC.exe
```

该目录没有出现在当前 PowerShell 会话的 `PATH` 中，因此脚本仅按命令名查找时失败。

## 处理方式

先定位实际编译器，再只对本次构建会话追加路径：

```powershell
$env:Path = 'C:\Users\Administrator\AppData\Local\Programs\Inno Setup 6;' + $env:Path
powershell -ExecutionPolicy Bypass -File tools\build-installer.ps1 -SkipBackend -SkipDesktop
```

当此前 PyInstaller 与 Tauri 阶段已经成功时，使用 `-SkipBackend -SkipDesktop` 可以复用已验证的二进制，仅重新进行暂存、运行时冒烟和 Inno Setup 打包，避免长时间重复编译。

## 后续改进建议

- 可将 `build-installer.ps1` 改为先检查常见用户级/系统级 Inno Setup 路径，再回退到 `Get-Command`。
- 发布前始终运行 `tools/verify-installer-artifact.ps1`，并明确记录 `NotSigned` 或 `Valid` 签名状态。
