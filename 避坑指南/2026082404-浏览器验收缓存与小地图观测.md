# 浏览器验收缓存与小地图观测

## 问题

画布脚本使用固定版本 query。修改 `static/js/canvas.js` 后，普通 iframe reload 可能继续使用旧脚本；强制刷新顶层页面还可能触发首次使用 API Key 提示。

## 处理

使用 CDP `Network.setCacheDisabled({cacheDisabled:true})` 后重新加载画布 iframe；若顶层出现 API Key 提示，只点击“稍后设置”，不输入未知凭据。验收 fixture 通过 `finally` 恢复保存拦截、节点、连接和视口状态。

模块 4 复验又确认两个额外边界：

1. `python main.py` 使用相对路径启动时，命令行只能看到脚本名，不能证明进程来自目标 worktree。重启隔离 QA 服务必须显式指定 `Start-Process -WorkingDirectory <目标 worktree>`，并核对端口 owner PID、数据目录和运行模式。
2. 固定脚本 query 下，单独调用 `Network.setCacheDisabled` 后的普通 reload 仍可能沿用当前文档已加载的旧脚本。应在当前标签再次禁用缓存后调用 `Page.reload({ignoreCache:true})`，再读取目标函数的 `toString()` 或唯一新签名，确认运行时代码确实包含待测改动。

真实验收前先比较“磁盘源码签名”和“运行时函数签名”；两者不一致时不得继续记录功能结果，也不得把旧代码失败归因到新实现。

## 观测注意

经典小地图拖动有独立的 `window.onmouseup`，不会进入统一 `endDrag`。必须在该回调显式调用 `CanvasPerformance.markPaintFrom('classic.minimap-drag', ...)`，否则只能记录交互开始，无法形成耗时样本。
