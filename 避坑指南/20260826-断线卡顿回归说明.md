# 无限画布断线卡顿回归说明

## 问题与处理

断开连线原先调用 `pushUndo()`，会深拷贝整张画布（包括节点媒体），大画布上点击断开按钮因此出现数秒卡顿；智能画布随后还会全量重建连接层。本次改为结构事务记录连接差异，普通连接走增量 DOM 删除，分组折叠线和历史线保留必要的完整连接层回退。

## 验证

- `python -m pytest tests/test_canvas_incremental_connections.py tests/test_canvas_incremental_render_performance.py tests/test_canvas_undo_transaction_performance.py -q`：36 passed。
- `python -m pytest tests/test_canvas_*.py -q`（PowerShell 需先展开文件列表）：310 passed。
- `node --check static/js/canvas.js`：通过。
- `node --check static/js/smart-canvas.js`：通过。
- 全量 `python -m pytest -q`：860 passed，3 failed；失败为仓库已有 `test_ecommerce.py` 的 free-creation iframe 入口契约及 `test_unified_theme.py` 的页面缓存版本契约，与本次改动无关，未修改无关模块。

## 避坑

PowerShell 不会按 Unix 方式把 `tests/test_canvas_*.py` 展开传给 pytest，直接执行会报“文件不存在”；应使用 `Get-ChildItem tests -Filter 'test_canvas_*.py' | ...` 先展开绝对路径。全量回归前先运行本次相关测试，避免把既有入口缓存契约失败误判为断线修复回归。
