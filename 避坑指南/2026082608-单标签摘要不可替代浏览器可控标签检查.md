# 单标签摘要不可替代浏览器可控标签检查

日期：2026-08-26

## 问题现象

- 对话环境摘要显示应用内浏览器存在一个智能画布标签，但浏览器控制接口的当前标签和用户标签列表均为空。
- 误以为旧标签已被回收后新开同一画布 URL，短时验证正常；随后在静默窗口出现周期性完整 `smart.render`、数百毫秒 Long Task 和远程数据刷新。
- 节点/连线数据保持 2000/0，说明不是用户操作路径本身触发，而是同一画布的两个 WebView 标签通过远程同步互相刷新。

## 根因

- 环境摘要中的可见标签不一定能被当前自动化会话枚举或接管；“控制接口列表为空”不能证明对应 WebView 已不存在。
- 对同一画布新开 URL 会把不可控旧标签与新标签并存，破坏单标签性能采样隔离。

## 正确处理

1. 若摘要显示同一画布仍有标签，但控制接口列表为空，不得直接新开同 ID 标签作为正式采样环境。
2. 若为恢复状态不得不临时新开，任何出现周期性完整 render/远程刷新迹象的样本立即作废，不归因于产品交互路径。
3. 先持久化并核对精确 2000/0 基线，再关闭新开的可控标签，使环境回到单标签。
4. 最终结论只采用明确处于单标签隔离环境的历史正式样本；重复标签期间只允许做数据恢复和诊断，不采信稳态分位数。

## 本轮恢复结果

- 重复标签期间产生的重建/稳态样本已作废。
- 新开标签关闭前已保存并重载核对：2000 模型、2000 DOM、0 连线、2000/2000 图片、6 个真实 URL、undo/redo 为空。
- 本轮仍保留独立有效证据：首次冷启动批量结构操作 Long Task `331 ms`，落在用户确认的 `<=350 ms` 单次例外内；事务撤销/重做严格执行 2001/1 → 2000/0 → 2001/1。
