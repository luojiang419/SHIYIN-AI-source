# 大模型分包下载需按源复用断点并校验 Range

## 问题表现

数 GB 模型通过代理下载时，瞬时断线会导致安装失败；如果重试重新下载整个分包，会重复消耗代理流量。

## 触发条件

- 代理或 TLS 连接在流式下载中断开。
- GitHub 返回 408、429 或 5xx。
- 下载请求携带 Range，但服务端返回的范围与本地断点不一致。

## 根本原因

只有 `.part` 文件并不等于完整的恢复策略。下载器还必须在同一源与分包路径上自动重试，并验证 206 响应的 `Content-Range` 起点。

## 正确解决方案

- 启动时读取 Windows 系统代理，官方源先走代理，失败后回退直连。
- 每个来源使用稳定的分包文件名，代理与直连切换时复用官方源 `.part`。
- 暂时性错误有限次退避重试，永久 4xx 立即切换来源。
- 仅在服务端返回 206 且 `Content-Range` 起点匹配本地长度时追加。
- 完整包必须通过大小和 SHA-256 校验；已校验分包直接复用。

## 验证方法

模拟首次请求写入部分字节后抛出连接异常，确认第二次调用看到相同 `.part` 长度；同时覆盖系统代理优先和 404 不重复请求。

## 如何避免

大文件下载功能必须同时验证代理发现、断点保留、Range 语义、重试边界和完整包哈希，不能只验证成功下载路径。
