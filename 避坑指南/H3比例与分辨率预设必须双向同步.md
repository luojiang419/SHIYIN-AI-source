# H3 比例与分辨率预设必须双向同步

## 问题表现

视频节点选择 21:9、4:3、1:1、3:4 或 9:16 后，MiniMax H3 后端仍生成 16:9 视频。

## 触发条件

- 前端同时维护独立 `aspect_ratio` 和包含比例及像素尺寸的 `resolution`。
- 用户只修改比例，`resolution` 仍保留默认 `0.2MP 16:9 - 608x352`。
- H3 请求适配器发现 `resolution` 是合法预设后直接采用，并忽略 `aspect_ratio`。

## 根本原因

两个字段都携带画幅信息，却没有一致性约束；旧完整分辨率预设的优先级高于用户刚修改的比例。

## 无效尝试

- 只检查 `G:\app\minimax` workflow：后端会忠实使用收到的 `resolution`，无法修复上游已经传错的 16:9。
- 只调整比例下拉框：请求仍会携带旧 `resolution`，适配器依旧可能覆盖比例。

## 正确解决方案

- 比例变化时，把完整 H3 分辨率映射到目标比例；存在相同 MP 档位时保留档位，否则回退目标比例的基础档位。
- 完整分辨率变化时，反向更新独立比例字段。
- 服务端再次检查两者是否一致，以合法 `aspect_ratio` 为画幅权威字段，兼容旧画布和外部请求。
- H3 界面只展示后端实际支持的六种比例。

## 验证方法

1. 在经典视频和影视视频节点中修改比例，确认分辨率同步变化。
2. 选择带其它比例的完整分辨率，确认比例反向变化。
3. 用冲突字段构造 H3 请求，断言提交给上游的 `resolution` 已修复。
4. 对六种基础比例分别真实生成视频，使用 ffprobe 读取真实宽高。

## 如何避免

任何同时包含 `ratio` 与 `width/height` 或完整尺寸预设的 API，都必须定义单一权威字段，并在 UI 与服务端两侧做一致性校验。

## 影响模块

- 经典视频生成节点
- 影视视频生成节点
- 智能画布视频设置
- MiniMax H3 请求适配器
