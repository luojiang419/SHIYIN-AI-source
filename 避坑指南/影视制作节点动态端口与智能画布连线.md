# 影视制作节点动态端口与智能画布连线

## 问题现象

智能画布新增影视制作节点后，连接到动态演员、服装或道具端口时，连线逻辑可能抛出 `to is not defined`，导致连接创建失败。

## 原因

智能画布的连接函数使用 `toId` 保存目标节点 ID，但影视节点分支误用了不存在的旧变量 `to`。影视节点的端口又是根据演员数量动态生成的，因此这个问题只会在新节点的输入端口连接场景中暴露。

## 修复方式

在连接函数入口根据 `toId` 查找目标节点并复用同一对象：

```js
const target = nodes.find(node => node.id === toId);
if (target?.specialType === 'film-storyboard' || target?.specialType === 'film-video') {
  // 按动态 inputRole 校验影视节点端口
}
```

同时将影视节点的端口定义统一收敛到 `CanvasFilmNodes.inputPorts()`，经典画布和智能画布共用同一套角色编号规则，避免一端生成 `演员A/B`、另一端仍按旧端口判断。

## 预防检查

- 修改连接函数变量名后，执行 `node --check static/js/smart-canvas.js`。
- 用两个演员配置分别验证分镜合成节点和生成视频节点的动态端口。
- 执行 `pytest -q tests/test_canvas_film_nodes.py tests/test_canvas_ecommerce_workflow.py tests/test_canvas_special_nodes.py`，确保影视节点与既有电商节点连线规则没有回归。
