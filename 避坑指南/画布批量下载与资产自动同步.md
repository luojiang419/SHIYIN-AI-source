# 画布批量下载与资产自动同步避坑记录

## 经验（1.0.302 开发）

- 普通无限画布的“下载全部”右键入口是输出节点菜单，不是素材库下载按钮；修改前应沿着 `openOutputNodeMenu()` → `downloadOutputNodeImages()` 定位，避免误改工作流或资产库 ZIP 导出。
- 浏览器多文件 `<a download>` 无法保证写入用户刚选择的目录；桌面 WebView 应优先使用 `showDirectoryPicker()` 和 File System Access API，逐文件写入并处理重名。
- 素材库的画布资产标签按钮在 `#assetManagerRoot` 外部，root 事件委托无法覆盖它；首次加载必须在按钮自身监听器中调用 `ensureTabData()`。
- 画布实时事件通过主壳转发到 iframe，资产页面需同时兼容 `canvas_updated` 和 `entity.changed(topic=canvas)`，并用令牌/延迟刷新避免连续保存造成请求风暴。

## Windows WebView2 兼容补充（1.0.303）

- WebView2 的 iframe 不保证提供 `showDirectoryPicker`；不能只用浏览器 File System Access API 判断桌面能力。
- 桌面版应通过顶层页面消息桥接 Tauri 原生 `FileDialog::pick_folder`，再以 IPC 逐文件写入；目录只选择一次，避免退回 ZIP 或每个文件弹一次保存框。
- Rust 写文件命令必须拒绝包含 `\\`、`/`、`.`、`..` 的文件名，防止下载名称穿越所选目录。
